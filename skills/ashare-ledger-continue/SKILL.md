# 接续项目

先定位实际工作区，依序读取 AGENTS.md、docs/handoff.md、docs/collaboration-workflow.md、docs/implementation-plan.md 与对应阶段任务。总账 docs/retro-and-gaps.md §6.0 只索引阶段，任务状态单点维护。

1. 固定分工：网页ChatGPT负责方案、任务增删/重排、验收和逐轮审核；Codex执行、测试、报事实及建议。旧免网页审核和自行改计划授权已由2026-09-18新规则取代。
2. 接续前核 GitHub/主干/在途PR、当前工作区、前任成果和实际差异；不要清脏树或从主干另建后漏掉未合分支。新切片先取得网页明确派工。
3. 领取时核任务ID、计划版本、范围、验收、停止条件和审核回执。无回执/回执不匹配或未指定下一轮则HOLD；仅可准备安全证据，不擅自跨轮开发。
4. Codex可选择批准范围内的实现细节，发现更优方案或额外缺陷则提交依据和替代建议，由网页ChatGPT统筹。重大范围/策略/接口或验收变化必须先复核，不自批。
5. 完成切片后运行 AGENTS §1 适用完整门禁，保留反例、版本、环境、未验范围与恢复。按 ashare-task-handoff 生成审核包，停止并请求网页独立审核。
6. 修复只覆盖审核明确整改项；合并须网页有效批准和准确提交的原完整CI。开始下一业务轮另需明确派工，不从“测试通过”推断继续权限。

Codex额度不足时不调用模型，不买额度、不切付费API、不循环重试。当前工具不能触发网页审核或Codex续作时，由用户转递 docs/collaboration-workflow.md 的短模板；工具返回成功不等于任务完成。
安全/金融/权限边界不变，应用内LLM没有继承Codex开发授权。自动桥接、审核来源隔离和强制检查未验收前，以人工文件闭环运行，不宣称无人值守。
