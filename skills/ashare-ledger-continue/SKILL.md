# 接续项目账本

仓库根目录由 `git rev-parse --show-toplevel` 定位；不要依赖某台机器的绝对路径。
先读根目录 `AGENTS.md`，文档入口是 `docs/INDEX.md`；唯一任务状态在
`docs/retro-and-gaps.md` §6.0，实测与交接明细在 `docs/handoff.md`。

## 开工

1. 同时核对账本 §6.0 的当前入口、§6.5 最新停止点和 handoff §1；旧轮次只能作为历史证据。
2. 刷新 GitHub 与 `origin/master`，核对本机 HEAD、暂存/未暂存/未跟踪资产和在途 PR。
   新切片从最新主干建独立 `codex/*` 工作区；已有成果先查代码与提交，不按旧计划重复实现。
3. 按用户最新明确优先级选择任务，否则按状态档、优先级与编号选择可做项。
   指针冲突先映射回现有任务 ID 并纠正；无 ID 的新缺口先登记，历史编号不能复用。
4. 简述切片、事实依据、验收及假设，然后动手。首次发现无法在授权内决定的语义差异时，
   登记阻塞并继续其它独立事项；不能把等待常规 PR 合并当作停止条件。

当前切片验收后，继续用户授权范围内下一项。红线、策略口径、凭据、付费与不可恢复操作
均遵循 `AGENTS.md` 和本轮用户指令；技能不扩大权限，也不授权修改用户全局配置。

## 实施与验收

- 每行改动对应任务，先复现实际缺口，再做最小修复。守卫要以真实缺陷注入证明能判红，
  随后还原并核对哈希；不要靠注释、阈值放宽或豁免让门禁变绿。
- 完整门禁及环境前提以 `AGENTS.md` §1 为准。新文件须先精确暂存再跑基于跟踪清单的守卫；
  路径迁移需在干净检出验证。后端与前端全量串行；实测数字注明服务和负载，不转述旧数字。
- 代码、测试、文档改完立即跑覆盖该改动的判据；最终检查提交树包含本轮回填。
  `git diff --exit-code` 查未暂存漂移，`git diff --cached --name-status` 和暂存正文核范围，
  `git diff --cached --check` 查补丁；逐项分类未跟踪文件。暂存的 A/M/D 是正常状态。
- 提交后才要求本任务工作区干净；不得吸收无关文件、清掉用户脏树或删除未知资产求干净。

## 收口与继续

按 `skills/ashare-task-handoff/SKILL.md` 更新账本、双向交接及两处施工指针。
长证据放忽略的 `artifacts/`，可迁移经验只提炼到现有 `docs/kb/`，不建立第三份状态索引。
发布遵循 `AGENTS.md` §6.5；运行只读 `scripts/audit/release_check.py` 核验精确 PR HEAD。
新提交、最新 master 漂移或 CI 重跑都要失效旧结论。合并确认进入主干后才清理本任务分支。
