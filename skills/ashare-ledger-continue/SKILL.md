# 账本接续

当前工作方式见 docs/collaboration-workflow.md。网页ChatGPT统筹计划、任务增删重排及独立审核；Codex执行，用户只触发，不自批、不依赖Bridge或自动调度器。

1. 在已明确的AI-Trading项目中，先读AGENTS和固定分支codex/collaboration-runtime-state的docs/handoff.md，再读协作规范、实施方案和唯一当前阶段任务。新会话未绑定项目时先定位，不猜项目或最新分支。
2. 收到“ChatGPT审核完了”只代表开始重读；核当前任务轮次、实际工作区/分支/HEAD、计划和证据。不要将原主目录、master、最近窗口或旧会话当作最新施工现场。
3. 初次明确派工可实施；需修改只做限定整改；阻塞就停止；审核通过且明确下一动作才继续。已进行/已完成的同一轮不因重复通知重做，原执行者未退出不并行写同一工作区。
4. 新提交、未推送回填、归属不明改动或版本不一致先核实；不reset/clean、不覆盖前任成果、不丢未合功能分支。取远端更新之前保全本机差异。
5. 执行批准范围内的代码、测试和兼容处理，发现更优做法或遗漏先回填事实、收益/风险和低成本替代建议，重大规划由网页裁决；不机械按旧账本顺序连续施工。
6. 完成后按ashare-task-handoff回填同一阶段任务、证据与handoff指针，提交/推送并核到远端。用户无需替你搬运提交号；未推送就不说已交付。
7. 本地验证、网页独立审核、准确版本CI和运行加载分开。Codex无额度不试探、不换付费API；平台安全拒绝不重放绕过。自动化原型已退出当前建设目标，不再自选其剩余功能开发。

只有出现实际访问/证据/并发/权限问题才要求最小必要介入；正常情况从记录直接接续，不额外向用户索要整套历史或重新确认同一派工。
