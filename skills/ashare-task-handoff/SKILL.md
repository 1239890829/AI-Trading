# 原位交接

全项目范围按 `docs/product-closure-design.md`、`docs/hunting-decision-design.md`、`docs/feature-closure-audit.md` 核大小功能及消费者。任务唯一状态只写所属 stage；handoff 只定位当前模式、现场和最近关键基线。

1. Codex 回填本轮编号、真实实现/偏差、修改文件、准确代码提交、测试命令/结果/环境、未验证项及证据。新问题和建议写本条，不代写网页审核通过。
2. 网页收到“Codex执行完了”后，从最新 `master` 的固定入口读取 handoff / stage，并核真实分支、代码与证据；给通过/需修改/阻塞后重新评估下一步。
3. 若本轮引入或改变模型、工具链、架构、产品语义、协作、权限或治理规则，交接前必须按 `docs/plan-registry.md` §1.1 附**传播核对**：受影响权威面分别标“已更新”或“不适用+理由”。专题文档更新但总方案/索引/账本/Skill 等应更新面遗漏时，本轮不得标文档闭环。
4. 方案确需变化才改原 `implementation-plan.md`；任务状态只在 stage；handoff 不复制整套方案。历史基线不因新方案被批量重写，取代关系写 plan-registry。
5. 先核原位更新、提交/推送和远端可读，再报告本轮已交付。用户不复制任务卡、提交号或下载新 handoff；回写失败时另一端不能只按聊天结论执行。
6. 详细日志留原项目 artifacts 并提供双方可读的必要脱敏证据；密钥、私人持仓、原始私人聊天不进入共享仓库。
7. 审核代码提交与后续协调文档提交分开；最终合并仍要准确候选 SHA 的网页审核/完整 CI。作者自检不冒充独立审核。
8. 编号不复用；退出/合并有依据和去向。下一轮始终先从最新 `master` 调用 `ashare-ledger-continue` 恢复上下文，不从旧会话或已删除功能分支猜现场。若 handoff 允许实施，用户只需明确说“继续任务/继续”即可授权该 Skill 动态领取一个最高优先级可开工切片；若仍处 REVIEW/BLOCKED 或排序不唯一则只报告，不执行。

短提示只是触发读取，不是跳过安全、费用、生产、发布或传播核对的授权。
