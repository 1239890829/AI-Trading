# 原位交接

全项目范围：执行前按docs/product-closure-design.md、docs/hunting-decision-design.md和docs/feature-closure-audit.md核大小功能及当前切片消费者。局部补充不替代主任务；后台开放情境，前台简洁不删必要能力。收尾必须核原任务、新要求、事实回填及剩余项，不能以答完猎场问题结束整批。

依据AGENTS和docs/collaboration-workflow.md，任务唯一状态只写所属阶段；handoff只定位当前任务、工作区和证据。自动转递/Bridge不是前置，旧全自动要求已被用户选择的短提示接力替代。

1. Codex回填本轮编号、真实实现/偏差、修改文件、准确代码提交、测试命令/结果/环境、未验证项及证据定位。执行中发现新问题与建议也写在本条目，不代写网页审核通过。
2. 网页收到“Codex执行完了”后，从最新 `master` 的固定共享入口读取 handoff / stage，并核真实功能分支代码与证据，给通过/需修改/阻塞。审完还要复评功能衔接、遗漏、可复用部分、成本、风险及低成本替代，只有净收益有依据才调整计划和任务。
3. 审核结论与下一动作写回同一阶段条目；方案确需变化才改原implementation-plan，总账只更新索引/排序。保留前任贡献、被审代码版本和限制，不能事后降低原验收门槛。
4. 先核原位更新、提交/推送和远端可读，再报告本轮已交付。用户不再复制任务卡或下载新handoff文件；回写失败时明确说明，另一端不可只根据聊天结论执行。
5. 详细日志留原项目artifacts并提供双方确实可读的必要脱敏证据；只有仓内摘要不代表网页读过本机原始记录，读不到时保持未核验。密钥/私人持仓/原始私人聊天不进入共享仓库。
6. 审核代码提交与后续协调文档提交分开，旧审核不自动覆盖新代码；最终合并仍要准确候选SHA的网页审核/完整CI，按既有PR审查留证，不造自指提交循环或额外批准平台。
7. 编号不复用；退出/合并有依据和去向，完成只留必要结论。当前自动化的退出不写成已成功交付；未知资产和唯一证据不删。文档检查与受影响回归按范围运行，不为纯文案重复全部业务构建。
8. 下一轮先看最新 `master` 的当前实际记录，再定位 handoff 指定的施工分支；不能根据最近窗口、旧下载稿、已删除功能分支或用户“审核完了”几个字猜现场。重复通知不重复实施；会话可换，项目、任务、版本和证据不得丢。

本机与远端有冲突或旧执行者仍活跃时保全现场并先核实；短提示是触发读取，不是跳过安全、费用、生产或发布约束的授权。
