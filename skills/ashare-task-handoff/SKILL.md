# 任务交接

先读 AGENTS.md 与 docs/implementation-plan.md；任务从 docs/retro-and-gaps.md §6.0 进入 docs/stages/ 的唯一条目。不要恢复 A–F/H 多表同步，也不在 handoff 新建任务明细。

1. 只更新所属阶段任务的状态、范围、验收、证据、下一步和恢复。部分交付写余下条件；完成须有实测及 PR/commit，退出/合并使用“已退出/已合并”，补“处置依据”和“合并至”有效 ID；在所属阶段保留简短条目，不能算成功交付，也不追加到冻结的旧号迁移表。仍支撑依赖的完成成果留本阶段简短基线，其余由 Git 和历史处置记录追溯。
2. docs/handoff.md §1 只替换当前分支/工作区、在途交付、实际运行版本、未跟踪资产归属、最近门禁及预算。历史长日志放忽略的 artifacts；知识回已有专题/KB。测试数不复制到 AGENTS，passed 与 skipped 分开报，注明负载和服务前提。
3. 按 AGENTS §1 完整验收，跑 python3 scripts/doc-health.py。P 检查十阶段双向索引、跟踪路径和反链；Q 检查任务唯一、合法状态、证据、依赖无环和旧号去向。缺载体/空判定面必须报错；新文件先精确暂存，迁移在干净检出复验。
4. 按 AGENTS §6.5 精确暂存与审阅，核 git diff --exit-code、暂存范围/正文/补丁和未跟踪清单。提交后查实际 commit 文件集，不能吸收用户资产或清脏树求干净。
5. 发布前刷新分钟预算，按 IMP-043 持续比较 job/安装/测试耗时、重复次数和真实账单，优先后端隔离与慢项；不为度量增加 Actions，不删测试或绕检查。
6. 合并按 scripts/audit/release_check.py 核准确 PR HEAD、最新主干、最新 CI attempt 和三 job；空集、API 失败、skipped/cancelled 不算绿，新提交/base 漂移/重跑使旧核验失效。满足既有长期授权则合并，随后核 master CI、实际运行版本及提交可达再清理本任务分支；未加载生产必须说清。

本技能不扩大安全权限。外部条件不满足时保存可恢复现场和具体阻塞，不将本地完成写成已发布；一次交接不复制全仓任务表或建立新的 MEMORY 权威入口。

更换执行者时，在 handoff 记录前任/接手者、接手日期、来源任务、接手 HEAD 和继承差异；明确各自完成内容及未验证部分。不得修改旧会话来伪装连续执行，后续按最新 Git 与验收回执接续。

交接必须说明本轮只修文档、做局部复现还是已修业务代码；把前任成果、接手增量、待实现项分开。详细证据优先保存在原项目 artifacts/runs 的持久目录；不能只留 /tmp 路径，也不能把上一提交的全量结果冒充当前提交已验。
