# 任务交接

先读项目 `AGENTS.md`。任务唯一状态在 `docs/retro-and-gaps.md` §6.0，
`docs/handoff.md` 仅存明细；文档入口为 `docs/INDEX.md`。不另建任务清单或 MEMORY 权威文件。

## 当轮收口

1. 更新账本任务行及 §6.0-H 索引；在 handoff 新增或更新 `## <任务 ID>`，首行回链账本 §6.0。
   同步 handoff §2 索引与 §1 现场：分支、提交、实际服务、测试前提、在途及未跟踪资产归属。
2. 闭环时同时从 A–E 移出、在 F 留档、H 标闭环；只做后两项会重复领取已完成工作。
   部分交付保留开放状态，明确未完成的验收条件；任务编号永不复用。
3. 更新账本当前入口与最新停止点，用户调整施工顺序须注明来源；其它历史轮次不冒充当前指针。
4. 运行 `python3 scripts/doc-health.py`，并按 `AGENTS.md` §1 跑完整门禁。
   修改 docs 仍会触发后端文档守卫。长日志放忽略的 `artifacts/`，有价值的结论提炼到既有 KB。
   若写逐日日志，写前/后各取 `wc -l`，单轮新增 ≤80 行；不改写旧轮次。
5. 按 §6.5 核对暂存范围、提交正文与远端 PR；合并必须满足本地门禁、精确 CI、当前主干、
   审查意见、敏感信息与授权全部条件。使用 `scripts/audit/release_check.py` 获取核验证据，
   不把 API 失败或空检查集当绿，也不把客户端检查称作服务端分支保护。
6. 提交后核对任务工作区干净；合并后刷新主干、验证提交可达与 master CI，才删除本任务分支。
   因外部条件无法交付时保留 PR 与现场并如实登记，不能把本地 commit 写成已交付。

## 明细七字段

沿用 `docs/handoff.md` §0 模板：账本/日期/状态、缺口与验收、改动、机械证据、
注入自证、门禁、遗留与下一步。门禁数字写本轮实测并同步 `AGENTS.md` §1；
collect 增量区分 passed 和参数化 skipped，不能把跳过数增加记为覆盖增强。

## 指针与守卫的易错边界

- P 交接索引须双向闭合，ID 只取表格第一列；自然语言提及不能算任务条目。
  缺章节、空结果、漏回链均应判红。
- Q 档位一致性需区分 F 与 H；H 中闭环必须在 F 有记录，不能仍留未完成档。
- 检出可用性由 Git 跟踪清单判定；本机有忽略目录不等于 CI 有。
  新文件先精确暂存，删除后的跟踪清单也必须再验，避免旧路径靠本机残留假绿。
- 引用章节先确认锚点；历史轮次节号不等于账本当前节号。恢复清单、缓存、私有凭据不入 Git。
