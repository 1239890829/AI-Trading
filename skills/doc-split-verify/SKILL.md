# 文档按子类拆分（零丢失 + 引用面同步）

## 0. 先判「该不该拆」——阈值要分清是硬门还是触发条件

| 约束 | 性质 | 动作 |
|---|---|---|
| **条目级**（单条 ≤N 行） | **硬门**，不过就是违规 | 超长 ⇒ 拆知识点 |
| **文件级**（总量 >N 行） | 多数规范里只是「**评估**拆分」的**触发条件**，非硬 FAIL | 先评估，能拆则拆 |

⚠️ 先读自己项目的规范原文，别把「触发条件」当成硬门去恐慌性拆分；
反之若规范写的是硬门，也不要拿「只是提示」自我豁免。**这条口径差本身常是历史遗留的 bug**（检查脚本实现得比规范更严/更松）。

拆分三条件（满足其一即可，但**必须有共同索引页**）：
1. 超所在层阈值且**主题可分离** 2. 服务于不同时点的决策 3. 更新频率差异大

## 1. 分类轴：按「内容/缺陷发生在哪一层」，不按编号段切

反例：`01~26 一份 / 27~56 一份` —— 读者 30 秒内判断不出该读哪份。
正例（实测好用）：按**缺陷发生的层**分
- 操作层（怎么用工具，短条目）
- **验证层**（测试/门禁/CI/环境——"你用来验证的东西本身会骗你"）
- **数据契约层**（写入/去重/传输/时间/质量门）
- 应用与设计层（架构/接口/口径判据/前端/方法论）

规模参考：每份 **8 条以上、约 250~400 行**为宜。低于 8 条就别拆（拆分有断引用成本，阈值过低会反复重组）。

**保留一份"母文件"是正常且诚实的做法**——写明「本文件 = 其余各层未覆盖者」，比硬凑一个假主题好。

## 2. 执行：只搬不重写 + 脚本化

1. **先备份原件**（`cp` 到 /tmp），它是唯一可信的比对基准。
2. 解析成**条目字典**（按标题切块，块内逐字节保留），**不要在搬运时顺手改写文字**。
   拆分应该是一次纯移动；任何"顺手优化措辞"都会让核对失效、也会藏进新错误。
3. 新文件头部要写明：定位 / 与本套其他册的分工 / **共同索引页** / 拆分依据（引用规范条目）。
4. 保留条目**编号升序**（或原序），别重排。

## 3. 独立复核：哈希逐条比对，不靠肉眼

以**拆前副本**为基准（不是靠脚本自证），逐条比：

```python
def parse(path):
    lines = pathlib.Path(path).read_text(encoding="utf-8").splitlines()
    st = [i for i, l in enumerate(lines) if re.match(r"^### ID-\d+", l)]
    out = {}
    for j, s in enumerate(st):
        e = st[j+1] if j+1 < len(st) else len(lines)
        out[re.match(r"^### (ID-\d+)", lines[s]).group(1)] = "\n".join(lines[s:e]).rstrip("\n")
    return out
```

必须同时断言四件事：
1. **零丢失**（原件每条都在）
2. **零重复**（同一编号不出现在两个文件里）
3. **正文逐字节一致**（逐条 sha256 比对）
4. **编号无缺号**（`range(min,max+1)` 全覆盖）

只看「行数差不多」或「我搬的是整块」都不算复核。

## 4. 引用面同步（最容易漏）

- **全局 ID 引用（`[[KB-XXX-NN]]` 这种）不受搬家影响** —— 前提是项目有**唯一的登记页**。拆分前先确认它存在；没有就先建。
- **必须更新的**：登记页（含文件分工说明）、文档地图 / AGENTS 类手册、各册互相指路的抬头。
- **不要动的**：逐日日志、台账「去向表」、「原件已删除」注记 —— 这些是**记录性引用**，
  描述的是「当时」的状态，改了等于抹掉治理痕迹。
  判别信号：同句含「已删除/已归档/被取代/移入/去向」等词 ⇒ 记录性，别改。
- **册名级指针**（`见 kb/03-xxx.md 的 KB-ENG-39`）是全套里最脆的一环：条目一搬家它就静默指错。
  拆完**必须专项审计**：扫「同句同时出现 `kb/NN-x.md` 与 `KB-ID`」，逐处判读；
  再决定要不要做成门禁（见 §5 的窄触发原则）。

## 5. 给检查器补「覆盖守卫」（如果拆分会让新文件逃出扫描面）

**真实事故形态**：检查脚本用 `glob("0[1-9]*.md")` 选文件 ⇒ 只覆盖 `01~09`；
新建 `10-*.md` **不被任何检查看到**（不查条目长度、也不出体积提示）——
**"没进检查"与"检查通过"在输出上完全一样，都是全绿。**

三条修法：
1. **扫描面收成一个入口函数**（多处共用），不要两处各写一遍 glob —— 否则只会改到一处。
2. **配覆盖守卫**：枚举全部应扫对象，凡「没被任何检查覆盖」的文件直接 FAIL。
   这样「新增文件即自动纳入」不依赖有人记得改 glob。
3. **门禁触发先量假阳性再定档**。宽触发（如「同行出现即比对」）常因**记录性引用与长句巧合**
   产生大量误报 —— 实测 23 命中 / 0 真阳性就是典型 ⇒ 会变成「永远红的门禁」，**宁可否决**。
   改窄触发（只认明确的指针句式）后 1 命中 / 0 误报，才值得上缴。

**新守卫必须做注入验证**：造一个必然违规的样本，确认它**真的变红**并报出位置。
只断言「守卫存在」= 假守卫（常量被 import 但表达式没用它，照样绿）。

## 6. 收尾清单

- [ ] 原件已备份；拆后逐条哈希比对通过（零丢失/零重复/逐字节一致/无缺号）
- [ ] 登记页 + 文档地图 + 各册抬头已同步为「N 册」描述
- [ ] 记录性引用**未被动过**（逐处判读过，不是靠正则一刀切）
- [ ] 册名级指针专项审计完成（0 处真误指针 或 已修）
- [ ] 检查器覆盖守卫已加 + 注入验证变红
- [ ] 全量门禁跑过（**文档改动也要跑** —— "无行为变更"这句话只有门禁全绿才配写）
- [ ] 探针/临时文件走回收站，不用 `rm`
