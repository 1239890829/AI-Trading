# 外部创新雷达

本 Skill 解决“系统不能只等用户告诉我们外界发生了什么”。它负责**发现、核实、筛选和设计验证**，不拥有生产采用权，也不建立第二套 backlog。

## 1. 启动前读取

始终从最新 `master` 读取：

1. `AGENTS.md`
2. `docs/implementation-plan.md`
3. `docs/continuous-evolution.md`
4. `docs/plan-registry.md`
5. `docs/INDEX.md`
6. `docs/retro-and-gaps.md` 与真正相关的 `docs/stages/*`
7. 与候选相关的专题蓝图、KB、策略/因子/数据登记；AI候选同时读 `docs/jev-integration.md`

先知道现有能力和已否证方案，再去外部找，避免重复研究和“换名字重做”。

## 2. 默认只读

普通雷达轮只允许：

- 搜索/读取官方文档、版本、仓库、issue/PR、原始论文、标准与监管资料；
- 比较当前系统与外部候选；
- 记录来源、假设、风险、验证计划和生命周期建议；
- 将长扫描证据放忽略的 `artifacts/radar/`。

未经对应任务明确授权，不：

- 安装软件或插件；
- 写 API key / 凭据；
- 注册付费服务或消耗未批准预算；
- 改生产配置、阈值、策略、模型路由；
- 扩大 Agent/工具权限；
- 把外部代码直接搬进仓库；
- 让一个热门候选自动生成施工任务。

## 3. 搜索面

每轮按任务需要覆盖，而不是机械全扫：

- AI/LLM/Jev/Agent/Skill/MCP/协议；
- A股量化、选股、事件/题材、资金/筹码、市场状态、执行与风险；
- 时间序列/金融基础模型；
- 数据源与数据质量；
- 回测、walk-forward、因果/消融和研究治理；
- 工程、数据库、缓存、调度、可观测、CI、安全；
- 产品交互和信息表达；
- 监管/交易所/市场微观结构变化。

同时主动搜当前方案的**反证和替代**，不能只搜支持现状的材料。

## 4. 来源纪律

优先级：

1. 官方规范/文档/发行说明/仓库、监管/交易所、原始论文；
2. 可复现实验、官方 issue/PR、独立 benchmark；
3. 高质量技术文章和成熟社区讨论；
4. 热榜、营销、社媒只作为线索。

任何二手说法都要尽量回原始来源。Stars、下载量、榜单名次、作者自报收益只能影响“是否值得核查”，不能影响最终准入。

## 5. 候选卡

每个值得保留的候选至少回答：

- **identity**：名称、版本/commit、来源、核查日期；
- **problem**：它解决什么真实问题；本项目是否真的存在该问题；
- **baseline**：现在怎么做，哪里不足；
- **increment**：候选相对基线的新能力是什么，不是换名重复；
- **claims_vs_verified**：外部声称什么；本轮实际核实了什么；
- **fit**：A股/当前架构/数据/权限是否适配；
- **license_security_privacy**：许可、供应链、secret、遥测、权限；
- **cost**：费用、token、延迟、CPU/内存、维护、CI；
- **failure_and_fallback**：失败模式、降级、锁定版本与恢复；
- **falsifier**：什么实验结果会否定采用；
- **evidence_level**：E0–E5；
- **state**：DISCOVERED / TRIAGED / WATCH / SHORTLISTED / LAB / SHADOW / ADMISSION_CANDIDATE / REJECTED / RETIRE；
- **owner**：若进入实验，应由哪个现有 stage/任务拥有；没有明确实验价值时不创建任务；
- **revisit_trigger**：观察/拒绝后什么变化才重开。

不要给候选做一个掩盖硬风险的总分或排行榜。

## 6. 筛选顺序

```text
有真实问题？
  否 → REJECT / 不记录噪声
  是
   ↓
原始来源可核？许可/权限/隐私/费用硬门可接受？
  否 → REJECT / WATCH
  是
   ↓
相比当前机制有独立增量？
  否 → REFERENCE / REJECT
  是
   ↓
最小 E2 复现值得做？
  否 → WATCH
  是 → SHORTLISTED，交给网页规划侧决定是否派 LAB 切片
```

只有 LAB 以后才讨论 SHADOW/CHALLENGER；任何生产采用仍走原 stage、PR、网页审核、CI 和运行/研究准入。

## 7. Jev 的角色

Jev 可以在候选很多时做 bounded：

- 主题/用途分类；
- 与现有任务的重复度判断；
- relevance / shortlist 辅助；
- 多个真实候选的受限路由；
- 证据→主张支持关系的旁路验证。

Jev 不决定“是否采用某技术”，不把 confidence 当技术正确率或投资收益。确定性许可/版本/依赖/数值比较先由代码或原始事实处理；复杂技术取舍升级给 DeepSeek/Codex/ChatGPT，最后靠实验。

## 8. 量化/选股候选附加门

新因子、战法、模型或“高胜率方法”必须额外写：

- 经济/市场机制或可证伪假设；
- 数据当时是否可见、是否含未来信息；
- A股规则和历史股票池适配；
- 手续费/滑点/涨跌停/T+1/停牌/可成交性；
- 样本数、purged walk-forward/embargo、分市场状态；
- 参数搜索/多重试验和幸存者偏差控制；
- 与现有因子/策略的结构新颖性；
- Champion 对照与失败条件。

论文、其他市场回测或单只股票案例不直接进入策略登记的现役层。

## 9. 输出纪律

正常一次雷达轮应当很短：

- **值得立即深入**：最多少量 SHORTLISTED，给最小验证切片；
- **观察**：有潜力但缺条件，给重开触发；
- **拒绝/仅参考**：说明最关键原因；
- **对现方案的挑战**：若新证据足以改变长期方案，明确触发 `plan-registry.md` §1.1 传播核对。

没有高价值候选时直接报告“本轮无值得升级项”。这比为了显示进化而硬造任务更正确。

## 10. 持续校准本 Skill

每若干真实轮次复核：

- 发现的候选中多少真正产生 E3/E4 增量；
- 哪些来源长期高噪声；
- 哪些重大变化是事后才发现、为什么漏；
- 扫描本身消耗的 token/网络/时间；
- 是否积压大量永不验证的 WATCH。

根据结果调整来源、频率和分类，而不是永久固定今天的雷达规则。
