# Anti-Patterns

## 1. Existing = Necessary
“已经有了，所以应该保留。”

纠偏：重新证明用途、消费者、增量和成本。

## 2. Passed Test = Business Value
“测试通过了，所以功能有效。”

纠偏：工程正确性与业务/研究效果分层验证。

## 3. Winner Story
“这个成功案例说明规律成立。”

纠偏：补全失败对照、全分母、漏选和反例。

## 4. Feature Accumulation
“能力不够就再加一个模块/Agent/规则。”

纠偏：先比较最小修补、复用、合并和删除。

## 5. Taxonomy Prison
“为了好管理，把现实锁死在固定几类。”

纠偏：允许 unknown/unclassified；有限枚举仅限 bounded experiment。

## 6. Autonomous Theater
“系统要自主，所以应该自动调参/升级/改生产。”

纠偏：自主发现和验证，不自主获得生产授权。

## 7. Knowledge Hoarding
“KB 越大越好。”

纠偏：知识必须有消费者、适用域、反例和贡献反馈。

## 8. Confidence Substitution
“模型置信度很高，所以判断可靠。”

纠偏：回到独立 gold、真实数据和可复现实验。

## 9. Backlog Gravity
“任务已经在计划里，所以迟早必须做。”

纠偏：任务本身持续接受价值审核，可合并/退出/WATCH。

## 10. Permanent Winner
“过去长期有效，所以继续用。”

纠偏：所有机制只有阶段性证据资格；监控衰退和 regime 变化。

## 11. Cost Blindness
“便宜模型/自动化一定节省。”

纠偏：质量相同条件下测 token、调用、延迟、返工和维护。

## 12. Documentation Completion Illusion
“设计文档写完了，所以方案完成了。”

纠偏：区分设计、实现、运行、效果、用户价值五种证据。
