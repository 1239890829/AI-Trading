# 测试间接写真实数据文件：定位 · 隔离 · 注入验证

## 为什么难：写入口不在被测对象的调用栈里

测试通常存在一条间接调用链（用例 → 路由 → 服务 → 落盘），但测试文件可能没有直接引用落盘模块。
逐层追踪调用与运行副作用，不以“测试中没有同名引用”推断没有覆盖或没有副作用。
语句覆盖率只能表明代码执行过，不能证明写入目标正确。

**症状**：测试全绿、无失败、无告警，但仓库里某个运行时文件的内容变了。

## 四步工作流

### 1. 内容级取证（不要靠 mtime 推断）

mtime 窗口边界靠估、不可靠。做法：

1. `git status` / `git diff` 看该文件有没有变动；若未被跟踪，用 `git show HEAD:<path>`
   （曾跟踪过就能拿到历史版本）对比内容。
2. **挑「与数据源实现强绑定的量」当判据**。
   例：`symbols_seen=6` 恰等于 mock 的 `UNIVERSE[:6]`；`days_with_pool=30` 恰因 mock
   对**任何日历日**都给池 ⇒ 这类量**只有 mock 源能产出**，是决定性的。
3. ⚠️ **不要挑「看着像不像有内容」的量**（空字典 / 空列表）——真实数据在特定条件下
   同样为空，会把正常状态误判成污染。**判据本身也要复核**。

**先确认「是测试写的」再动手**：也可能是自己的验证脚本写的（自伤）。
单独跑、组合跑各一轮，确认干净复跑零写入，才能定案。

### 2. 实测完整影响面（别猜，跑一遍数）

先建立只读护栏，再运行测试；禁止关闭隔离后对生产目录做污染实验。

1. 检查 conftest 的数据库、文件路径和后台调度隔离。内存库不代表文件也隔离。
2. 在独立测试进程中拒绝生产数据目录写入和外网连接，记录被拒操作、路径及调用栈；可用操作系统沙箱，或用 Python 审计钩子作应用级探针。
3. Python 审计钩子不是安全容器：原生扩展、子进程并非全覆盖；执行未知代码必须使用真正的受限环境。
4. 报告原始测试数量、加强约束、失败分类；不得把拒网/拒写条件下的失败说成原始门禁回归，也不得撤护栏凑全绿。
5. 对发现的写路径在测试入口重定向到项目内隔离目录，读写两侧必须一致；涉及初始数据时使用脱敏合成夹具，不搬生产秘密。
6. 保留磁盘快照或哈希作为辅助证据，mtime 仅供定位，不能独立证明责任来源。文件/内容检索使用 Glob/Grep。

本仓复现样例：`app.predict.storage.REPORT_DIR` 未被 conftest 隔离；7 个 `test_predict` 用例尝试写生产 `data/review/predictions/2099120*.json`，在写入前拒绝后可取得完整调用链。

### 3. 单点沙箱化（不做无差别重定向）

在 `conftest.py` 顶部，改**入口模块的属性**指向临时目录：

```python
_DATA_SANDBOX = Path(tempfile.mkdtemp(prefix="ashare-test-data-"))

import app.services.leader_archive as _leader_archive_mod
_leader_archive_mod.ARCHIVE_PATH = _DATA_SANDBOX / "leader_archive.json"
```

要点：

- **改入口模块属性，不改业务代码**（业务代码零改动 ⇒ 风险面最小）；
- **不做无差别重定向**——同目录下同类常量可能有一二十个，其中多数会被**读**；
- 放在 conftest **顶部**（collection 期即生效，早于任何 fixture）；
- 注释写清**触发链 + 判据 + 影响面实测方法**，否则下一个人会以为这段是多余的；
- 若项目已有同类隔离先例（如 `REPORT_DIR`），**沿用同一范式**，别另发明。

### 4. 加覆盖守卫 —— 并给守卫做**注入验证**

守卫两层：

1. **AST 清点 + 登记表**：扫描「模块级赋值 + 表达式含 `__file__` 与 `'data'` 字面量」的路径，
   与登记表**双向对齐**（未登记 → 失败；登记了但源码已无此项 → 也失败）。
   这样**新增对象自动纳入检查面**。
2. **功能回归**：用桩 provider 直接调写入口，断言文件**落在沙箱里**（不只看变量值）。

> **⚠️ 新增守卫必须做「注入验证」**：把被守的东西**弄失效**（摘掉隔离 / 改回真实路径），
> 确认守卫**变红**。否则「全绿」只证明它没报错，**不证明它在守**。

**真实教训**：守卫首版把「项目根」算成了仓库根
（`_REPO_DATA = Path(__file__).resolve().parents[2]`，而该文件在 `tests/` 下），
使 `if _REPO_DATA in current.parents` **恒真** ⇒ 注入验证时**仍然全绿**，
四个测试全 passed 却根本没在守。

> ⚠️ **`parents[N]` 的层级随文件位置变**：同一个「项目根」，
> 写在 `app/<pkg>/<mod>.py` 里是 `parents[2]`，写在 `tests/<file>.py` 里是 `parents[1]`。
> **写守卫时先在测试里打印一次实际解析结果**，别凭层级数字推。

## 同类变体：测试触网（表现是**假绿**，不是假红）

与「写真实数据文件」同族、但更隐蔽的一种间接副作用：**测试真的连上了外部服务**。

2026-09-16 实测（`IMP-038`：给逐笔成交接 TDX **TCP 直连**备源）：
- 新源走 TCP 7709，`ASHARE_DATA_PROVIDER=mock` **替不掉它**；
- 单测桩返回 `[]` ⇒ 降级链判"链失败" ⇒ **降级到新源** ⇒ 真的建连并拿到 **200 行真数据**；
- 断言碰巧被真数据满足 ⇒ **用例"过"了**（两条既有用例同时这样"过"）。
⇒ **表现是假绿，比假红难发现**：无报错、无告警，只是单测悄悄变成
「**有网才过、结果随行情变**」—— CI 上无外网就红，本地永远绿。

**处方（三步，缺一不可）**：
1. **直连型外部源一律排链后做备源**，除非确认该端点**没有任何既有用例**
   （**不要用"它更快"当排前面的理由**）。
2. **给新源加显式开关**：`settings.<xxx>_enabled`（默认 `True`），并在 `tests/conftest.py` 置 `false`；
   要测降级链本身时用 fixture 显式打开 + **注入假实现**（仍然不触网）。
3. **同轮同步根 `.env.example`**（不在 `backend/`）——
   `tests/test_env_docs.py` 扫 `config.py` 字段集 ⇄ `ASHARE_*` 键，漏一行立刻红。

⚠️ **发现"正在触网"的最快办法**：把开关关掉再跑一遍受影响的用例 ——
**若某条由绿变红，说明它此前依赖了真实网络**。这比读代码快。
⚠️ **别把"测试触网"误判成"环境不稳"**：它的红只出现在无网/异网环境（CI），本地恒绿 ⇒
**"本地全绿"不构成 CI 绿**（与时区同族：宿主属性不改代码也能翻断言）。
⚠️ 修法是**加开关 / 容错取值形态**，**不是改断言**。

## 收尾清单

- [ ] 污染文件已**入回收站**（不 `rm`），不是静默留下
- [ ] 被污染的数据用**真实数据源**重建，并记录对照量（如 `symbols_seen` 6 → 789）
- [ ] 在只读护栏下完成验证，并说明应用级护栏的覆盖限制；不要仅凭 mtime 不变宣称所有路径零写入
- [ ] 守卫在**正常态全绿 + 注入态变红**，两个方向都实测过
- [ ] 事故与判据入知识库（**含「伪判据」的自我纠正**），索引状态同步

## 附带收益：仓库跟踪口径

运行时状态文件若**缺文件时代码能自建 / 降级**，入库只带来噪声（每次重建产生整文件 diff）。
处置：`git rm --cached <path>`（**保留磁盘文件**，不是删除）+ 写进 `.gitignore`。

⚠️ 这类约定通常在 `.gitignore` 里**已有一节**（如「运行时状态文件」）——
先去看有没有，往往只是**漏了一项**，不必新立规则。
