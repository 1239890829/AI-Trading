# 折叠 / 披露式改动的双向验收

**核心判断**：折叠是**双刃**的，两条风险方向相反，必须同时验收——

| 方向 | 风险 | 失效表现 | 一句话判据 |
|---|---|---|---|
| 藏够了没 | 折了个寂寞，噪音原样回来 | 默认态里被藏项还在 | **默认必须折** |
| 还找得到吗 | 内容被藏 ⇒ 检索也够不着 | 用户搜不到 ⇒ 认为"没有这个东西" | **检索必须穿透** |

只验一条就上线 = 用整洁换走了可检索性（或反之）。**这两条契约要写成方向相反的测试**：
任一被单独"优化"掉，另一条立刻变红。

## 标准流程

### 1. 先定位根因是不是「口径」

折叠前先回答：**默认全展开这件事，是当初的决策口径，还是实现顺手？**
查当时的决策记录。若记录只写了功能名（如「树+搜索+跳转」）而**没定义范围**，
那 `rglob` / `querySelectorAll` 式的无差别扫描就是**实现顺手，不是口径** ⇒ 可放心改。
（若能查到明确口径，则属口径变更，要先提后做。）

### 2. 分层判定放后端，默认呈现放前端

- **后端**：给每份对象打 `tier` / `bucket` 字段。**未登记的新对象落"展开可见"那一档**——
  失败要可见：新内容宁多占版面，也不静默钻进折叠区。
- **前端**：只按 `tier` 渲染分组与折叠，不自己猜。

### 3. 渲染实测（文本通道，别用推理）

```bash
agent-browser open "http://<host>:<port>/<page>" >/dev/null 2>&1; sleep 3
# 切到目标页签（按可访问名找，别赌 CSS 选择器）
agent-browser eval "(()=>{const b=[...document.querySelectorAll('nav button')];b.find(x=>x.textContent.trim()==='<页签名>').click();return 'ok';})()"
sleep 2
# 一次拿全：分组标题 + 折叠按钮文案 + aria 状态 + 实际渲染条目数
agent-browser eval "(()=>{const btns=[...document.querySelectorAll('button')];const t=btns.find(b=>(b.textContent||'').includes('<折叠按钮关键词>'));return JSON.stringify({groups:[...document.querySelectorAll('p')].map(p=>p.textContent.trim()).filter(x=>/<分组关键词>/.test(x)),toggle:t?t.textContent.trim():null,ariaExpanded:t?t.getAttribute('aria-expanded'):null,rows:btns.filter(b=>/<条目特征>/.test(b.textContent)).length});})()"
```

逐项核对：**默认条目数 = 后端展开档计数**、展开后 = 全量、`aria-expanded` 翻转、
子分组计数加总 = 折叠按钮上的总数。

### 4. 两条契约各测一遍

1. **默认态**：DOM 里**不应存在**被藏项；折叠按钮须报出被藏总数（否则用户不知道还有东西）。
2. **穿透态**：搜一个**只存在于被藏区**的名字 ⇒ 必须命中。
   顺带验两个配套文案，它们常被漏：
   - 搜索态下折叠控件应 `disabled`（已自动展开，别留"点了没反应"的死控件）；
   - **空结果文案必须声明检索范围**（如「无匹配文档（含历史与日志）」），
     否则用户会以为没搜那部分。

### 5. 逐向注入验证（全绿只证明没报错）

| 注入 | 应命中 |
|---|---|
| 让折叠恒开 | 「默认必须折」 |
| 让自动展开失效 | 「检索必须穿透」 |
| 把后端 fallback 改成"藏起来"那档 | 「新内容不被静默隐藏」 |

每条注入**必须精确命中对应测试**并看到有意义的报文；报红数不对或全绿 = 测试没守住。

### 6. 回滚注入后**再跑一次渲染验收**

最容易漏的一步：注入期间改的就是被测代码。回滚后必须重跑第 3 步，
否则**验收的是被改坏的版本**。

## 坑

- **别用 DOM 条目数当唯一判据**：过滤态下数量天然变少，要验的是"特定名字在不在"。
- **折叠控件缺 `aria-expanded`**：验收时只能靠数 DOM 按钮判态 —— 这本身就是该补属性的实证证据。
- **体检脚本会误报**：测试/示例里出现被归档对象的**名字**（当搜索关键词用）会被"死引用"检查抓到。
  按已有的例外登记机制写理由，**不要放宽扫描面**（扫描面写窄 = 全绿假象）。
- **改例外登记后必须复跑确认命中**：登记到错的常量上，复跑仍报红 —— 不能假定生效。
- 收尾 `agent-browser close`；确认常规服务端口仍在跑。
