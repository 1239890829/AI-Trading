# 入口文件装配切出（环先取证 + 断言保真）

## 0. 先分两件事：环清查 ≠ 装配拆分

审计里常把「存在 import 环」与「入口太长」写成一件事。**不要合并执行**：
环是**事实问题**（有/没有、会不会炸），拆分是**结构问题**。先各自动手前取证，
结论不成立就**只做拆分并销掉另一半**——不要为凑审计结论制造重构。

## 1. import 环：必须分两张图，混算必然得出"到处都是环"

**核心判据**：

| 图 | 参与加载期依赖？ | 会不会 ImportError |
|---|---|---|
| **模块级** import | 会 | **会**（真环） |
| **函数内** import（延迟导入） | 不会 | 不会（常被用来**破环**） |

混在一张图里算：实测某中型仓库会把 **196 文件 / 585 条延迟导入**全报成环
⇒ 得出"到处都是环"的假象。**必须 `module_level=True/False` 分建两张图**（Tarjan SCC）。

**扫描面必须排除虚拟环境**：`backend/` 下同时存在 `.venv` 与 `.venv-research`（数万个第三方 `.py`）
⇒ 递归会爆掉（`exit 137`）。用**项目文件白名单**（只认 `app/` `tests/` `scripts/`）而非黑名单。

### 1.1 写检测器时最容易自己踩的两个静默 bug

1. **BFS 求最短环时把"回到起点"的边也过滤掉**（起点恒在 `seen` 里）
   ⇒ **环找得到、路径永远打印不出**（静默返空，极易被当成"没有环"）。
   修法：`if w == start: prev[start] = u; found = True; break` **置于 `seen` 过滤之前**。
   ⇒ **纪律：「找不到路径」与「没有环」必须靠失败文案区分**，否则工具在骗自己。

2. 只打印环的成员、不打印**成因**。没有成因就无法判断修法：
   实测环的成因往往藏在 `__init__.py` 的 re-export 与被 re-export 模块的**模块级回引**之间。

### 1.2 危害要实证，不要推理

「有环」不等于「会炸」。实测：一个环**当前能正常跑**，
**仅交换 `__init__.py` 两行 import 的顺序（零逻辑改动）**即
`ImportError: cannot import name 'X' from partially initialized module`。

⇒ 结论应是「该环能跑**完全依赖行序**，属潜伏缺陷」，而不是"能跑就没事"。
**修法**：从**定义处**导入（`from pkg.mod import X`），而非回引包；
**反向自证**：修复后**再交换行序，若不再报错**，才证明行序依赖真被解除。

### 1.3 函数内环不要顺手改

延迟导入环不参与加载期图、不会 ImportError。解耦它们是**独立决定**（先提后做），
**如实留档**，而不是悄悄重构——否则等于把"顺手改的"混进"为审计做的"。

## 2. 装配拆分：两条保真设计，决定可核性

### 2.1 同名局部别名 ⇒ "行为不变"可机械比对

把 400 行声明清单搬出去时，若逐行改写 `hub` → `services.hub`，
"有没有漏改"就只能**人工审查 400 行**。改成在函数首部绑定**同名局部别名**：

```python
def register_schedulers(reg, app, services):
    hub = services.hub          # 同名别名 ⇒ 下方函数体逐字不动
    alert_engine = services.alert_engine
    ...
```

⇒ 函数体**逐字保真**，「行为不变」变成可机械比对的事实。

### 2.2 延迟导入必须保持延迟

原来在函数内的导入（`import app.picks.shadow` 等）**一律维持函数内**。
提到模块级会**新增加载期环**——用第 1 节的工具核验「改后仍为 0」。

### 2.3 「刻意不搬」要写进注释

有些东西搬走会**毁掉设计意图**，即使搬了更"整齐"：

- **鉴权守卫 + 路由挂载点**：意图是"哪些路由可以没有凭据"在**挂载处**一眼可读；
- **中间件、错误处理器、启动姿态校验**：属于"进程一启动就生效"的层；
- **纯副作用导入**（`Base.metadata` 表注册）：搬动即改变导入时机。

⇒ 显式写下"刻意不搬 + 理由"，否则下一轮的人会当成遗漏再搬一次。

## 3. 保真判据（四路机械，缺一路就有盲区）

| # | 判据 | 抓什么 |
|---|---|---|
| 1 | **对外契约逐条相同**（如 OpenAPI：paths / ops / schemas，**含 `tags` 逐条比对**） | 路由/参数/标签被改动的全部形态 |
| 2 | **注入自证**：删掉一个可见行为 ⇒ 断言必须精确报红 | 判据是否真的在判事 |
| 3 | **纯行为断言**：从契约遍历端点逐条发请求断言最终行为 | 结构式判据对包装对象的盲区（见 §4） |
| 4 | **`git diff` hunk 边界** | 「某一段完全没动」是**可证明**的，不必靠人读 |

**注入自证要能区分"红得有信息量"**：删掉被测行为后，若报「未登记」说明**扫描面没覆盖新文件**；
报「**未传 X**」才证明判据在真判事。只要求"变红"是不够的——
**红得没有信息量 = 判据其实没覆盖到。**

### 3.1 结构式判据常在本版框架下不可用

实测（FastAPI）：`include_router` 生成 `_IncludedRouter` **包装对象**，
其 `original_router.routes` 是**未加 prefix** 的原始路由，
且 `include_router(dependencies=[...])` **不写进**这些对象
⇒ 遍历 `route.dependant` 会得出「176 条全部无守卫」的**错误结论**。

⇒ 改用**行为式**：遍历 `app.openapi()["paths"]` 逐条发无凭据请求断言 401。
⚠️ `app.openapi()` 结果**被实例缓存** ⇒ 注入自证前必须先清 `openapi_schema = None`，否则**假绿**。

## 4. 判据随实现迁移，强度不许降

拆分最常见的假绿来源：**指着旧位置的判据静默失效**。

- 结构臂原来扫 `main.py` **单文件** ⇒ 搬家后必然失效（找不到该调用）。
  **修法 = 扫描面改为装配层白名单**（`main.py` + `bootstrap/*.py`），
  **断言、口径、失败文案一字不改**（可只改测试名）。
- 新目录若属于装配层，**显式登记进分层规则的白名单**——不登记会落进
  "既非装配层也非业务层"的**第三类**而被静默跳过（跳过无害，但会让
  "装配层有哪些"只能靠数文件反推）。
- 凡文档里**按行号**引用代码（`app/main.py:617`）的，一律改**符号名**：
  行号会随搬家漂移，且漂移**不会让任何检查变红**。

## 5. 门禁数字：增量必须归因，别把"没跑的用例"记成"覆盖增强"

**`+N 个文件 ⇒ +N 个测试` ≠ `+N 项覆盖`。** 增量可能**全部是参数化跳过项**。

两个机械核验动作：
1. 解析 `--junitxml` 或 `-rs`，**逐条读出跳过用例名**（别只看总数）；
2. 核对恒等式：`总 skipped − 无关键` = 非业务层模块数 = 各前缀逐项相加。

实测样例：`+3 = 0 passed + 3 skipped`，且
`73 = api/ 30 + bootstrap/ 3 + main.py 1（=34）+ 39（其他）`——**逐字相符**才算归因完成。

⚠️ 「**某一侧不变**」同样是可核对的自洽项：纯后端改动时，
前端测试数应与上轮**逐字一致**，并明确写出"本轮 `git` 核对 `apps/web/` 无改动"。

## 6. 路径存在性类判据：判定面是 git 跟踪清单，不是文件系统

新增文件后跑"路径/锚点存在性"检查（文档代码锚点、索引闭包等）会**误报**——
因为**判定面 = `git ls-files`**（= CI 检出内容），
用 `Path.exists()` 的判据必然「本地恒绿 / CI 恒红」。

⇒ **新增文件必须先 `git add`，再跑这类检查。**
（同源纪律：本地绿 ≠ CI 绿；怀疑时用 `git worktree add --detach /tmp/ci-sim HEAD` 造干净检出复现。）

## 7. 收尾自查清单

- [ ] 环：分两张图取证；有成因；危害有实证；修复有**反向自证**；函数内环**留档未动**
- [ ] 装配：同名别名保真；延迟导入未提前；**刻意不搬**写了理由
- [ ] 判据：契约逐条相同 + 注入自证（**红得有信息量**）+ hunk 边界 + 行为式
- [ ] 迁移：扫描面改白名单，**断言/文案一字未改**；新目录已登记进分层规则
- [ ] 门禁：增量**逐条**归因；"某一侧不变"已核对；路径类检查在 `git add` **之后**跑
- [ ] 欠账：顺手抓出的**既有**指针失效 / 口径未回填，一并修并在提交信息里说明"不是本批引入"
- [ ] 红线：零数据口径变更（未 bump 算法版本、未触碰业务产物）——若触碰则需独立复核动作
