# 盘后复盘

从 `git rev-parse --show-toplevel` 定位项目，先读根目录 `AGENTS.md`。
执行前读 `docs/daily-review-sop.md` 的判据与 `docs/daily-review-checklist.md` 的逐项清单；
定性判断按 `docs/kb/06-review-framework.md`。它们维护完整流程，本技能只补执行入口和易错边界。
任务状态归 `docs/retro-and-gaps.md` §6.0，交接归 `docs/handoff.md`。

## 先确认可用现场

核对当前后端的监听端口、进程身份及 `/api/health` 响应；监听存在不能证明请求正常。
健康异常时先记录错误、源时间及最后成功时间，定位服务故障。
不要为绕开无响应而另起连接同一生产数据库的后台实例。
需要启动、重启或更改实例时按本轮授权与 AGENTS 执行，并验证用户实际使用的实例。

交易日与前一交易日必须由有效日历锚定，不以 weekday 推测；日期无法确认时停止相关比较。
本地日历的 `days` 是日期数组，不能把外层对象键当交易日。
缺失、陈旧、请求失败、合法空结果分别披露；收取时间不能代替源数据日期。
指数 `index_batch` 是最近完成批次的覆盖证据，须结合请求失败记录与新鲜度使用。

## 按清单执行并留证据

- 核验盘前简报、精选、执行闸门、模拟操作、通知和数据链；每项标通过、存疑或异常，附来源。
- 消费系统已有的方向四分类、失败归因和 T−1/T−3 提醒收益，不按主观再造一份统计。
  盘中重生成的简报不能冒充盘前决策；空仓闸门日、无模拟委托是正常状态，不自动记为数据缺口。
- 题材归因按 `core.votes` 成员票型；情绪 bands 标明口径版本和校准日期，避免把口径变化误认成市场变化。
- 限价异常先核 N/C 新股、ST 摘帽及交易板块。调用本项目 `compute_breadth` 复核，
  不用遗漏豁免条件的临时脚本替代系统判据。Parquet 快照在项目根 `data/parquet/snapshots/`，
  需要读取时使用项目后端环境的 `pyarrow.parquet`，不依赖平台专属解释器。
- 区分判断、执行、系统、纪律与外部因素；过程与盈亏结果分开，单案例规律保持待验证。
- 通知检查已有记录与回执，通道配置存在不代表已发送，接口接受不代表送达或阅读。
  复盘本身不授权向外部补发历史通知。

## 接口与处置

接口先核当前 OpenAPI 与调用代码；以下日期/字段差异已有回归约束：

| 用途 | 契约 |
|---|---|
| 复盘报告 `/api/review/reports/{date}` | `YYYYMMDD` |
| 精选复盘 `/api/picks/review?date=` 与生成接口 | `YYYY-MM-DD` |
| `PATCH /api/review/action-items/{id}` | 说明字段 `note`；`rejected/reverted` 必填；提交所读记录的 `trade_date/category/title` 守卫三元组 |

PATCH 前确认记录身份及本轮处置授权；写后按报告日期回读核对状态与说明。
重复项注明承接关系；`applied` 必须对应实际实施与验证，不能把确认提议记成已应用。
每项改进保留 `target`、`proposed_change`、证据、验收和回访条件。
应用内复盘 Agent 只产提议；外部开发任务按既有授权，经独立分支、门禁和 PR 实施。
不得把本技能当作扩大策略、参数、凭据或交易权限的授权。

测试使用项目既有隔离，不在 pytest 后无条件还原生产日历；若发现数据漂移，
先保留前后证据并查写入者，按已确认恢复点处理，不能用 Git 覆盖现场掩盖污染。

## 需要额外研究时

先使用 `docs/kb/01-stock-picking.md` 中的 KB-STOCK-34：产业链八层、稀缺层与证据阶梯。
固定来源数量、公司排名配额和未经验证的评分权重不进入实时策略。
第三方研究工具的许可、输入、费用和执行状态以 `docs/kb/05-repo-tracker.md`
及 `docs/platform-directory-migration.md` 为准；旧平台安装目录保留供审查与恢复，
不沿旧调用命令自动执行未完成迁移验收的包。

## 交付

报告包含：当天错误与证据、归因类别、次日条件与失效条件、改进项处置结果。
缺失或尚未执行的项目明确列出，不写成复盘已全部完成。
机会表述带「不构成买卖建议」；开发改动的实测与交接按项目交接技能回填。
