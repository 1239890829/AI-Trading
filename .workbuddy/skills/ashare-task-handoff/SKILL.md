# 任务交接：账本索引 ⇄ 明细条目（双向、当轮、机械可查）

项目：`/Users/hezifeng/Desktop/project/ms/ashare-ai-trader`

> **本文件不含任务清单、不复制任何任务状态。** 唯一任务清单是
> `docs/retro-and-gaps.md` **§6.0**；唯一明细层是 `docs/handoff.md`。
> 本文件只描述「**怎么让这两者始终对得上**」——复制内容 = 制造第二份真相源（本仓已多次因此失真）。

## 1 三层结构与职责边界（先分清，再动手）

| 层 | 载体 | 回答什么 | 谁维护 |
|---|---|---|---|
| **清单层** | `docs/retro-and-gaps.md` **§6.0** | 有哪些任务 / 优先级 / 状态 / 前置是否满足 | 每轮开工与收口 |
| **索引层** | 账本 **§6.0-H 交接索引** | 哪个任务去 `handoff.md` 的哪一节看 | **当轮**写，不许攒 |
| **明细层** | `docs/handoff.md` `## <TASK-ID>` | 这个任务做了什么 / 凭什么算完 / 还剩什么 | **当轮**写，不许攒 |

**禁止**：① 在 `handoff.md` 里另立任务清单（新任务一律归集账本 §6.0）；
② 把过程细节 / 长证据写进 `handoff.md`（放 `.workbuddy/artifacts/`、逐日日志或测试文件本身）；
③ 只在 `handoff.md` 写条目而忘了 §6.0-H 登记（**单向 = 指针失效**）。
④ **轮次编号口径**：`§6.NN` 形式的轮次小节位于 `.workbuddy/memory/<日期>.md`（逐日日志），
**不是账本节号**——引用前先确认它属于哪份文件（本仓踩过：`AGENTS.md` 引用 "§6.47/§6.48"，
账本标题其实只到 §6.7）。
⑤ **逐日日志单轮 ≤80 行必须机械计数**：开始收口前记录该文件 `wc -l`，写完再取一次，差值
必须 ≤80，并在回报中列 `before / after / added`。长证据写 `.workbuddy/artifacts/`，日志只留结论与
指针；既有超限轮次遵守 append-only，不回写压缩（完整命令见 `ashare-ledger-continue` 收尾清单第 4 条）。

## 2 一次收口 = 七处写入（缺一即未收口；1~3 由 `doc-health` P 项机检）

1. **账本 §6.0 行**：改状态（闭环移 **F 档**；**编号保留、永不复用**），行尾追加
   `↪ **明细**：`docs/handoff.md` §<TASK-ID>`。
2. **账本 §6.0-H 索引表**：新增/更新该任务行 —— `| 任务 ID | 状态 | 日期 | 明细条目 |`。
3. **`docs/handoff.md`**：写 `## <TASK-ID> <一句话结论>` 条目（模板见 §3），
   **首行必须含回链**「`docs/retro-and-gaps.md` §6.0 `<TASK-ID>`」（守卫扫的就是 `§6.0` 字面）。
4. **`docs/handoff.md` §2 条目一览** + **§1 现场**（分支/基线/服务/归属不明的未跟踪文件）。
5. **销账时「三处一致」**（闭环专属，2026-09-16 新增为硬要求）：
   **未完成档（A~E）里删掉该行** ⟺ **F 档新增该行** ⟺ **§6.0-H 标 ✅**。
   **只做后两处 = 没销账**——下一个执行者按「状态档 → 优先级 → 编号」排序，
   必然先领到那行**早已做完**的任务，白跑一轮。实测：`BUG-014` 就曾这样滞留 A 档一轮
   （代码与守卫都在 `80c6428` 交付、§6.0-H 也标了 ✅，A 档那行没人删）。
   该形态已由 `doc-health` **Q 档位一致性**机检（见 §4）。
6. **交付远端**（2026-09-16 用户追加，硬要求）：`git log --oneline origin/master..HEAD | wc -l` **必须为 0**。
   非 0 ⇒ 推功能分支 → 开 PR → **满足 6 条件即自动合并**（`gh pr merge <N> --merge`），
   合并后立即删本地与远程功能分支。**常规 PR 合并不是停止条件，只有改写 `master` 历史才是。**
   ⚠️ **本地 commit ≠ 已交付**：`handoff.md` 写得再全，只要提交没合并，接手者读到的条目
   在远端 `master` 上**根本不存在**，`§6.0` 的状态与代码必然对不上——**交接不是"写了"而是"对方能拿到"**。
7. **交接现场必须干净**（2026-09-16 用户明确：「交接的时候工作区必须是要干净的」）：
   判据 = `git status --porcelain` **无任何输出**（**含未跟踪文件**）。
   出现 `??` 时**先分类再决定动作**，判据是「**同系列历史文件的跟踪状态**」，**不是印象**：

   | 类别 | 判据（先查，别凭印象） | 动作 |
   |---|---|---|
   | **已入库系列的新成员** | `git log --diff-filter=A -- <同目录同命名模式的历史文件>` **有记录** ⇒ 该系列本就入库 | **按同惯例入库**（`chore(data)` / `chore(evolution)`） |
   | **真·运行态**（可再生产 / 每次运行都变 / 含本机路径） | 同目录历史文件**无**入库记录，且 `.gitignore` 已有同类规则 | 补 `.gitignore` 规则（按**实际落盘路径**写），**不删文件** |
   | **凭据 / 秘密** | 命中 `api_key` / `token` / `password` 等 | **绝不入库**，按红线 4 处理 |

   ⚠️ **本条纠正了一个已发生的误判（勿重蹈）**：「**看起来像**运行产物」**不构成**「不该入库」的证据。
   上一轮把 `backend/data/{lhb,minute_decisions,position_plans}/` 与 `docs/{evolution,daily-review}/`
   **共 6 个文件**登记为「不得提交的运行时产物」⇒ 工作区**连续多轮不干净**。
   实测为误判：`git log --diff-filter=A` 显示**同目录同命名模式的历史文件全部已跟踪**，
   且以专门的 `chore(data): 运行数据留痕` / `chore(evolution): …入库` 提交进入主分支。
   ⇒ **一条 `git log --diff-filter=A -- <目录>` 即可查清**；凭印象判"不提交" = 把工作区留脏给下一轮。
   入库前先扫敏感信息（红线 4）与格式有效性（如 JSON 合法性）——**别把坏文件或密钥提交进去**。

⚠️ **新文件（`handoff.md` 首次建立时）必须先 `git add`**：`doc-health` 的 J 项判定面取自
`git ls-files`，未入索引 ⇒ 文档点名的仓库路径被误报「全仓不存在」（**假红**，实测踩过）。
**该纪律适用于所有新增文件**（含新增测试文件本身被文档点名时）。

## 3 条目模板（七字段固定，便于机械核对与快速接手）

```markdown
## <TASK-ID> <一句话结论>
- **账本**：`docs/retro-and-gaps.md` §6.0 `<TASK-ID>` ｜ **日期**：YYYY-MM-DD ｜ **状态**：✅ 闭环 / 🟡 部分闭环 / ⛔ 阻塞
- **缺口与验收标准**：开工前认定「哪里不对、做到什么算完」。
- **改动**：文件清单 + 一句话作用（含"刻意没动什么"）。
- **机械证据**：可复算或可复跑的数字/命令，不写形容词。
- **注入自证**：把缺陷形态注回去，守卫是否真的变红（没有守卫的项写明「无」）。
- **门禁**：后端 / 前端 / 静态检查 / doc-health 的实测数字。
- **遗留与下一步**：未做项与它的账本 ID；无则写「无」。
```

**写「机械证据」时的三条硬纪律**：
- **不写形容词**，写**可复跑的命令 + 可复算的数字**（"提高了准确率" ❌ / "重放 `mismatches=0`，覆盖率 1.0" ✅）。
- **样本不足 / 未真正触发的路径必须显式声明**。例：集成跑在盘前、当日无候选 ⇒ 归档 0 行 ⇒
  `state=ready` **只证明未抛异常、不证明 INSERT**，必须写明并用另一路全链探测补上。
  **把"没跑到"记成"验证过" = 伪造证据**，比没写更糟。
- ⚠️ **必然随工作推进而变的量，写成命令、不写静态值**（2026-09-16 实测踩到，代价是一次连带的
  "自己打破自己的文档"）：行数 / 条目数 / 未合并提交数 / HEAD SHA 这类量，**每做一轮收口就会变**
  ⇒ 上一轮写下的值在下一轮**自动失效**，而读到它的人**会把它当判据**去核对，然后报出一堆假偏差。
  实测：交接提示词里写「`handoff.md` **11** 个条目，789 行」，而权威值（守卫输出）是 **10** 条、
  文档已涨到 **805** 行 —— **条目数从一开始就数错了，行数则被本轮改动打破**。
  写法：`wc -l <文件>`（让接手者自己跑）或「条数以 `doc-health` P 项输出为准」。
  **只在"这一轮刚刚实测过、且下一轮一定不会变"时才写死数字**——否则写死即埋雷。

## 4 机械守卫：`doc-health` **P 交接索引**项

```bash
python3 scripts/doc-health.py          # 关注 `P 交接索引` 行
```

判据（`scripts/doc-health.py`）：`ledger_handoff_index_ids()` ⇄ `handoff_entry_ids()` 双向闭包，
比对三路差异 —— `ho_missing`（索引有、条目无）/ `ho_unindexed`（条目有、索引无）/
`ho_noback`（条目正文缺 `§6.0` 回链）。

**三个设计要点，改动该守卫时不许退回**：
- **只取 §6.0-H 表行的第一列**：该表第四列字面含 `§RSH-026` 这类"明细条目"指针，
  若整行扫 ID，判据会**恒真**（自己证明自己）。
- **`§6.0-H` 小节缺失 ⇒ `return None` 判红，不跳过**：fail-loud。
  守卫找不到判定面时静默通过，比没有守卫更糟（本仓 [[KB-ENG-72]] 同族）。
- **保险丝三道**：文件缺失 / 小节缺失 / 条目数为 0，**判红不跳过**。

| 项 | 位置 | 说明 |
|---|---|---|
| `HANDOFF_FILE` | `docs/handoff.md` | 明细层路径（常量） |
| `HANDOFF_INDEX_HEAD_RE` | `^#{3,5}\s*6\.0-H\b` | 定位账本索引小节 |
| `HANDOFF_ENTRY_HEAD_RE` | `^##\s+...((?:BUG|IMP|RSH|GOV|OPS)-\d{3})` | 解析条目 ID |
| `HANDOFF_BACKLINK_POINTER` | `§6.0` | 条目回链必须出现的字面 |

### 4.1 `Q 档位一致性`项（`GOV-015`，2026-09-16 新增）

**被守的是什么**：同一任务的「状态」在账本里有**三份副本**（未完成档行 / F 档行 / §6.0-H 状态列）。
三份各说各话时，**唯一后果是执行者领到已做完的任务**——不报错、不崩，只是白跑。

判据（**双向**，缺一向只守一半）：

| 方向 | 判据 | 不判会怎样 |
|---|---|---|
| 一 | 已闭环的 ID **不得**留在 A~E 未完成档 | `BUG-014` 型滞留（领到已完成任务） |
| 二 | §6.0-H 标 ✅ 的 ID **必须**在 F 档有行 | 「偷偷销账」：索引说完了、F 档没登记，无法追溯 |

**四道 fail-loud 保险丝（走单独返回值，不塞进冲突列表）**：① 账本文件缺失；
② A 档标题形态失效（认不出未完成档）；③ `§6.0-H` 小节缺失；④ **闭环记录合计为 0**。

> ⚠️ **第 ④ 道最要紧**：闭环集合为空时，「未完成档未命中」**恒真** ⇒ 方向一永远报绿 ⇒
> 守卫静默变摆设。**凡判据形如「不在集合中 ⇒ 通过」，都必须先证集合非空。**
> 保险丝用**独立返回值**，别复用冲突列表——否则「保险丝触发」与「发现冲突」在调用方无法区分。

**实现要点（改动时不许退回）**：
- 扫 F 档**必须显式收边界**：`§6.0-H` 索引表**紧跟 F 档**、形态**完全相同**（都是 `| ID | … |`）⇒
  不收边界则索引行被当作「F 档行的延续」，索引里**每个 ID 都成了闭环记录**。
  实测首版即因此把 `RSH-026` 误判为「已闭环却留在 A 档」（**假红**）。
  写法：在行循环开头 `if HANDOFF_INDEX_HEAD_RE.match(ln): break`。
- 「取状态列原文」与「取有没有登记」**分开实现**：前者（Q）若与后者（P）合用同一函数，
  P 项判据会跟着状态列措辞变化 ⇒ 无谓耦合。
- **新增任何检查函数，必须同时登记 `backend/tests/test_doc_health_anchors.py` 的 `_NEUTRAL` 表**，
  否则 AST 反查守卫（`_checks_called_by_main`）**点名报红**（该守卫到 2026-09-16 已真命中三次）。
  注意返回形状：`(冲突列表, 保险丝说明)` ⇒ 中性值写 `((), None)`，
  **保险丝写成 `""` 会让 `bool("") is False`，使「保险丝未触发」与「中性打桩」不可区分**。

⚠️ **改动 `main()` 时注意**：`check_handoff_index()` 的**调用行**与**使用行**是分开的两处。
只加使用行 = 运行到该处 `NameError`（实测踩过，且 `grep` 一次就能查出：
调用点应紧邻 `cat_unreg, cat_ghost = check_catalog_closure()`）。

## 5 守卫的自证（新守卫必须能真的变红）

**没有注入自证的守卫 = 未经验证的守卫。** `doc-health` 单次约 26s ⇒ 三路串跑 ~130s，
**必须用 `run_in_background`**，否则会撞前台超时被杀（exit 137 / 零输出，实测踩过）。

三路注入（脚本见 `/tmp/inject_handoff_p.py` 的形态，**勿写进仓库**）：

| 注入 | 期望 |
|---|---|
| [A] 把 `handoff.md` 的 `## BUG-014` 改成 `## BUG-014-X` | `ho_missing` 点名 `BUG-014` |
| [B] 打掉 `BUG-014` 条目里的 `§6.0` 字面 | `ho_noback` 报「缺回链」 |
| [C] 在账本 §6.0-H 加一行幽灵 `OPS-999` | `ho_unindexed` 点名 `OPS-999` |

脚本必须**自带还原断言**（`assert read() == orig`，逐字），且**任一路没红就 assert 失败**——
防「注入没生效却被当成守卫有效」。基线也要先跑一次，**基线不绿则自证无意义**。

### 5.1 `Q 档位一致性`的四路注入（`GOV-015` 实测 4/4）

**Q 项的自证必须在「修好之后的真实账本」上做**——先在账本上注入、跑 `doc-health`、再还原，
**不要**只靠合成 fixture 的单测（合成 fixture 证机制，真实账本证「它在本仓真的会红」）。
还原校验用 `hashlib.sha256` 逐字比对（`assert sha256(after) == sha256(before)`）。

| 注入 | 期望 | 触发的是 |
|---|---|---|
| [A] 把某个 **F 档已闭环**的 ID 行**塞回 A 档** | 方向一判红并点名该 ID | 销账漏删未完成档 |
| [B] 把某闭环 ID 的 **F 档行删掉**（保留 §6.0-H 的 ✅） | 方向二判红并点名该 ID | 偷偷销账 |
| [C] 改 **A 档标题形态**（如把 `**A 可做**` 改成 `**A. 可做**`） | 保险丝判红 | 认不出未完成档 |
| [D] 改 **`§6.0-H` 小节名** | 保险丝判红 | 索引面缺失 |

⚠️ **注入形态要区分「改措辞」与「改形态」**：`**A 可做（措辞变了）**` **仍匹配** `^\*\*A\s`
⇒ 它**不会**触发保险丝。只有把**分隔符本身**改掉（`A.` / `A、`）才算断掉判定面。
写自证用例时踩过：「想验证标题改名」结果用例自己假红——**先确认注入真的生效了**。

## 6 新建任务时的顺序（编号不清是常见返工来源）

1. 先在账本 §6.0 找该域**最大号 + 1**，按状态档（A 可做 → B 待批 → C 等窗 → D 观察 → E 搁置 → F 闭环）
   与优先级定位行，**号码一经分配不复用**。
2. **既有行在前、新增行在后**；同一档内按优先级排。
3. 本轮只写「**已完成 / 已登记的**」的条目不攒账；未完成项**当轮**进 §6.0（不是只在叙述里提一句）。

## 7 常见坑（都实测踩过，写在这里是为了不再踩）

- **⚠️ 「为了讲清楚而另起一份」是产物的第一大来源 —— 内容重叠 ≥ 80% 就应合并、不是新建。**
  2026-09-16 实测：用户先要「全日工作总结」，后又要求「让接手方会用两个技能 + 审阅 + 接续」，
  我**另建了一份 285 行的新提示词**，与既有那份**高度重叠** ⇒ 用户直接指出
  「**生成了太多无用的文档了…直接在那个里面改就好了**」。
  ⇒ **判据**：新内容若与既有产物 **≥80% 重叠**（同对象、同读者、同结构），
    **一律并入既有那份**（新增小节 / 新增一组判据），**不要新建文件**；
    只有**读者或用途不同**时才另立。
  ⇒ **副产品纪律**：**别把「行数 / 条目数 / 提交数 / SHA」写死在给他人用的文档里**（见 §3 第三条）
    —— 一旦写死，下一轮改动就把自己的文档打破，逼你再写一份去修它，**产物由此滚起来**。
  ⇒ 建新文件前先自问：**「这份能不能长在既有那份上？」** 不能，才建。

- **⚠️ 最贵的一条：在 `docs/**.md` 里写「未纳入版本控制的运行产物」的文件名 ⇒ CI docs job 必红，而本地恒绿。**
  2026-09-16 PR #13 实测：`docs/handoff.md` §1 现场写死了 4 个 `??` 文件（含 2 个 docs 路径）
  ⇒ **CI `B 死链 2 处`、本地 `全部通过`**。根因 = B 项判定面取自 `git ls-files`（[[KB-ENG-95]]）。
  **修法是改文案，不是登记豁免**（豁免只会让下次换个文件重演）：
  - 只写**目录** + 「具体文件名跑 `git status --short` 取」，**不写文件名**；
  - 边界要记住：B 项**只认 `docs/` 面的引用** ⇒ 写未跟踪的 docs 路径**必红**，
    写未跟踪的非 docs 路径**不红**（所以只看本地"没红"会得出错误结论）。
  - **推论（强制）**：**新增或改动任何文档后，一律用干净检出复验** ——
    `git worktree add --detach /tmp/ci-sim HEAD`（存在则先 `git worktree prune`），
    在 `/tmp/ci-sim` 里跑 `python3 scripts/doc-health.py`。**「本地全绿」不构成 CI 绿。**
- **`Edit` 用行首片段匹配会劈开长表格行**：曾用 `| **IMP-027** | \`app/main.py\` **启动装配重构**`
  这种**行前缀**做 `old_string`，结果该行被劈成两半、残尾粘到下一行行尾。
  ⇒ 长中文表格行**要么给足上下文**，要么**用 Write 工具写独立脚本**处理。
- **别用 `difflib` 校验长表**：`unified_diff` 默认 `autojunk=True`，对重复表头/空行的高频行
  按 junk 丢弃 ⇒ **字节相同的行被误报为「删除」**。改用「**构造式比对**」：
  拿 HEAD 原文施加脚本**显式声明的 N 处编辑**，结果必须与待写内容**逐字相等**。
  这个判据更强——同时证明「除声明差异外全文零改动」。
- **「先删后插」必须重新扫描定位**：删掉一行后，锚点下标**不一定会左移**
  （若锚点在被删行之前则不动）⇒ 算术偏移必然算错。一律**按内容重新定位**。
- **写长中文表格行不用内联 heredoc**：正文含 ASCII 双引号会与 Python 字符串定界符冲突
  （`SyntaxError: invalid syntax. Perhaps you forgot a comma?`）。
  ⇒ 用 Write 工具写成 `/tmp/xxx.py` 再执行。
- **`git add -A` 会把运行产物带进暂存区**（`backend/data/minute_decisions/scan-*.json` 等无
  `.gitignore` 规则）⇒ 收尾先看 `git status --short`，非本轮产物用 `git restore --staged <path>`
  **只移出、不删除**。
  ⚠️ **但「移出暂存区」不等于「永远不提交」**：这些路径**多数是同系列历史文件的已入库成员**
  ⇒ 处置见 §2 第 7 条的三分类表。**把"看起来像产物"一律判为不提交，会让工作区长期不干净**
  （上一轮就是这样连续多轮留下 6 个 `??`）。判据只有一条：`git log --diff-filter=A -- <目录>`。
- **⚠️ 给接手方写「提示词/核对清单」时的两条纪律（2026-09-16 实测踩到）**：
  ① **凡是写进提示词的「期望输出」，发布前必须自己跑一遍**。
     实测代价：初稿给了一条核验命令 `grep -c '^## \(BUG\|IMP\|RSH\|GOV\|OPS\)-' docs/handoff.md`
     —— 该命令依赖非 POSIX 的 BRE `\|` 扩展，**不可移植**；但 2026-09-16 复核时，本机
     GNU-compatible BSD grep 实测为 **`10` / exit 0**，推翻了原记载的 `0 / exit 1`。
     正确形式仍统一写 `grep -cE '^## (BUG|IMP|RSH|GOV|OPS)-'`（同样实测 **`10`**），
     目的是消除实现差异，而不是声称当前命令必然返空。
     ⚠️ 从 BRE 改成 ERE 时不能只加 `-E`：还必须把 `\|` 改为裸 `|`；本机实测
     `grep -cE '^## (BUG\|IMP\|RSH\|GOV\|OPS)-' ...` 恰为 **`0` / exit 1**。
     ⇒ **命令一律用 `-E`（扩展正则）或 `E`/Grep 工具；写「期望值」前先跑**。
     **本条纪律第一次被写下，正是因为上一次没跑就写。**
  ② **必然随工作推进而变的量（行数 / 条目数 / 提交数 / SHA）不要写死**（见 §3 第三条）——
     写死的值会在下一轮自动失效，而读到它的人**会当判据去核对**，然后报假偏差。
     反面实例：提示词里写「`handoff.md` **11** 个条目，789 行」，权威值实为 **10** 条、文档已 **805** 行。

- **⚠️⚠️ `\|` 是不可移植的 BRE 扩展，不得拿实现假设解释返空**
  历史上同一 session 有 4 次 shell 检索返空，但 2026-09-16 独立复核证明当前本机 grep
  **接受** `\|` 并正常命中；旧的“BSD grep 不认它”归因已撤销。保留真正有效的纪律：
  ⇒ **强制触发规则（不依赖记性）**：
  **凡「我预期有多处命中，命令却返空 / 返 0」，一律先假定是命令写错**，
  **换 `Grep` 工具复验后才允许下结论**。**不得直接把返空当作「内容不存在」上报或写进文档。**
  ⇒ 更好的做法：**根本不用 shell grep 做多备选检索**——直接调 `Grep` 工具（它支持正规正则）。
  ⇒ 可移植对照：`echo "alpha" | grep -E "x|alpha"` ⇒ `alpha`；不要把未带 `-E` 的实现相关结果写成跨环境期望值。
  **代价实例**：我据此一度判定「三个 skill 改动全部丢失」（实际全部落盘），
  并在提示词初稿里写出一条会让接手者**报出假偏差**的核验命令（见上条 ①）。

## 8 接手时的入口顺序（新会话 / 换人接手，照这个顺序走）

1. `date` 实测当前时间（**不要信会话上下文的 `current_time`**，实测滞后过 12 小时）。
2. `git status --short` + `git branch --show-current` + `git log --oneline -5` —— 确认现场。
3. 读 **`docs/handoff.md` §1 现场**（分支/基线/服务/**归属不明的未跟踪文件——保留、勿删**）。
4. 读 **账本 §6.0-H** → 按需跳进 `handoff.md` 对应条目，**只读需要的那几条**。
5. 读账本 §6.0 的「**下一件**」指针与「**本轮停止点**」（两处**常常不同步**，缺一不可）。
6. 跑 `python3 scripts/doc-health.py`，P 项应为 `[OK ]`；不绿先修文档再动手。
