### 1.2 行情"连接中"卡死 —— 根因与修复

**实测证据**（不是推理）：

```
[8000 直连] OK: {"type":"snapshot","seq":13,...,"data":[]}
[3000 代理] FAIL: InvalidMessage: did not receive a valid HTTP response
```

- 后端 WS **本身正常**；问题在 `wsBase()` 的取值路径
- `.env.local` / `.env.development` 均已配 `NEXT_PUBLIC_WS_BASE=ws://127.0.0.1:8000`，但 `NEXT_PUBLIC_*` 在 **dev server 启动时**读取；3000 启动时早于配置生效 → WS 走向连不通的 `/backend` 代理
- **致命放大器**：`WebSocket` API **没有连接超时**。对端接受 TCP 却不完成 upgrade 时，`onopen/onclose/onerror` 三个回调**都不触发** → `retry` 永不递增 → `startPolling()` 降级兜底**永不启动** → 状态永久停在 `connecting`

**修复**（`hooks/use-quote-stream.ts`）：新增 6s 握手超时兜底，未 open 即主动 `close()`，让既有重试/降级链路生效；`onopen`/`onclose`/cleanup 三处配套清理定时器。

> 顺带说明：这类"没有超时"的缺陷属于**降级链路不可达**——兜底代码写了，但触发条件永远不成立。凡"连接类"实现都要有独立超时，不能只依赖回调。

**验证**：页面实际渲染 `行情状态：休市 · 展示最近交易日数据`，指数数据到位（上证 3,979.89）。
注意状态是"休市"而非"WS 断线 · REST 轮询" → 说明 **WS 直连成功且收到推送**，未降级。凌晨休市时"休市"即正确状态。

### 1.3 `--reload` 反复挂死 —— 根因定位（重要环境结论）

改完 `picks.py` 触发 reload 后，8000 再次挂死（HTTP=000，日志停在 `Reloading...`）。

**根因**：SQLite 锁竞争。旧 worker（97827）仍持有 `data/ashare.db`，新 worker 在 **import 阶段执行 alembic 迁移**需要 DB 写锁 → 永久等待。
（与 09-01 那次的 29 个孤儿进程是不同诱因，但同源：多进程 + SQLite + 启动期 DB 访问。）

**处置**：已改为**不带 `--reload`** 启动。代价：改后端代码需手动重启。收益：不再挂死。
建议后续保持此方式，或改走 Postgres 再开 reload。

### #1 休市/停牌标识缺失 ✅ 已落地（2026-09-02）

**定位**：前端**完全没有**个股级停牌状态。仅有：
- `components/detail/quote-strip.tsx:29`——把 PE 缺失的原因**猜测**为"长期停牌"（已修）
- `app/market/page.tsx:190`——市场宽度里的 `breadth.suspended` 计数（全市场，非个股）

**根因**：后端 Quote 模型无停牌字段，无从渲染。

#### 判据：有历史 K 线，但最近交易日缺 bar = 停牌

原方案里写的"不要靠成交量=0 硬猜"经实测**成立且必须**——全市场快照 5565 只里
`volume == 0` 有 19 只，但分两类，靠量能根本分不开：

| 现象 | 只数 | 真相 |
|---|---|---|
| 有昨收无最新价（002274 prev=6.47 等） | 7 | 真的停牌 |
| 全字段 None（301688 / 601091 / 920071…） | 12 | 日K 接口 **502**，数据源里没这只票 |
| 一字涨停 | 若干 | 无量但仍在交易 |

**顺带推翻原方案的一个假设**：原以为"K 线为空 = 未上市新股"，实测不是——
301688 / 601091 的零 bar 是**接口 502**。所以枚举里**没有** `pre_listing`，
空 K 线一律判 `unknown` 并在 reason 里并列陈述两种可能。
把数据源故障标成"未上市"是典型的静默误判。

#### 实现

- 后端 `app/market/trading_status.py`（新）：纯函数 `resolve_trading_status(bar_dates, trade_days, now)`，
  返回 `{status, suspended_days, suspended_since, last_bar_date, anchor_date, reason}`，**永不抛异常**
- 枚举只有三态 `trading / suspended / unknown`──`unknown` 是"判不出来"，
  绝不是"正常交易"，UI 必须显式呈现
- 挂在 `GET /kline/{symbol}`（`KlinePayload.trading_status`），**仅 `timeframe=1d` 有值**，
  零额外网络请求（bars 已在手上）
- 前端 `components/detail/suspended-badge.tsx`（新）：头部徽标 + 图表区判据条 + 分时遮罩

#### 盘中口径（最容易踩的坑）

当日未收盘时数据源通常**还没有当日 bar**。若直接拿"最后一根 bar 日期"对"最近交易日"比，
盘中会把**所有正常股票**误判成停牌 1 天。故当日未收盘时"缺今天"从停牌天数里剔除——
代价是同一只票盘中和盘后的天数会差 1（设计如此，非抖动）。

#### 实测结果（2026-09-02 02:10，9/2 未收盘口径）

| 股票 | 判定 | 依据 |
|---|---|---|
| 600519 / 000001 | trading | 最近完整交易日 9/1 有成交 |
| 002274 华昌化工 | **suspended 5 个交易日** | 自 8/26 起无成交 |
| 002731 / 002870 | suspended 1 | 自 9/1 起 |
| 301139 / 688432 | suspended 2 | 自 8/31 起 |

**顺带修掉**：`quote-strip.tsx` PE 缺失原因里的"长期停牌"是**猜**的，
现在停牌状态真实可得，该文案改回"数据源未提供（常见于新股、亏损股）"，停牌交给徽标表达。

**验证**：后端 12 条单测（`tests/test_trading_status.py`）+ 前端 8 条组件测试
（`suspended-badge.test.tsx`）；浏览器实测 002274 头部徽标"停牌 5 个交易日"（含判据 title）、

## 三、数据与功能对标（竞品调研结论）

### 3.1 题材梯队 vs 同花顺口径

**竞品口径**（有据可查）：
- **同花顺**（[官方投资者关系回复](https://m.10jqka.com.cn/20240712/c659766588.shtml)）：概念板块基于公开信息选取，来源含上市公司互动易、公告、官微；自研 Hithink 大模型初筛 + 严格审核
- **东方财富**（[财富号 2026-08-31](https://caifuhao.eastmoney.com/news/20260831155857914667060)）：三道门槛（主题号召力/标的数量/监管认可渠道）；成分股准入三条——业务实质匹配（在研/规划/仅持专利/参股不并表**不算**）、信息源**仅限公告 + 交易所互动平台官方回复**（公司官网、公众号、媒体报道**均不作依据**）、合规一票否决
- **差异**：同花顺接受官微且"大模型初筛+人工"；东财明确排除官微/官网/媒体，纯人工交叉验证 → 同一概念两家常有成分股差异

**可程序化数据源**：
- 东财：`push2.eastmoney.com/api/qt/clist/get`，`fs=m:90+t:3`（概念）；成分股 `fs=b:BKxxxx`
- 同花顺：`q.10jqka.com.cn/interface/stock/concept/board`（约 850 概念）+ `/interface/stock/concept/detail?boardid=`；AKShare 封装 `stock_board_concept_cons_ths`（含市盈率字段）
- **本项目现状**：记忆记载 ths fuyao 官方 API 最全（59 端点）且**独占连板天梯、题材成分股**，涨停原因覆盖率 ths 100% vs 东财 0%

**结论与建议**：
1. **不建议改用东财口径**。ths 是我们的优势源（涨停原因 100% 覆盖、题材成分股、连板天梯），换东财等于自废武功，且东财成分股人工维护、接口非官方
2. **建议做"双源交叉 + 差异可视化"**：ths 为主口径，东财作为对照；成分股差异处标注"口径分歧"，避免用户拿东财对不上时困惑
3. **梯队判定补三向量**：不要用单一涨幅排序，改为 **启动时序 + 连板高度 + 带动性（板块内跟涨家数）** 打分。竞品未公开算法，社区口径（龙头=最先涨停/连板最高/带动性强；中军=流通市值≥200亿且板块内前3、日成交额≥15亿）可作为参数起点，但**需自测校准**

### 3.2 龙虎榜：数据全空 + 席位交互

#### ✅ 数据全空已修复（2026-09-02，第四类"静默失败"）

**表象**：前端龙虎榜一片空白。**实测**：`/api/longhu?date=` 其实返回了 **68 条记录**，
`source=ths`、`quality=high`——不报错、不空数组，但**每个数值字段都是 null**。

**根因（`data_providers/ths.py:254`）：字段名全是凭猜测写的，一个都不存在**

| 代码原用（猜的） | ths 文档真实字段 | 结果 |
|---|---|---|
| `price_change_ratio_pct` | `change` | null |
| `buy_amount` / `sell_amount` | `buy_value` / `sell_value` | null |
| `net_buy` | `net_value` | null |
| `last_price` / `turnover` | （该接口**没有**这两个字段） | null |

请求参数同样错：传 `date_ms` + `size`，而文档只支持 `date`(YYYY-MM-DD) + `board_type`。

**附带修复——概念冒充上榜原因**：原代码 `reason = it.get("reason") or concepts`，
真实原因缺失时拿 `concept_list` 顶替 → 界面"上榜原因"显示成"玉米,粮食概念,乳业"。
现改为只用真实 `limit_reason`，概念另存 `concept_tags` 字段（新增）。

**修复后验证**：68/68 条 `net_buy`、`buy_amount`、`sell_amount`、`change_pct` 全部有值。

**修复过程中发现的两个单位/口径问题**：
1. `change` 是**小数比例**（0.0997 = 9.97%），项目统一用百分数 → 已 ×100。
   未换算时涨停股会显示成 0.1%
2. 曾怀疑 `max=290.98%` 是 bug，核实后**是合理数据**：920xxx 为北交所（±30% 上限），
   601123/301697 为**新股上市首日**（无涨跌幅限制）。教训：先理解业务规则再改数据

#### ✅ "重复条目"已定位并修复（2026-09-02）——不是脏数据，是丢了 `range_days` 维度

上一节推测"重复条目是 ths 按上榜类型各返回一条"，方向对、结论错：
**这不是重复，是交易所对不同触发条件的分别披露**，`range_days` 就是区分维度
（文档里写作"上榜天数"，实测语义是**统计区间**）：

| 榜单 | 触发条件（例） | 金额含义 |
|---|---|---|
| `range_days=1` 当日榜 | 日涨幅偏离值达 7% | 当日累计 |
| `range_days=3` 三日榜 | 连续三日涨幅偏离值累计达 20% | 三日累计 |

旁证：`count=76` 而 `stock_count=70`，差值 6 = 同时上两榜的 6 只股票，
**官方字段本身就区分"记录数"与"股票数"**。且三日榜买额普遍大于日榜、
`net_rate` 因分母更大而更小，全部自洽。

**真正的 P0 在下游，不是数据源**：`predict/collector.py` 用
`dragon_map = {r.symbol: r for r in dragon}` 建映射 → **静默覆盖**，
取到哪条取决于服务端返回顺序。实测 2026-08-31：

| 股票 | range_days | 净额 | 判定 |
|---|---|---|---|
| 002396 星网锐捷 | 3（三日榜） | **+0.73 亿** | 游资净买入 → `capital_score=1.0` |
| 002396 星网锐捷 | 1（当日榜） | **−0.98 亿** | 游资净卖出 → 不应给分 |

**同股两榜净额符号相反，结论随机反转，且不报错。** 这是本项目第 4 类静默失效。

**修复**
1. `LongHuRecord` 补 `range_days` / `net_rate` / `org_net_value` / `hot_money_net_value` / `hot_rank`
2. `ths.py` 按文档解析；`org_net_value`、`hot_money_net_value` **允许 None**

3. 新增 `predict/collector.py::pick_daily_board()` —— 显式取 `range_days==1` 的当日榜，
   只有当日榜缺席才回退，回退时调用方必须标注区间口径
4. `predict/engine.py` 资金验证文案订正：原写"龙虎榜**游资**净买入"但用的是
   `net_buy`（全席位合计）→ 改为"上榜席位净买入"+ 分列游资/机构 + 标注区间口径
5. 前端 `longhu-tab.tsx`：新增"区间/游资净额/机构净额"列、行 key 带 `range_days`

`org_net_value` 42/76、`hot_money_net_value` 67/76（缺失保持 None 未被填 0——

#### 席位交互的数据基础：ths 已经具备

调研时判定"点击席位看 K 线价位"是竞品空白点，而 **ths 该接口已提供所需字段**：
- `org_net_value`（机构净额）、`hot_money_net_value`（游资净额）→ 直接支撑"机构/游资区分"
- `hot_money_items[]`：`name`（游资名）+ `buying`（买入额）+ `rows[]`（关联个股明细）
  → **这就是席位画像与"席位→个股"关系的数据源**，无需换数据源

**注意**：龙虎榜**只公布金额不公布价格**，席位均价只能 `买入额 ÷ 估算股数` 得出，
必须标注"估算"，不可伪装成真实成交价。

**竞品做法**：
- 同花顺营业部页：上榜历史 + **营业部偏好类型**（行业分布）+ **协同营业部**（携手操作次数/成功率/金额）——三件套
- 同花顺个股龙虎榜：席位名后挂标签（一线游资、知名游资、敢死队、跟风高手）；"机构成功率回测"给 T+1 上涨概率、平均盈利、最优持有期
- 东财：席位代码区分身份——机构专用 **ZT 打头**、游资 **ZA 打头**
- 东财 PC 端有"席位异动 K 线（黄金K线）"：设置 → 图线叠加 → 勾选席位异动，把上榜事件标记到 K 线

**关于"点击席位看在哪根 K 线、什么价位买卖了多少"**：
> **未检索到官方功能文档**——判定为**竞品空白点**，可做差异化。
> 仅有的第三方说法互相矛盾，且都提到只能用成交明细**推算**成本价。

**落地方案**（建议分两步）：
- **第一步（必须有）**：数据修复 + 席位画像页（上榜历史 + 偏好行业 + 协同席位），回测指标固定为 T+1 胜率/平均收益 + 最优持有期
- **第二步（差异化）**：每次上榜做成 **K 线可点标记**，弹窗显示「营业部名 / 买入额 / **估算**均价 / 上榜原因 / 后续 N 日涨跌」
  - ⚠️ 龙虎榜**只公布金额不公布价格**，均价只能由 `买入额 ÷ 估算股数` 得出，**必须标注"估算"**，不能伪装成真实成交价
  - 提供开关（吸取通达信信息地雷的干扰教训）

**重要反直觉结论**（必须纳入）：
- 机构龙虎榜呈 **"V 字型"**——极端净买入与极端净卖出两端都有预测力，中间平庸段无信号
- 纯量化席位（如开源西安太华路，一日游铁律）主导净买入的个股**次日下跌概率超 70%**
- → **席位属性必须作为负向因子**，否则资金面因子会系统性反向（[来源](https://www.xuntou.net/forum.php?goto=lastpost&mod=redirect&tid=6607)）

### 3.3 事件驱动：独立 Tab + 筛选

### 4.3 合成方法（华泰 6 法实测结论）

- 效果排序：**最大化 IC_IR ≈ 最大化 IC > PCA > 等权**（参数窗口 T=12 月）
- **共线性**：不要直接多元回归。两步走——① 同类因子先合成大类风格因子；② 大类间做**施密特正交化**。海通实证：市值+反转+换手等权 IC 0.09/ICIR 2.29 → 正交后 IC 0.10/**ICIR 3.30**
- **有效性检验四件套**：回归法（WLS 市值平方根加权 + t 值序列）、IC 分析（RankIC + IR + 胜率）、**分层回测看单调性**（IC 好但分层不单调很常见，以分层单调性为准）、换手率（短线体系必须单独考核，扣费后可能归零）
