## 日常使用

权责按 [协作审核规范](collaboration-workflow.md)：网页ChatGPT负责规划和任务增删重排，Codex回填执行事实并提交审核。状态“待交付”可表达待网页审核/待CI，具体阻塞写任务页；不得未审核自标最终完成或直接跨轮。

1. 按本索引进入当前阶段，在该页领取有证据、前置满足的最高优先级切片；跨阶段依赖按任务 ID 查找，并区分开工/发布/效果前置；引用长期核查任务不等于等待其整体完成。最多一个行为变更切片和一个不冲突的治理切片。
2. 任务只有一份：阶段页的 `## BUG/IMP/RSH/GOV/OPS-NNN` 条目。新增先去重、取域内未用序号；迁移/合并保留原 ID 的去向。不要把工作包数量或任务数量当作工时/完成率。每个领取切片补文件/消费者、反例、低成本替代、实施步骤及恢复；业务任务由 Codex 实现，方案文字不是完成证据。
3. 状态使用 `待执行 / 进行中 / 部分完成 / 待条件 / 待交付 / 已完成 / 已退出 / 已合并`。退出/合并须增加“处置依据”；合并还须填“合并至”另一个有效任务 ID。退出不算完成，活动任务不得继续依赖退出/合并项。待条件须在“下一步”明确条件；未验收不是完成。P0 正确性/安全优先，P1 核心能力，P2 仅证据支持的简化。
4. 更新时只改任务本页。完成后保留一句结论、验收证据、PR/commit 与必要限制；长日志进忽略的 artifacts，稳定知识回原专题/KB。不再为每轮复制全仓门禁、F 档、H 索引和 handoff 条目。
5. 完成项不再影响施工顺序。被依赖/引用的 ID 保留简短条目，迁出时须同步可解析去向，不能留下幽灵依赖。仍支撑依赖/恢复的成果留阶段“已交付基线”；后续新任务完成/退出/合并后在所属阶段尾部保留简短 ID 条目与证据，不参与活队列；[旧编号处置记录](archive/ledger-transition-20260917.md) 冻结本次 123 个源 ID，不追加新任务或成为第二份状态表。不再维护已关闭任务的长篇日记。
6. 每批跑 doc-health：阶段全部可达、任务唯一、依赖有效无环、状态合法、完成有证据、旧编号可解析。门禁验证这些不变量，不强制旧多表格式。
