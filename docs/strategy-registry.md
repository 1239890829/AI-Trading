# 策略级登记册（Strategy Registry）

> **速览**：本项目「策略/战法」级资产的唯一登记处。回答四个问题：**有哪些策略在跑、各自凭什么依据、谁在失效、失效后怎么处置**。
> **本文与因子登记册的分工**：`factor-candidates.md` 管**因子**（单一可计算谓词，用于评分）；本文管**策略**（完整的「何时买什么、何时卖」规则集，可含多个因子）。
> **制度依据**：[[KB-DEC-019]]（准入—监控—退役闸门 + 反固化条款）、[[KB-STOCK-28]]（策略生命周期）。
> **代码承载**：`backend/app/picks/strategy_registry.py`（可评估策略键的机器真相源，与本文由测试守卫一致性）。
> **状态语义**：🟢 现役（有组件承载 + 已接入）｜🟡 观察项（有证据但不接入）｜⛔ 已否决（有证据链封存）｜⚪ 候选假设（未验证）。
> 建立：2026-09-10（P1-37）。最后更新：2026-09-10。

## 0. 为什么「因子登记 ≠ 策略登记」

一个**策略** = 入场规则 + 标的范围 + 出场规则 + 仓位规则；一个**因子** = 一个横截面排序谓词。

两者的差异是结构性的，不能互相替代：

| 维度 | 因子（factor） | 策略（strategy） |
|---|---|---|
| 粒度 | 单谓词（如 `mom20`） | 规则集（入场+出场+仓位） |
| 评价 | RankIC / ICIR（截面） | 事件驱动收益（有持有期、有成本） |
| 数量关系 | 一个策略可含多个因子 | 一个因子可服务多个策略 |
| 失败模式 | IC 衰减 | 规则被套利 / 环境 regime 变了 |
| 登记处 | `factor-candidates.md` + `factors/library.py` | **本文** + `picks/strategy_registry.py` |

**推论**：因子全 PASS 不代表组合成策略就有效（[[KB-STOCK-29]] 的五步法就是反例——每步看着都"合理"，组合后显著负超额）。所以必须有独立于因子层的策略登记。

## 2. 逐条明细

### `daily_picks` 每日精选六维组合（🟢 现役）

- **定义**：收盘定次日，六维（情绪/消息/技术/基本面/资金/梯队）规则版多角色评分 → ≤5 只瀑布流卡片；两道稳定性约束（换股门槛 15 分 + **每日换股上限 2 只**）；盘中硬性失效。
- **数据源**：`daily_pick_review`（逐股 verdict + `excess_pct`，基准缺失为 `None` 并被统计跳过）。
- **监控**：`picks/signal_health.py` —20 组合日滚动窗口 + CUSUM 单侧下漂（`mu0` 全历史基线 / `delta` 容忍漂移 / `threshold` 阈值）→ `drift`/`warning`/`ok`/`insufficient` 四态；`drift`/`warning` 触发告警 + 自动改进项。
- **失效判据**：CUSUM `s_max > threshold`（drift），或滚动胜率 < 0.40 / 日均超额 < −1.0%（warning）。
- **处置**：保留。参数调优走 `experiments.py`（30 日实验劣化自动回滚）。
- **样本边界**：起点 2026-08-31，目前 8 个交易日 / 43 条 —— **远低于 `min_groups=10` 的判定线，当前状态必然是 `insufficient`**（这是诚实结论，不是故障）。

### `intraday_watch` 盘中跟踪台账（🟢 现役）

- **定义**：盘中筛选出的个股**首见即登记**（当日唯一），记 `entry_price` → 收盘比对 `close_price` 得 `pnl_pct` → `settle_day` 逐股 verdict（`success`/`fail`/`flat`）+ 当日/累计胜率。
- **数据源**：`watch_ledger`（258 行 / 3 个交易日 / 2026-09-08~09-10；实测分布 success 94 / flat 49 / fail 47 / 未清算 68）。
  - 🔴 **数据质量警告（2026-09-10 实测发现）**：2026-09-09 的 `layer='quiet_starting'` 共 44 行、其中 **29 行 `entry_price` 是错误值**——写入时把 `alert.meta.trigger_value`（净额亿元 / 涨跌幅）当成了股价（奥士康记 0.32，实际收盘 71.2 → `pnl_pct` **22150%** 且被误判 `success`）。**该日统计不可用**：单日 `mean_excess` 虚高至 **+827.3%**，把窗口均值拉到 **+278.73%**（对照 09-10 干净日 **−1.20%**）。`pre_limit` / `today_strongest` 两条路径不受影响（entry/close 比值实测 0.99）。代码已修（`watcher._alert_price`）+ 回归测试已加；**存量 29 行待处置，见 `retro-and-gaps.md §6.1 P0-6`**。⇒ 在此之前，本策略的 `mean_excess` **不得作为任何结论依据**。
- **监控**：**此前无（本轮 P1-38 接入）**。这是本次泛化的实际增量——一份已有 258 行真实逐笔判定的数据，此前完全在健康监控视野之外。
- **失效判据**：同 `daily_picks`（复用同一评估器）。
- **处置**：保留。
- **样本边界**：3 个交易日，**远不足以支撑统计**（`insufficient`）。

### `pullback_reversal` 超跌反攻（🟡 观察项）

- **定义**：`涨幅 3~7% + 收盘跌破 MA5 3~8% + 大盘涨 >0.5%`。方向 = 短期反转。
- **验证证据**（[[KB-STOCK-30]]，先冻结后盲测）：测试段 2022-01~2026-09 **+1.33%**（扣 35bps 仍 +0.98%、t=+11.3、胜率 68.2%）；同市值段中性化后 +1.19% ⇒ **不是小市值 beta**。
- **🔴 为什么仍是观察项**：**中位 −0.08%、跑赢比例 49.3%** ⇒ 收益靠少数极端样本（右偏），**典型一笔并不赚钱**。方向一致性 32/35（91%）说明整族方向成立，但不足以接入。
- **失效判据**（接入前预登记）：中位仍 ≤0、或跑赢比例长期 <50%、或样本外再测扣成本后超额 ≤0 —— 任一成立即退回 ⚪ 候选假设。
- **样本边界**：训练/测试已分段；但网格筛选本身在同一训练段内做过 48 组比较，**仍有多重比较残余风险**。
- **处置**：**观察**，不接入。翻案路径 = 换独立时间窗再盲测一次。

### `triple_volume` 三倍量战法（⛔ 已否决）

- **定义**：T0 成交量 ≥ 前 5 日均量 × 3（不含当日）；左侧回踩 T0 最低价 +1% 低吸（止损 T0 最低价）/ 右侧收盘破 T0 最高价介入（止损突破日最低价）；离场一律**收盘价判定**。
- **验证证据**（[[KB-STOCK-27]]，近 250 交易日 / 1.79 万条信号）：

  | 口径 | n | 均值 | 中位 | 胜率 |
  |---|---|---|---|---|
  | T0 当天收盘无脑买、持有 5 日 | 17,308 | −0.70% | −1.52% | 40.3% |
  | 左侧低吸 | 9,789 | −0.32% | −1.63% | 33.5% |
  | 右侧突破 | 8,903 | −0.44% | −2.29% | 35.9% |
  | 全市场同周期基准 | 1,335,182 | +0.06% | −0.35% | 46.8% |

- **位置分层检验**：低位组（信号前 20 日涨幅 <10%）−0.23% / 33.4%，高位组 −0.49% / 33.3% ⇒ **社区"高位派发/低位吸筹"假设在本样本未获支持**。
- **处置**：**不接入**。代码保留为纯函数（`picks/triple_volume.py`，12 项测试）+ 3 个可重跑核验脚本。
- **样本边界（翻案前提，三者齐备才重测）**：①样本仅 ~1 年、可能处于特定市场状态；②**未做市场环境分层**（原策略提到"大盘环境"，本轮未分层）；③未剔除权日、未含费用滑点（含了更差）；④参数未网格扫描（M=2/3/4、N=5/10/20、持有期）。
- **真正可复用的价值**：验证形态策略的五步法（规则化 → 事件驱动模拟 → 全市场同周期基准对照 → 单变量分层 → 明列未覆盖变量）。

### `two_thirty_five` 两点半五步法（社区原版，⛔ 已否决）

- **定义**：①涨幅 3~5% ②量比 ≥1（原文偏好 1.5~3）③换手 5~15% ④量阶梯放大 ⑤均线多头且不偏离 MA5 —— 五步全通过。
- **验证证据**（[[KB-STOCK-29]]，2407 交易日 / 5555 只 / 968 万条）：五步全通过 T+5 **−0.51%**、超额 **−0.65%**、胜率 39.3%、**年度仅 2/11 为正**。
- **累计漏斗（关键发现）**：通过①卡② **+0.77%** → 通过①②卡③ +0.33% → 卡④ −0.55% → 卡⑤ −0.62% → 全通过 −0.51% ⇒ **后三步把好样本筛掉了，不是筛出了更好的**。
- **单条件诊断**：①涨幅 3~5% 唯一微弱正（市场中性口径下实为 −0.19%，即 beta）；②量比>1 **零信息量**；③换手 5~15% **负贡献（t=−16）**；④阶梯放大 **0.00%**；⑤均线多头近零。
- **处置**：**不接入**。候选B 已独立抽出为 `pullback_reversal`（见上）。
- **样本边界**：全样本 2016-09~2026-09；换手率为**估算值**（用最新快照反推股本 → 前视偏差），故换手相关结论仅作近似；买入价 = 信号日收盘，不含费用滑点，**结果偏乐观**。

## 4. 监控机制（P1-38）

**评估器复用**：`picks/signal_health.py::evaluate_signal_health(groups, ...)` 已是**纯函数**（接收按日聚合的序列，不关心数据来源）⇒ 策略级泛化**无需改动评估逻辑**，只需加「策略键 → 当日序列」的适配层。

**适配层**：`picks/strategy_registry.py`

| 函数 | 职责 |
|---|---|
| `list_strategy_keys()` | 登记册中「可评估」的策略键及元数据 |
| `collect_strategy_health(session_factory, key)` | 按策略键取数 → 聚合成组合日序列 → 复用 `evaluate_signal_health` |
| `collect_all_strategy_health(session_factory)` | 逐键评估（每键独立状态，不合并） |
| `strategy_verdicts()` | 仅返回「非 ok」的策略键（供告警/复盘消费） |

**新增一档：`thin`（触发次数长期不足）**——原实现只看**组日数**（`len(groups) < min_groups`），不看**总笔数**。10 天 × 1 笔 = 10 个样本，统计不可靠；10 天 × 20 笔 = 200 个样本，可靠。故策略级评估增加**最小笔数门槛**，不足则状态 = `thin`（区别于 `insufficient` 的"天数不足"），且**不判 ok**（三态纪律）。

**告警口径**：`daily_picks` 沿用既有 `__signal_health__` 规则；新增策略键的告警走同一规则，快照带 `strategy_key` 字段以便分流。**样本不足（`insufficient`/`thin`）绝不告警**——那不是失效信号。

## 4.5 核验产物（S2-11：状态有证据可回查）

`strategy_verify` 是**离线重计算**（duckdb 全历史特征表），不进请求链；它的结论此前只流向
脚本 stdout，登记册的 ⛔/🟡 靠人工誊写 ⇒ **无时间戳、不可回查、状态无背书**。

现在补上落盘 → 回读：

| 部件 | 位置 | 职责 |
|---|---|---|
| 产物 | `backend/data/research/verify/<key>.json` | 一次核验的结论（verdict / headline / metrics / sample / recorded_at） |
| 落盘 | `app/research/verify_registry.py` | `save_record` / `load_record` / `verification_of`（三态）/ `list_records` |
| 判据 | `app/research/strategy_verify.py::gate_verdict` | **[[KB-DEC-019]] 准入五条里可机判的四条**（另两条需人工） |
| 挂接 | `StrategySpec.verify_key` | 有值 ⇒ `list_strategy_keys()` 附 `verification` 三态 |
| 消费 | 议程 `strategy_verification` 一路 | 含 `without_evidence`（标了却没产物）与 **`conflicts`（状态与实测结论打架）** |

**重跑**：`python scripts/verify_two_thirty_five.py`、`python scripts/verify_candidate_b_oos.py`
（各约 12~30s），结尾会打印结论并落盘。**verdict 由 `gate_verdict` 依判据算出，不写死**——
重跑后数据变了，结论自己会变。

**⚠️ 判据口径（2026-09-11 订正）**：`gate_verdict` 的中位/跑赢比例**只接受中性口径**
（`excess_median` / `excess_win_rate`）。初版误用原始口径，会把候选B 判成 pass——
原始胜率在上涨市天然 >50%，用它当判据形同虚设。拿不到中性口径时**跳过该条并记 `unchecked`**，
绝不拿原始口径冒充。

## 5. 维护规则

1. **新策略入册的前置**：先有可计算规则 → 走 `app/research/strategy_verify.py` 五道检验 → 样本外盲测 → 才可登记为 🟡 观察项；接入线上另需 [[KB-DEC-019]] 准入五条（含扣成本 0.2~0.35% 仍为正）。
2. **登记册与代码同步**：`picks/strategy_registry.py` 的策略键与本文 §1 总表由**测试守卫**（键集合一致），改一处必须改另一处。
3. **状态变更必须留痕**：任何 🟢→🟡 / 🟡→⛔ 的变更，须在 §3 处置台账追加一行（含证据链 + 样本边界）。
4. **累计失效自动待评估**：监控状态连续 `drift` 达阈值 → 自动生成待评估项（走既有改进项通道），**不自动退役**（退役是人工决策）。
