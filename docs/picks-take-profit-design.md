# P1 冲高止盈提醒 · 设计方案（2026-09-04，供拍板）

> 需求出处：每日精选改进清单 P1——「日内冲高 ≥3% 减半仓」的**独立可选档位**。
> 本文档只做方案，未写任何实现代码；拍板后按 §5 工作量实施。

## 1. 现状盘点（为什么不能直接用现有机制）

- **预警引擎 AlertEngine**：用户手动建 `change_pct_above 3` 规则可近似实现，但有三个缺口——
  ① scope 只有 all/watchlist/symbols，**没有"每日精选组合"语义**；
  ② cooldown 是秒数，**表达不了"当日一次、跨日重置"**；
  ③ 通知是裸条件陈述，**不衔接出场纪律**（ROI 阶梯/失效条件）。
- **picks watcher**：盘中每拍取数，已有 简报绑定 + alert key 当日去重（append_alert）+ 系统规则 + 通知通道——**缺的三个东西它全有**。
- **日内高点数据**：腾讯批量快照自带 `change_pct`（当日涨跌幅）与 `high`（日内最高），**不需要自己累积状态**，每拍取数即可。

结论：挂在 watcher 侧新增一个 tracker，而不是扩展 AlertEngine。

## 2. 方案（推荐）：watcher 新增 TakeProfitTracker

**挂载点**：`watcher_loop` 内与 `IntradayWatcher` 并列（不塞进 DirectionTracker——那是题材方向语义，这是标的级纪律）。

**标的池**：当日每日精选组合成员 ∪ 盘前简报方向池成员（去重，上限 10 只）。
备选：仅组合成员（更聚焦，拍板点 A）。

**每拍动作**：
1. `_batch_quotes`（腾讯批量，10 只以内单请求）拉标的池快照；
2. 对 `change_pct ≥ 阈值` 的标的生成提醒（触发后当日不再重复）。

**触发口径**：`当日涨跌幅 ≥ 3%`（默认值，env 可调）。涨跌幅口径 = 相对昨收，
与"日内冲高"等价且**直接来自快照字段，无自算误差**。

**当日一次**：alert key = `take-profit:{trade_date}:{symbol}` → `append_alert` 天然去重
（与现有 direction alert 同机制），提醒落当日简报 alerts，前端零改动可见。

**开关（独立可选档位的落地）**：`ASHARE_PICKS_TAKE_PROFIT_ENABLED`（默认 **off**）+
`ASHARE_PICKS_TAKE_PROFIT_PCT`（默认 3.0）。关闭时 watcher 完全不拉这批快照（零开销）。

**提醒文案**（条件陈述 + 纪律衔接 + 红线 3）：

```
【冲高止盈提醒】600XXX {名称} 现价 {price}，日内 +{change_pct}%（≥ 3%）
参考纪律：{tier} 档 ROI 阶梯第一档「减半仓 / 减 1/3」；若为当日追高开仓，注意回踩风险。
失效参考：跌破分时均价线 / 题材退潮。不构成买卖建议。
```

**与 ROI 阶梯的关系**：不替代。ROI 是**持仓累计收益**口径（risk.py TIER_PARAMS），
本档是**日内冲高分批兑现**的独立提醒；文案互相引用，不重复建模。

## 3. 备选方案 B（不推荐）：AlertEngine 扩展

加 `spike_take_profit` condition_type + scope=picks。放弃原因：
组合成员概念缺失、"当日一次"要新表存跨日状态、文案无法衔接 risk.py 档位——
全部要新造，而 watcher 侧全部现成。
