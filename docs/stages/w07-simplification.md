## IMP-050

**猎场及全站用户视图与后台职责分离**

- **状态**：待条件
- **优先级**：P1
- **依赖**：IMP-049
- **方案依据**：用户最新前台简洁/原UI风格/所有功能闭环要求；product-closure-design与hunting-decision-design。
- **范围**：apps/web/app/hunting/page.tsx、agent/page.tsx、components/picks/pick-card.tsx、components/hunting、nav-bar、原ReviewTab、通知/个股详情及对应API消费；保留现有主题/字号/组件体系。
- **验收**：主屏清楚回答为何/等什么/何时失效；参数、进化、调度、预警规则编辑不在普通UI；用户风险结果保留，后台授权直接URL/API不可绕过；同股不重复，盘前/盘中时点不混，旧深链/真实Canvas/键盘与亮暗小屏通过；不靠前台打开维持后台业务。
- **证据**：当前猎场可见生成组合、简报、手动单拍等，agent默认进化并暴露8个内部标签；新增两份设计给出实际路径映射与卡片规格，尚未改UI或上线。
- **产品确认边界**：product-design-confirm-01，等待用户确认总流程与猎场信息架构；Codex不得仅凭旧自动化/旧控制台计划开始改代码。收到确认后由网页依据相关缺陷与阶段状态写下一切片。
- **下一步**：条件为用户确认设计；先固定夹具验证按状态两区卡片和详情，不能硬编码四家族，再接IMP-049真实契约。运营动作迁到受控后台后再移除旧UI，保留功能而非只CSS隐藏。每片不超过一个主要用户流。
- **实施步骤**：①录当前视图/用户路径和接口副作用；②定义读/写与用户/运营边界；③原组件改轻量卡片、等待条件与状态；④复盘替代调试主导航，保留工作台/盘面/市场/猎场已有用途；⑤确认旧链接/无权请求/空态等矩阵；⑥实源和反馈证明简化，没有用户收益的合并不做。
- **恢复**：保留旧路由兼容映射与读模型版本；数据和用户设置不随导航删除；禁用新呈现即可恢复，但不得重新开放已被安全切片封堵的自动转正。
- **细粒度范围**：不止猎场：feature-closure-audit列工作台、详情、盘面、市场、通知、助手、复盘及公共交互，逐动作指定保留/融合/后移/退出与验证。包括搜索失败可见性/旧结果Enter、空池日期、云图聚焦与自选刷新、记账时区、资金历史/板块切换请求身份等源码发现，需相应行为测试再改。


## IMP-005

**按消费者证据聚合与退出**

- **状态**：待条件
- **优先级**：P2
- **依赖**：GOV-020
- **方案依据**：主方案 §7、§8、W07
- **范围**：复核职责冲突、公共原语与重复入口；涵盖事件配色、过宽 export、零调用候选，已交付拆分不重做。
- **验收**：有实际消费者/动态引用与收益证据；契约、导入及 UI 不退化；退出有保留义务核查和恢复点。
- **证据**：api/tools/market/bootstrap 拆分已交付；旧 PR #4 不直接合并，文件行数不构成立项理由。
- **下一步**：满足以下条件再实施：在真实改动暴露耦合时选一个领域；取消“把剩余三个大文件全拆完”的承诺。

- **实施步骤**：①从正在变更的真实消费者找重复与耦合；②比较现状、共享原语、薄兼容门面三种最低成本办法；③调用/动态导入/运行/许可核对后确定可退出范围；④先替代再移除；⑤同输入契约/用户动作步骤与维护成本对照，没有显著收益不拆大文件。
