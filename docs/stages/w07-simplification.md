> 定位：最终融合方案的阶段任务文档；由 [总账 §6.0](../retro-and-gaps.md#60-阶段索引) 唯一索引。任务状态只在本页更新。

- **阶段目标**：让全产品及大小动作有明确用途、信息层次和上下游；仅做有用户/维护收益的聚合、后移与退出。

- **验收**：每个已识别动作能说明用途、输入/对象、消费者、成功/空/错误/取消反馈与恢复；主屏能回答为何/等什么/何时失效。猎场导航按工作流而非封闭战法枚举，默认候选为“机会 / 跟踪 / 影子 / 复盘”四个职责面，具体形态只作筛选/标签；页面/body 不产生业务级纵向滚动，主内容和 Drawer/Modal 自己承担内部滚动。上下文浏览优先 Drawer/inline，轻量筛选优先 Popover，阻断确认或需要大画布/高度聚焦的任务才用 Modal，不机械把所有现有 Modal 改成 Drawer。配置/进化/调试告警后移，必要风险结果保留；直接URL/API鉴权不因隐藏菜单减弱。亮暗/小屏/键盘/焦点恢复/reduced-motion、真实Canvas、旧深链与源时间分别验证，不靠打开页面产生核心业务计算。

- **规划确认边界**：U47 已授权网页按现有系统事实判断并把合理的猎场/UI方向纳入账本，故无需未来再次逐项征求产品方向确认；这不等于当前授权改 UI 代码。实际实施仍只在阶段门轮到后，由 `ashare-ledger-continue` 的“一次继续一个切片”或网页明确派发具体切片触发，Codex不得据设计文档自行抢跑。
- **下一步**：满足以下条件再实施：总账阶段门计算轮到相应 G2 切片，并由既有“继续任务”授权或网页明确派发冻结该切片的范围/对象/验收/恢复依据；消费新猎场机会结构的 UI 还须对应 IMP-049 契约可用。条件满足后先用明确夹具验证信息架构/overlay/内部滚动，再接真实同版事实；其余功能不必等猎场整体完成，但同样不得无派工实施。
- **实施步骤**：①每个实际 UI 切片先执行 Design Read，按 `design-taste` 冻结设计方向与 dials（当前产品建议 DESIGN_VARIANCE≈4/10、MOTION_INTENSITY≈5/10、VISUAL_DENSITY≈8/10，若真实页面证据不支持可在切片内有据调整）；②核原用户路径、每个动作及接口副作用；③分业务读写与用户/运营权限；④先用固定夹具重排信息层次和 overlay 语义，再接同版后端事实；⑤先让受控后台承接管理操作，再退出普通前台入口；⑥按小动作和相邻消费者验证正常/失败/取消/恢复，并用 `ui-state-verify` 覆盖真实渲染的 loading/empty/error/stale/rare branch；⑦实源与用户反馈验证简化收益。一个切片只改变一个主要行为链。
- **恢复**：旧深链保留准确对象的兼容落点，切换前后不抹历史/用户数据；呈现可回退，但不能重新开放已封堵的代码执行/自动晋级权限。后端契约变化须版本对照，不把旧批准套到新代码。
- **条件化依赖**：取消原依赖栏对IMP-049的全任务锁定。只有消费新机会结构的猎场卡片/详情才以IMP-049相应接口为前置；搜索/日期/错误反馈等依据其自己的对象和API；运营迁出依据已有后台承接及鉴权。每片先列真实输入条件，不能将“无整体依赖”解释成没有安全或发布前置。
- **细粒度范围**：feature-closure-audit逐项保存来源及已读/未验边界，product-closure-design §5/§5.1定义小动作目标契约。新增入口/按钮/筛选/计数/提示/后台动作不得被父模块完成覆盖；不为每个按钮新增平行任务编号。
- **历史复盘回调证据**：源9d439c5、review-tab.tsx blob 65b4777dd8d1eb7bd4854f06abfcdeb282708f70。此前在独立Node容器对原toggle只去一处TS注解并注入Promise/setter：控制组单次A成功一致；先A后B且B先成功，迟到A成功会显示B标题/A正文，迟到A失败会清掉B正文。是同一请求身份缺陷的两种反例，不是生产事故或真实React验收。
- **历史反例的未来验证**：在获准实施片用真实组件覆盖初始化、focusDate、toggle、reloadAfterDispose、关闭/卸载/重开；成功和失败都绑定当前对象/代次，显式区分加载/有效空/缺失/错误与陈旧缓存。公共useResource只保护其返回快照，回调自设状态仍须逐消费者检查。
- **非猎场补充契约**：复盘采纳率不作效果指标，“已实施/确认/回退”管理动作迁后台并留证；六位数字先核实体再链接证券。助手本地历史缓存不等于后台任务事实，不能借后台化无授权上传私人聊天。搜索失败、云图自选同步、空池日期、资金历史切换、记账时区和前端费率均按原任务验收。
- **本次变更边界**：只校正任务范围/依赖与历史说明，状态仍待条件；不追加模型/组件/交易试验，不把旧3851/151结果写成本轮新测。


## IMP-054

**全站动效、状态过渡与空间连续性精修**

- **状态**：待条件
- **优先级**：P2
- **阶段门**：G4
- **门内序**：85
- **门禁角色**：非阻断
- **依赖**：IMP-050
- **效果前置**：无
- **方案依据**：U47；`skills/design-taste` motion / interaction-states / pre-flight；现有 `globals.css` motion tokens、NotificationDrawer 与 BoardFlowDrawer。
- **范围**：在既有视觉体系和组件原语上补“状态变化可读、空间连续、防止突兀”的动效：机会状态迁移、Tab/面板切换、Drawer/Modal 进出、必要的列表重排、成功/失败/加载反馈和焦点恢复。默认复用现有 120/160/200/280ms 与 easing token，不为“更酷”引入新动画库或全站装饰动画。
- **验收**：常规过渡目标 <300ms，优先 transform/opacity；高频行情轮询/价格刷新不重复播放整页动画；键盘导航、数据输入和风险提示不被动画延迟；Drawer 从空间来源方向进入，Modal 保持聚焦语义；`prefers-reduced-motion` 下仍完整可理解；真实渲染覆盖 loading/empty/error/stale/rare branch。若列表重排动效增加认知噪音或帧耗时，保持无动画是合法结论。
- **证据**：当前全局已有 motion token、按钮按压、价格 tick、fade/rise/scale、drawer slide 与 reduced-motion；问题不是“零动效基础”，而是关键状态与上下文切换应用不一致，部分交互仍显生硬。因此本项以审计和收敛为主，不重建动画系统。
- **下一步**：满足以下条件再实施：IMP-050 对应页面的信息架构、overlay 语义和内部滚动边界已完成并稳定，且真实页面已具备可对照的静态行为基线。条件满足后按页面价值逐切片实施；先猎场/详情/通知等高频上下文，再决定是否需要扩展到其它页面。每片做 Before/After/Why 设计审查和性能/可访问性回归。
- **恢复**：动效层必须可独立关闭/回退而不改变业务状态、导航落点、交易事实或数据持久化；出现眩晕、掉帧、焦点错乱或高频闪烁时优先退回静态过渡。
