# 联动系统通盘设计（Linkage Design）

> 触发：用户要求把应用**当作一个联动系统通盘设计**，覆盖 ①跨页面选中标的联动 bug 修复、
> ②多页面联动设计、③题材对标同花顺、④新闻事件→个股机会映射。
> 本文是这四点的唯一总纲；明细账本仍是 `docs/retro-and-gaps.md`，阶段索引在 README / PROJECT-MASTER。

---

## 0. 设计原则（全篇的公理）

1. **URL 是选中标的的唯一真相源。** 任何"当前看的是哪只票"的问题，答案都在地址栏；
   组件不各自持有持久化的选中状态。可分享、可回退、刷新不丢、无水合问题。
2. **详情入口只有一个**：`/workbench?symbol=`，一律经 `lib/routing.ts` 的 `workbenchUrl()` 生成，
   禁止手拼字符串（本次 bug 的直接教训）。
3. **页面间联动用 query 传递，不用全局 mutable store**：`?theme=`、`?symbols=`、`?date=` 已是先例
   （题材卡 → 涨停池高亮）。仅当出现"无 URL 语义的瞬态"才考虑引入 store。
4. **归属与结论必须可解释、可反推、可证伪**：题材归属标来源，事件映射标依据与失效条件；
   按项目红线，只给"关联池 + 依据"，不给确定性买卖结论。

## 1. 跨页面联动 bug：根因与修复 ✅（2026-08-31 已完成）

### 1.1 根因链（实测复现 + 代码定位）

```
题材卡/涨停池/龙虎榜/板块/自选管理  <Link href="/stock/002855">   （路径参数）
        ↓
/stock/[symbol]/page.tsx 只读 searchParams.symbol（查询参数）——路径参数从未被读取
        ↓
redirect("/workbench")   ← symbol 永远为空
        ↓
workbench: useState(paramSymbol ?? "600519")  ← 硬编码回退
        ↓
表现：从题材榜点个股，详情永远显示贵州茅台（此前看的自选股）
```

浏览器复现记录：`/themes` 点击 `/stock/002855` → 落到 `http://…/workbench`（无参数）→ 详情显示贵州茅台。
搜索框路径（`router.push("/workbench?symbol=…")`）实测正常——bug 只在 `/stock/` 中转路由。

### 1.2 修复内容

| 文件 | 改动 |
|---|---|
| `apps/web/lib/routing.ts`（新增） | `workbenchUrl()`、`stockRedirectTarget()`、`LAST_SYMBOL_KEY`——统一跳转规范落点 |
| `apps/web/app/stock/[symbol]/page.tsx` | 路径参数优先（`params`），查询参数兼容保留；容错剥市场前后缀 |
| `apps/web/lib/routing.test.ts`（新增） | 7 组回归：路径参数/查询参数/优先级/前后缀/空值/截断 |
| `theme-card.tsx` 等 5 处调用点 | `<Link href={/stock/…}>` → `workbenchUrl()`（search-box、screener、limit-up、longhu、boards、watchlist、theme-card×4） |
| `apps/web/app/workbench/page.tsx` | 无参数进入时回退 **sessionStorage 上次查看标的**（原来硬编码 600519）；`activeSymbol` 渲染兜底 |

### 1.3 回归验证要点（改动跳转逻辑必查清单）

1. **题材页** → 点梯队成员 → `/workbench?symbol=该票`，详情渲染该票（非茅台）
2. **涨停池 / 龙虎榜 / 板块 / 自选管理** → 各点一次（已实测：002855 渲染 +9.99% 行情面板）
3. **外部书签形态** `/stock/600103` 直接访问 → 重定向后仍带 symbol（已实测）
4. **搜索框**从任意页搜索 → 详情正确（已实测：/market 搜 600105）
5. **裸 `/workbench`**（导航栏点"工作台"）→ 显示**上次查看**的票，而非固定 600519（已实测）
6. **工作台内切股**（自选行/持仓行点击）→ URL 同步、详情重挂载、无旧行情残留
7. vitest `routing.test.ts` 7 例 + `tsc`/`eslint`/`next build` 全绿

## 2. 多页面联动设计

### 2.1 状态管理规范（选中标的）

```
真相源层次：
  URL ?symbol=   >   sessionStorage lastSymbol   >   默认 600519
  （显式指定）        （会话内"之前看的"，无参数回退）      （首次访问兜底）
```

- 页面内切股：`setSelected(s)` + `router.replace(workbenchUrl(s), { scroll: false })`——不污染历史栈。
- 组件不得在 effect 外写选中状态；`StockDetailPanel` 以 `key={symbol}` 重挂载，
  保证切股时内部订阅/缓存归零（防旧行情残留，注释已在 workbench 内说明）。
- **不引入 zustand/context** 的理由：A 股工具的联动语义天然可表达为 URL；引入全局 store 会
  复制一份真相源，重新制造本次 bug 的土壤。唯一例外见 §2.4 切片 F。

### 2.2 路由跳转规范

| 场景 | 形式 | 示例 |
|---|---|---|
| 看个股详情 | `/workbench?symbol=600105` | 唯一详情入口 |
| 看题材 | `/themes?date=YYYY-MM-DD` | 日期可分享 |
| 题材→证据 | `/limit-up?theme=X&symbols=a,b` | 成员高亮（已有先例） |
| 事件→题材 | `/themes?focus=存储芯片`（规划） | 聚焦单题材 |
| 语义别名 | `/stock/600105` | 保留，经中转页重定向 |

参数命名统一 snake_case（`min_boards` 先例）；布尔开关用存在性不用 `=true`。

### 2.3 联动矩阵（现状 + 规划）

| # | 联动 | 状态 | 价值 | 优先级 |
|---|---|---|---|---|
| L1 | 题材卡 → 涨停池成员高亮 | ✅ 已有 | 归属可审计 | — |
| L2 | 各列表页 → 个股详情 | ✅ 本轮修复 | 高频路径 | P0 |
| L3 | 选股器/搜索/持仓 → 详情 | ✅ 已有 | — | — |
| L4 | **详情页 → 所属题材 chips**（点 chip → `/themes?focus=`） | ⬜ 缺口 | 详情是枢纽，回看题材最自然 | **P1** |
| L5 | **题材卡 ← 官方成分徽标**（成分/归因双源标注，依赖 §3） | ⬜ 缺口 | 归属可信度一眼可见 | P1 |
| L6 | 预警事件行 → 详情 | ⬜ 缺口 | 触发即查看 | P1（小） |
| L7 | 热力图格子 → 详情 | ⬜ 缺口 | 盘中巡览 | P2 |
| L8 | 回测标的 → 详情/题材 | ⬜ 缺口 | 低频 | P2 |
| L9 | **新闻事件条目 → 相关标的池**（依赖 §4） | ⬜ 缺口 | 事件驱动入口 | P1（依赖 §4） |
| L10 | 市场总览页题材榜 → 题材页 | ⬜ 缺口 | 顺手 | P2 |

优先级排序逻辑：**详情页（workbench）是全站枢纽**——L4/L5 让"个股⇄题材"双向闭环，是体验增益最大的两刀。

### 2.4 实施切片

- **切片 A（本轮）**：路由统一 + bug 修复（§1）。
- **切片 B（P1，小）**：详情页题材 chips（Phase 4 遗留的"概念题材 chips"）接入 §3 的题材归属 API；
  题材页支持 `?focus=` 聚焦。文件：`stock-detail.tsx`、`themes/page.tsx`、后端归属查询端点。
- **切片 C（P1，小）**：预警事件表 symbol 列加 `workbenchUrl` 链接（`alerts/page.tsx`）。
- **切片 D（P1，依赖 §4）**：事件条目 → 标的池 → 详情（`market` 页事件面板）。
- **切片 E（P2）**：热力图/回测/总览跳转（L7/L8/L10）。
- **切片 F（触发式）**：仅当出现"多页面需要实时共享瞬态"（如大盘联动高亮）才引入轻量 store。

## 3. 题材对标同花顺：题材—梯队—个股映射

### 3.1 现状与差距（代码级核实）

| 项 | 现状 | 差距 |
|---|---|---|
| 题材全集 | 无。题材名只出现在涨停股 `reason` 的「+」分隔串里 | **无涨停发生的题材不存在**（粮食概念等结构性题材缺失） |
| 题材→个股归属 | 仅"当日涨停归因"一层 | 无官方成分股层；无归属置信度；炸板池完全无题材 |
| 梯队 | 题材卡内按连板分层 + 角色（龙头/中军/补涨，规则可解释） | 已满足 |
| 板块行情 | 东财 push2 字段序推断，`verified: false` | 无题材级 K 线交叉验证 |

### 3.2 目标数据模型（三层归属，高层压制低层）

```
Theme（题材字典）            ThemeMember（归属）              梯队 = 当日涨停成员 ∩ 归属
- code        88xxxx.TI     - theme_code                    - 连板数分层（已有）
- name        粮食概念       - symbol                        - 角色判定（已有：龙头/中军/补涨）
- aliases     种业/粮食安全   - attribution_source            - 断层/健康度（已有）
- source      ths|em|manual   ths_official | limit_up_reason | event_infer | manual
- thscode_ver 同步版本        - confidence   3|2|1|0          ← 归属来源决定，见 §3.3
- updated_at                - verified_at
                            - override?（人工纠错引用）
```

**归属置信度层级（冲突时高层压制低层，不覆盖、并列展示）：**

| 层 | 来源 | 置信度 | 语义 |
|---|---|---|---|
| L3 | THS 官方成分股 | 3 | 结构性归属（粮食概念常年属于该题材） |
| L2 | 当日涨停归因（reason） | 2 | 行为性归属（今天为何涨停） |
| L1 | 新闻事件推断 | 1 | 推断性归属（§4 产物，必须标"推断"） |
| L0 | 人工 override | 最高（直接裁决） | 纠错机制产物 |

### 3.3 数据源与三方交叉校验

**主源（同花顺官方，key 已在 `backend/.env`，经 `skills/hithink-finance` 的 59 端点）：**

1. `GET /api/a-share-index/catalog/ths-index-list?tag=cn_concept` → **题材全集目录**（含粮食概念等无涨停题材），一次全量
2. `GET /api/a-share-index/constituents/ths-stock-list?thscode=88xxxx.TI` → **官方成分股**（注意：是"当前成分"，不是历史成分，需自存版本）
3. `GET /api/a-share-index/prices/historical` → **题材级历史 K 线** → 顺带把 B3「板块 3/5/10 日涨幅 `verified:false`」升级为可交叉验证

**对照源：** 东财概念板块（push2 板块列表已接）；涨停池 `reason` 归因（已接）。

**三方校验矩阵：**

| THS 官方成分 | 东财概念成分 | 涨停归因 | 结论 |
|---|---|---|---|
| √ | √ | — | `verified`，confidence 3 |
| √ | × | — | confidence 2（单源），进观察名单 |
| × | × | √（今日） | confidence 2，归因展示为"涨停归因"非成分 |
| 归因 ∈ 成分矛盾 | — | √ | **进人工复核队列** |

### 3.4 差异排查与纠错机制

- **同步 job**（每日收盘后）：题材目录全量（周频即可）+ 抽样成分日更 + 涨停归因每日比对；
  产出差异报告，暴露为 `GET /api/themes/reconciliation`（新增题材 / 成分变动 / 单源归属 / 归因冲突）。
- **人工纠错**：`theme_overrides` 表（symbol + theme_code → include/exclude + reason + 有效期），
  权重高于一切自动归属；题材卡与详情 chip 上，override 过的归属带人工标记。
- **展示规范**：详情页/题材卡的每个归属标注来源徽标（官方成分 / 涨停归因 / 事件推断 / 人工），
  悬停显示依据——延续全站"可解释"范式。

### 3.5 实施切片

- **T1（中）**：`theme` / `theme_member` / `theme_override` 三表（alembic）+ 同步 job + `GET /api/themes/catalog|members|reconciliation`。验收：题材全集含"粮食概念"，其成分与 THS 官网抽样一致。
- **T2（小，依赖 T1）**：详情页题材 chips 换官方成分源（L4/L5 联动一起做）。
- **T3（小，依赖 T1）**：题材 K 线替代东财字段序推断（B3 收尾）。

## 4. 新闻事件 → 个股机会（事件驱动选股）

### 4.1 现状

已有：**个股维度**新闻/公告 + 规则摘要器（重要度/情绪/关键数字，`app/news/rules.py`）+ LLM 可插拔降级。
缺：**事件维度**——宏观/行业新闻不挂任何 symbol，进不了个股摘要管线；无事件→题材/个股映射；无事件生命周期。

### 4.2 三个给定案例的判定示范（本节即判定 SOP 的用法说明）

**案例 1：「美国拟禁止中国 AI 企业经泰国、新加坡调用英伟达芯片」**

| 维度 | 判定 | 依据 |
|---|---|---|
| 可靠性 | 来源分级定档；**"拟"= 草案/意向，未落地** | 政策类事件必须区分"已立法 / 拟议 / 传闻"三档，直接影响确定性 |
| 方向 | 双向：利空海外算力链（算力租赁/转口），利好国产算力自主可控（国产 GPU/昇腾链/存储） | 禁令抬升替代需求——利好利空**必须成对分析** |
| 时效 | 半衰期长（政策博弈数周），但存在反复（听证/豁免会二次冲击） | 政策型事件生命周期模板 |
| 题材 | 命中既有题材「算力租赁」「国产芯片」；若"东南亚转口监管"无对应题材 → **候选新题材** | §4.4 新题材识别 |
| 标的池 | THS「算力/GPU」概念成分 ∩（东财资金流或涨停池确认）——**用成分反查，不用关键词猜股票** | 映射精度靠 §3 |

**案例 2：「沃什鹰派发言致美股与黄金大跌」**

| 维度 | 判定 | 依据 |
|---|---|---|
| 可靠性 | 发言公开转播，事实层高可靠；"致…大跌"是**因果解读**，需标注为解读而非事实 | 事实与解读分离，摘要器已有此纪律 |
| 方向 | 利空黄金股（金价）、利空高估值成长（贴现率敏感）；利好美元资产 | 宏观传导链：发言 → 利率预期 → 资产价格 |
| 时效 | **半衰期短（1–3 天）**：发言型事件，次日 A 股开盘传导后基本消化 | 时效模板：发言 < 数据 < 政策 |
| A 股联动 | 隔夜外盘 → 当日黄金概念开盘缺口；事件面板在 T 日盘前标记 | 事件时间线要挂"传导时点" |

**案例 3：「长鑫 LPDDR6 全球首发量产」**

| 维度 | 判定 | 依据 |
|---|---|---|
| 可靠性 | 若来自官方发布/一线权威 → 高；"全球首发"措辞需核（是否有竞品已发布） | 超级lativo词（全球首/第一/颠覆）触发置信度降档复核 |
| 方向 | 利好存储产业链：长鑫概念成分、存储模组、封测、上游设备材料 | 量产=业绩可兑现，比"研发突破"强一档 |
| 题材 | 「存储芯片」既有题材升温；"LPDDR6 国产量产"若库中无题材 → 候选新题材 | 新题材识别 |
| 标的池 | 长鑫概念成分（THS 有专门概念）∩ 流动性过滤；关联度按供应链环节分主次（主：模组/封测；次：设备） | 供应链环节分层 |

### 4.3 事件评估框架（可解释打分，规则先行 + LLM 增强）

```
EventCard:
  id, title, url, published_at, source, source_tier(1-5)
  fact_vs_opinion     事实 / 解读 / 传闻        ← 三档，摘要器口径延续
  certainty           已落地 / 拟议 / 传闻
  half_life_hours     政策 336 / 发言 48 / 数据 24 / 传闻 2（模板，可人工改）
  direction_map       [{target_type: theme|symbol|macro, target, direction: +1|-1|0,
                        strength: 0-3, chain: "利率预期→金价", basis}]
  new_theme_candidate 主题名 + 触发词
  status              active / expired / resolved / rejected
  review              人工确认记录（新题材入库、方向纠错）
```

- **可靠性分 = source_tier × 独立确认数**：官方公告 5 / 一线权威 4 / 主流财经 3 / 聚合转载 2 / 自媒体 1；
  多源独立报道才升档，聚合转载互转不算独立确认。
- **时效性**：`active = now - published_at < half_life × 2`；事件面板过期置灰不删（可回溯）。
- **方向判定**：题材×方向词典（规则先行）→ LLM 增强分类（配 `ASHARE_NEWS_LLM_*`，未配自动降级并显式标注）；
  夸张量级词（全球首发/史无前例）与"拟/传闻"措辞触发**确定性降档**。
- **新题材识别**：事件关键词在题材库（§3 目录）匹配失败且 direction_map 非空 → `new_theme_candidate` →
  人工确认入库（题材库新增走 THS 目录核对，避免臆造题材名）。

### 4.4 事件驱动选股 SOP（沉淀为可复用流程）

```
① 采集    东财快讯/公告（已接）+ 指定补充源；去重（标题指纹 + 多源确认计数）
② 抽取    规则分句/实体识别（复用 news/rules.py 的情绪与关键数字）→ LLM 增强分类（可选）
③ 注册    生成 EventCard（fact/opinion、certainty、half_life、direction_map，全部带依据）
④ 映射    direction_map.target = 题材词典命中 → §3 概念成分反查标的池 → 涨停池 reason/资金流佐证
⑤ 标的池  成分股 ∩ 流动性过滤（成交额下限）∩ 行为确认（当日涨停/主力净流入加分排序）
          ——输出「关联池 + 依据 + 失效条件」，不给确定性结论（红线）
⑥ 呈现    事件面板（market 页）→ 事件→题材（?focus=）→ 标的→详情（workbenchUrl）
          事件命中自选/持仓时走预警通道提醒（L9 × 预警）
⑦ 复盘    T+1 / T+N 验证每个事件的池内表现 vs 大盘，胜率回写事件模板权重；
          接入复盘 Agent 的元结论迭代
```

- API：`GET /api/events?active=1`、`GET /api/events/{id}/stocks`、`POST /api/events`（人工注册）、
  `POST /api/events/{id}/review`（人工纠错，写回模板）。
- 表：`event_card` + `event_direction`（映射行）+ 复盘结果回写。
- 与现有模块的联动：复用 news 摘要管线做 ②；复用 §3 概念成分做 ④；复用预警通道做 ⑥；
  复用复盘 Agent 做 ⑦——**事件模块是各既有成果的汇合点，不新造轮子**。

### 4.5 实施切片

- **E1（中）**：EventCard 表 + 规则抽取（词典/来源分级/半衰期模板）+ `GET /api/events` + market 页事件面板（只读）。
- **E2（小）**：事件→题材→标的池映射 + 详情/题材页事件标签（L9）。
- **E3（触发式，等 LLM）**：LLM 增强分类与新题材候选精排；未配置时全部规则路径可用。
- **E4（小）**：事件复盘回写（胜率权重），接复盘 Agent。

## 5. 总优先级与依赖

```
P0  路由统一 + bug 修复           ✅ 本轮完成（§1）
P1  切片 B  详情题材 chips + ?focus   ← 依赖 T1
P1  T1 题材目录/成分同步（粮食概念验收）
P1  E1+E2 事件最小闭环（规则版）
P1  切片 C  预警→详情（半小时级）
P2  T3 题材 K 线（B3 收尾）/ E4 复盘回写 / 切片 E 其余跳转 / E3 LLM 增强
外部触发项：E3、LLM 增强、推送通道（不变）
```

依赖主线：**T1（题材基建）是 B/E 两个切片的共同前置**——题材映射精度决定事件选股可信度，
这是"联动系统"的核心支撑关系；事件模块再把题材、新闻、预警、复盘四个板块串成闭环。
