# 知识库总索引（KB Index）

> 定位：**本项目唯一权威知识库**——用户亲授知识、历史教训、系统决策的 canonical 版本。
> 与 docs/INDEX.md 的分工：INDEX 管「文档」；这里管「知识点」。引用知识时必须标注 KB-ID。
> 建库：2026-09-09（用户指令：知识散落多文档无法回忆 → 整合为结构化可检索知识库）。

## 检索方式

- 按类别读：`01-stock-picking.md`（选股）/ `02-trading-lessons.md`（交易教训）/ **工程教训 KB-ENG 分四册**：`03-engineering.md`（**应用与设计层**）/ `09-verification-pitfalls.md`（**验证层**：测试·门禁·CI·防线有效性）/ `10-data-contract-pitfalls.md`（**数据契约层**：写入·去重·传输·时间·质量门）/ `08-tooling-pitfalls.md`（**工具与环境陷阱速查·操作类短条目 KB-ENG-01~15**）/ `04-decisions.md`（系统决策）
- 按关键词：`grep -rn "关键词" docs/kb/`（如 `grep "竞价" docs/kb/` → KB-STOCK-11）
- 按状态：本索引表格「状态」列过滤（⏳ 待落地条目 = 议程 C 类改进项候选池）

## 状态定义

| 符号 | 含义 |
|---|---|
| ✅ | 已落地：有组件/流程承载，注明位置 |
| 🔶 | 试验中：影子运行/实验窗口内 |
| ⏳ | 待落地：已有设计，未实现或未接线 |
| ❌ | 被取代：保留条目防回退，注明被谁取代 |
| 📎 | **示例/参考输入**：题材案例、外部材料等——**不构成规范，不得当判定标准使用**（[[KB-DEC-018]] [[KB-DEC-019]]） |

> **📎 的用法（2026-09-10 新增，KB-DEC-019 反固化条款）**：具体题材/个股案例只允许以「示例」身份存在；
> 其可迁移价值是背后的逻辑，**案例里的排序/强度/"更优"等结论性内容不得当已验证知识使用**。
> 单日、单案例的"吻合"**不构成验证**（同一交易日的多个吻合只算 1 个证据）。

## 文档治理（07-doc-curation.md）

docs/ 与 memory 的**文档整理方法论**（v1.6）：六层分类（L0 权威知识→L5 只读历史→L6 参考输入）、归属三问、精华五要素、完成态计划的压缩归档流程、双索引与串联纪律、同类合并/拆分判据、三级淘汰与安全护栏、**长度按层配额**（KB 条目 ≤60 / 框架 ≤500 / 报告 ≤600 / 日志单轮 ≤80）+ **摘要前置**（>150 行须前 40 行含速览与导航，**含层例外**）、试运行与自我淘汰条款。
**体检已脚本化**：`python3 scripts/doc-health.py`（A 未登记 / B 死链 / C 超层配额 + **C-KB 条目超长 + C-KB 扫描覆盖**（后者防"扫描面写窄导致新文件零检查"，[[KB-ENG-60]]）/ D 摘要前置 / E 同类聚集 / **F 代码注释死引用**（B 只扫 `*.md`、F 扫 `app/tests/web/scripts`）/ **F2 代码裸名死引用** / **F3 KB 指针错册**（`见 kb/NN-x.md … KB-ID` 必须同册），有问题 exit 1）——**每个功能点收尾必跑**。
**状态语义铁律（v1.6）**：`✅ 已落地`＝有组件承载；**示例/题材案例一律 `📎`**，两者不得混用（[[KB-DEC-019]]）。

任何"整理文档/整合同类/归档计划/清理冗余文档"类任务**先读该框架**；附录 A/B 为本仓库现状体检与首批整理候选（执行前需逐项确认）。

## 维护规则（沉淀机制）

1. **当轮入库**：对话中用户教的新知识 / 拍的决策 / 重大教训 → **同一轮**写入对应 KB 文件（含 ID/来源/状态/关联）并更新本索引；daily log 只留一行指针。
2. **状态流转**：⏳ 落地后改 ✅ 并补「组件 + commit」；被取代的条目改 ❌ 并写「被 KB-XXX 取代」——**永不删除条目**。
3. **冲突处理**：两条知识冲突 → 各自加 ⚠️ 指向对方，不得静默覆盖（矛盾本身是有价值的信息）。
4. **健康检查**：每日议程第八路证据（`evidence.knowledge_base`）自动统计本索引；⏳ 超 14 天自动列入复查；周五元评估做重复/孤儿扫描。
5. **召回链路**：会话开始 → `.workbuddy/memory/MEMORY.md` 指针 → 本索引 → 按类别读文件。（云端 conversation_search 对本项目召回已实测失败，本地 KB 是唯一可靠来源。）
