# 交易教训（KB-TRADE）

> 盘面判断、数据口径、归因层面踩过的坑。每条：触发条件 → 后果 → 正确做法。
> 整合自 `.workbuddy/memory/2026-08-29 ~ 09-09` 逐日日志与实战事故；发现遗漏按 00-INDEX 维护规则补录。

### KB-TRADE-01 会话 current_time 不可信
- **触发**：用系统注入的会话时间判断「今天/盘中还是盘后/数据是否定稿」。
- **后果**：09-02 实测会话时间滞后 12 小时——把凌晨的昨日终稿误判成盘中未定稿，结论全错。
- **正确做法**：一律先 `date "+%Y-%m-%d %H:%M:%S %Z"` 实测；涉及交易日的判断必须先验日期。

### KB-TRADE-02 UTC/北京跨日：日期源必须同源
- **触发**：测试用 `datetime.utcnow().date()`，被测代码用北京日期。
- **后果**：09-09 午夜后频率闸测试必炸（UTC 与北京差一天）——「一直好的测试突然挂」。
- **正确做法**：同一逻辑链里的日期必须同源（统一 `beijing_now()`）；排查「测试突然挂」先怀疑午夜跨日/时区，再怀疑代码。

### KB-TRADE-03 内存快照盘后重启为空
- **触发**：依赖 `app.state.snapshot_service.snapshot` 的端点，在非交易时段重启后端。
- **后果**：09-08 概念弹窗全部 `--`（change_pct/换手/流通全 None）。
- **正确做法**：此类端点必须有 parquet 存档 / 批量实时行情两级兜底；兜底不了的字段显式 null（三态）。
- **失效条件**：当消费该快照的**每一个字段**都有了存档或批量实时兜底之后，本条降级为「历史事故记录」而非当前约束；只要还有字段只能从内存快照取，它就继续成立。**判断方法是逐字段查兜底，不是查有没有兜底模块。**

### KB-TRADE-04 同名字段异源异单位
- **触发**：流通市值在快照（nmc，万元）与东财（ltsz，元）同名不同单位。
- **后果**：换算混乱、口径打架。
- **正确做法**：统一走单一数据源（快照），换算一处完成并注释；跨源字段必须标注口径。
- **失效条件**：字段被收口到单一源、换算集中到一处并有单位标注之后，这一**具体冲突**（nmc 万元 vs ltsz 元）不再成立。⚠️ 但「同名异源异单位」这个**模式**不会失效——换主源、加新源时必然重现，所以真正要留的是「跨源取同名字段先对齐单位」这道检查，不是这条记录本身。

### KB-TRADE-05 三态纪律
- **触发**：把「判读不出来」渲染成二态（有/无）。
- **后果**：unknown 被吞掉，用户把「未判定」当成「没问题」；09-08 曾因 `or "—"` 兜不住 truthy 泄漏事故。
- **正确做法**：unknown 显式「未判定」、缺失显式 `--`；对外文案单点收口（后端 tri_text / 前端 format.ts triText），禁止散落拼接。

### KB-TRADE-06 验收以实际渲染为准
- **触发**：凭代码推理/像素计算下「应该没问题」的结论。
- **后果**：08-29 连续两次事故（改后端没重启、布局被挤出）全靠推理漏掉。
- **正确做法**：UI/功能验收必须 agent-browser 文本通道实测（snapshot/eval）；纯布局问题看不出来就如实说「无法目视，需你确认」。

### KB-TRADE-07 盘点三原则
- **内容**：①盘点先 `grep` 再信文档（文档会过时）；②跨日先验日期；③跨口径数字不可相加（如 signal-health 的 0-1 小数与 intraday-review 的百分数）。

### KB-TRADE-08 空池=合法行情
- **触发**：把「数据源正常返回 0 行」当成失败（09-09 跌停池「all providers failed」实为东财上游明确返回 0 跌停——73 家涨停的强势日）。
- **后果**：误报 + 误熔断。
- **正确做法**：failover 语义区分「正常返回空」与「源异常」：任一源正常响应（空否）即采用；全源抛异常才报错。
- **失效条件**：本条的判据是「响应成功即视为正常，哪怕 0 行」。一旦某个源把**上游异常也返回成 200 + 空数组**（而非抛错），这个判据就失去区分力 ⇒ 必须改用源侧的错误码/字段判定，**不能再只看行数**。也就是：数据源行为一变，本条就从「正确做法」变成「误报来源」。

### KB-TRADE-09 瞬态状态不入异常白名单
- **触发**：connecting（WS 毫秒级握手态）进入「异常可见」名单。
- **后果**：每次进个股页都闪一下「● 连接中」然后隐藏（09-09 用户反馈）。
- **正确做法**：异常提示类 UI 一律加最小持续时间防抖；瞬态正常过渡不该打扰。

### KB-TRADE-10 归因误判：独立题材无共振时 certainty 高估
- **触发**：09-09 澳洋健康——情绪面独立题材，无板块共振却判了确定性=高。
- **后果**：唯一失败案例（当日亏 3%+）。
- **正确做法**：certainty 判定必须含「共振检查」：独立题材（归因单一、无相邻链涨停）降档处理；归因类别×胜率周度统计暴露此类系统性误判（[[KB-TRADE-13]]）。
- **失效条件**：本条是**单案例（n=1）提出的待验证假设**，不是已确认的规律。共振检查落地并经周度统计（[[KB-TRADE-13]]）检验后，只有两种结局：①「独立题材」这一类的胜率**显著低于**其他类别 → 本条升格为已验证判据；②与其余类别**无显著差异** → 本条前提不成立，应作为个案噪声撤销（可能那笔亏损的原因根本不是"无共振"，而是量价或大盘）。在统计跑出来之前，**不得把"独立题材必然亏"当选股结论引用**。

### KB-TRADE-11 筛选宁缺毋滥
- **触发**：机会候选登记无量化门槛（09-09 开盘 25 分钟滥登记 27 条）。
- **后果**：跟踪泛滥、提醒失焦、用户需要逐条排除噪音。
- **正确做法**：入池硬门槛（boards≥1 或 pct≥5 或 cert=高）+ 交易时段限制；watcher/买点等强信号路径豁免；门槛依据写入台账 reason 可追溯。
- **失效条件**：门槛是三项的**并集**（满足其一即入池），所以它的失效方式有两种，方向相反：①**漏报**——实测显示某条单独就会把有效机会挡在池外（门槛过紧）；②**失效豁免**——新增信号类型时忘记登记豁免，强信号被当普通候选拦下。两者都要靠「门槛依据写入 reason」来发现，不能靠感觉。此外门槛针对的是**盘中机会候选登记**，不适用于盘后复盘回看。

### KB-TRADE-12 清除类操作用时间切线
- **触发**：通知「一键清除」用当前窗口条目的 id 集合。
- **后果**：窗口外的历史记录滑入窗口后「复活」（09-09 用户反馈「连以前的记录也清除」）。
- **正确做法**：用清除时刻的时间切线（ts < line 全部隐藏），一条规则覆盖全部历史；渲染与过滤必须同源（[[KB-ENG-13]]）。

### KB-TRADE-13 归因类别×胜率周度统计（改进闭环）
- **来源**：09-09 五部分复盘第 2 问——归因记录的最终用途。
- **内容**：台账 reason 已固化五类归因（时事/消息/基本面/情绪/技术）；每周按「归因类别 × 成功/失败」聚合胜率，暴露系统性误判类别 → 反哺选股标准。
