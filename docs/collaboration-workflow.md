# 账本驱动协作：网页规划审核，Codex执行

> 现行方式是固定仓库记录+用户短提示；没有Bridge或自动互调依赖。协作任务归 [GOV-022](stages/w08-governance.md#gov-022)，当前允许动作看 [handoff](handoff.md)，理论/计划收口归 [GOV-020](stages/w00-foundation.md#gov-020)。

## 1. 职责与授权

网页ChatGPT负责理论、目标/架构/产品设计、计划、阶段任务增删重排、验收设计与成果审核。Codex实施明确派工范围、测试并回填事实/偏差/建议，不自行批准或降低验收。用户决定目标与重大权限/费用/范围取舍，并触发两端读取。
当前用户明确本次仅做理论、方案及关联文档，不执行账本业务任务；此前Codex无额度时网页临时代执行的授权不覆盖这个更具体的当前范围。更新计划/任务定义不是实施那些任务，设计批准不是代码批准。

## 2. 固定入口与共享事实

仓库1239890829/AI-Trading，当前固定入口为codex/collaboration-runtime-state分支的docs/handoff.md。分支名只保留历史身份，不运行同名自动化。执行目录只是交接记录，接收方仍核实际分支、HEAD、未提交变化及并行执行者。
方案决定目标，stage拥有任务状态/派工/结果/审核，handoff只定位本轮模式和唯一协调项；不建立重复账本，不每轮导出接手版。先提交并确认共享版本，再说已交付。仅本地文件不等于网页已看到，聊天中的“通过”也不替代可核记录。
更换执行分支先回写固定入口、确认双方可见，才切换；合主干和删除分支不得丢唯一入口或未合成果。临时目录不是唯一证据位置，必要脱敏证据须在双方可访问载体，缺原始证据明确未核验。

## 3. 人工短提示循环

网页在原阶段记录当前模式、轮次、范围/非目标、依据版本、验收和允许下一动作。Codex收到“ChatGPT审核完了”后只触发读取，按真实记录决定执行、整改、等待或只读；不能因为提示里有审核就默认通过。
Codex执行完必须记录实现/测试/偏差/剩余、提交推送，然后用户在网页说“Codex执行完了”。网页读真实差异和必要证据，先审核成果再复评下一步，结论写回同一任务。没有明确下一任务就不自行跨轮。
用户不复制任务卡、提交号或整段历史，不承担技术审核；短提示是通知，不是已完成证据、批准或发布授权。模型额度不足影响执行，不妨碍获准的规划工作，不试探额度或切收费API。

### 3.1 三种不同的完成

**规划交付**：需求/目标/边界/依赖/对象/验收方法/文档去向齐备，检查和共享版本可核；不需要现在修BUG、跑业务测试或证明策略收益。当前是这个模式。
**实施送审**：Codex有明确派工、执行事实和对应证据；初次开工不要求先有尚未产生的成果审核。需整改只返回明确范围，不能借整改启用新功能。
**发布放行**：网页对准确候选代码作出有效结论、明确允许发布，且原完整CI和权限条件全部满足；规划确认或作者自检均不能替代。未合/未部署如实说明。

### 3.2 换会话、重复通知与冲突

同项目新会话先读AGENTS→固定handoff→协作→方案→对应stage与证据。第一次完全无项目上下文时先定位仓库一次，之后不依赖聊天记忆或前台窗口标题。不能从不带项目的一句提示猜任务。
同轮已完成/已执行不因重复通知重做；先确认旧执行者停止，不并发写同工作区。不reset/clean、不覆盖未知改动；远端更新不代表本机已同步。目标/版本/任务不唯一时先核对，不能凭最新时间戳选择方便的一份。

### 3.3 模式不能自行升级

当前handoff的DESIGN_ONLY意味着只交付文档。没有另行明确的实施请求和网页派工，不因计划存在P0、图已展示或用户说“完善方案”而启动业务修复、回放、模型、采集、迁移或部署。用户中途增加某模块要求是叠加，不是取消其余规划范围。

## 4. 每轮需要思考什么

规划轮审要求去重、概念是否混用、用途/消费者是否完整、替代方案、隐私/权限、前后台和验证边界。实施审核轮另读实际代码与证据，沿真实影响链核所有大小消费者，不能只看报告或大模块标题。
对新发现记录证据等级、原因/竞争解释、用户净收益、开发/维护/迁移/运行/模型/CI成本、风险和恢复；比较保持现状、最小修补、复用与替代。可整改、并入原任务、重排、补证、观察、否决或不改，不要求每轮添加功能。
没有新证据不不断重写已定稿方案。工程与效果验收分开，不以任务数/采纳率/代码行数当收益；原验收不得事后放宽。持续节省但保留有效测试和安全机制。

## 5. 版本与审阅记录

阶段留本轮范围、依据/被审提交、实际读取内容、结论、限制及明确下一动作。作者自检不是独立代码审核；用户短提示不是审计签名，同账号权限也不是密码学角色隔离。
被审实现提交与随后纯协调文档提交分开；新业务代码/基点变化必须重审。最终合并仍针对准确候选SHA和完整CI，不做递归自指提交。规划稿由网页编制/自查可以交付，不能据此声称同作者业务代码获独立批准。

## 6. 故障与缺证据

读取失败不批准，写入/推送未成功就不称已交付；网络超时先核实际结果再重试。平台安全拒绝不能换接口重放同一动作。独立且获准的文档读取/规划可继续，不能把不相关失败扩大成所有工作必须停。
缺失原始资料的内容要么限定为未证候选，要么安排将来明确取证切片，不能伪造已读/已验证；也不因此把已完整定义的总体规划无限延期。源资料、设计、执行证据有不同的完成标准。
