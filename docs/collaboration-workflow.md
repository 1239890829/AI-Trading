# 账本驱动协作：网页统筹审核，Codex执行

> 当前规则：2026-09-18用户选择“固定仓库记录＋一句话人工触发”，替代此前自动调度、Bridge转递和跨网页唤醒路线。任务唯一归 [W08/GOV-022](stages/w08-governance.md#gov-022)，当前入口为 [handoff](handoff.md)。旧方案与试验从 Git 的 e852b03 及更早版本追溯，不是现行施工指令。

## 1. 分工不变，取消搬运

网页ChatGPT负责目标、架构、计划、阶段任务的增删重排、验收、独立审核及下一步决策；Codex负责已获准切片的实现、测试、提交和执行事实回填，不自批、不自行降低验收标准。用户只触发两端并处理重大取舍、权限、费用或异常。
用户对网页说“Codex执行完了”，对Codex说“ChatGPT审核完了”。这两句话只要求读取最新记录，不是完成证明、审核通过或合并授权。无需用户复制任务卡、提交号、整段聊天或新导出文件。
正常接续不再依赖Bridge、浏览器操作、后台调度、模型互调或运行状态SQLite。人工触发不是绕过权限/安全拒绝；确实受阻的动作和所依赖任务仍暂停。

## 2. 固定入口与共享事实

本批先固定 `1239890829/AI-Trading` 的 `codex/collaboration-runtime-state` 分支 `docs/handoff.md` 为双方协调入口。其任务链接指向唯一阶段条目；不得凭最近窗口、聊天标题或master推测当前工作。分支名中的runtime只是历史名称，不表示需要运行原型。
当前施工目录与分支由handoff给出，接收方必须核实际HEAD、差异和并发编辑者。执行分支需要切换时，先在固定入口回写新目标并推送，双方核到后再继续；未合主干前不得删除唯一入口分支。完成合并后转用master入口须明确交接一次。
长期只维护：implementation-plan负责取舍；retro-and-gaps索引阶段；docs/stages维护任务唯一状态、执行事实和审核结论；handoff只指明当前工作区/唯一活跃任务/最近证据，不复制另一份任务状态表。AGENTS和两份Skill负责强制读取顺序。
正式事实先保存在双方都可读的仓库版本。Codex先提交并推送，再报告交付；只有本地改动不算已交给网页。详细日志可在忽略的artifacts，但仓内须有命令、结果、输入版本及证据定位。无本机访问时，必要的脱敏证据由执行端在既有获准共享载体提供；拿不到就标未核验，不用摘要替代原始证据。

## 3. 一句话触发的循环

1. 网页在所属阶段条目写本轮编号、任务范围/非目标、计划与代码基点、验收和停止条件；handoff指向此条目。先核回写/推送成功，再说明可交给Codex读取。
2. Codex收到短提示后刷新并核对入口、任务和实际工作区。初次派工无需尚不存在的成果审核；已进行或已消费的同一轮提示不重复实施，上一执行者未退出时不并发写同一工作区。
3. Codex实现、跑适用检查、记录真实问题与建议，提交/推送代码及阶段执行记录，停在待审。没有完成就如实写阻塞，不能因为用户说“完成了”就标完成。
4. 用户对网页说“Codex执行完了”。网页自动读入口、固定版本的实际diff、关键消费者与测试证据，给出通过/需修改/阻塞，并进行§4的价值复评。
5. 网页把审核结论、发现、限制和下一动作写回同一任务；有必要时修计划、合并/新增/退出任务并重排，再更新入口和推送。无需每轮另发交接文件。
6. 用户对Codex说“ChatGPT审核完了”。Codex读取实际结论：需修改只做限定整改；阻塞就停；通过且有明确下一任务才执行。循环继续，用户不承担技术审批或内容搬运。

### 3.1 动作条件

首次实施以已写入任务的明确派工为依据；整改以“需修改”和限定范围为依据；合并必须有当前准确版本的网页审核通过及原完整CI/发布条件。提示词中的“审核完了”不代表通过。批准前证据不足时不放行。
单轮信息放在任务的本轮派工、执行记录、审核结论、下一步字段中；编号用于防重和历史定位，不新增任务系统。事实回填由Codex负责，审核结论及规划决定由网页负责；原任务整体未完成时不要因一个切片通过而销账。

### 3.2 新会话及重复通知

同一项目新网页会话或正确目录的新Codex任务，先读AGENTS、固定handoff、协作规则、当前方案、对应任务及证据；核验一致后可接续，不依赖旧聊天记忆。第一次新会话若缺仓库定位，必须明确指定本项目，不能从无上下文的“审核完了”猜项目。
窗口标题和会话ID不是代码版本；重复通知不能生成重复任务。固定入口无唯一当前条目、代码已变化、旧任务仍在运行、回填尚未推送或多人并发时，先核实不猜测。不重置、清理或覆盖归属不明的改动。

### 3.3 旧互调路线已退出

旧双端自动派工、网页唤醒、自动回执消费和Bridge控制方案被账本短提示方式取代，不再作为候选建设路线。旧结果记录原型及其44项专属测试已成对回收；版本与恢复证据保留，不把退出写成自动化成功。

## 4. 每轮审核之后必须重新判断下一步

先验本轮正确性，再沿实际影响链检查数据→存储→决策→页面/通知→模拟风险→复盘的一致性、重复建设和缺失能力；不每轮无差别重审全仓，也不机械领取下一行。
对新发现比较现状、最小修补、复用/合并与替代方案；记录事实与不确定性、用户收益、实现/维护/迁移成本、性能与安全影响、依赖、验收和恢复。只有净收益有依据、风险可控才纳入计划。无证据先做限定取证，无价值就拒绝或推迟，避免为了主动而堆任务。
结果可以是本轮整改、并入现有任务、调整下一优先级、退出重复项或不改变原计划。原验收门槛不能事后放宽。持续复核成本特别是后端CI，记录真实重复次数及热点，不删有效断言求快。

## 5. 审核记录与提交版本

阶段任务保存本轮编号、审核者、被审代码提交、计划依据、实际读取范围、结论、限制和明确下一动作。作者自检不等于独立审核，Codex不能代写网页批准；用户的一句话不是审核证据。
审核文档回填会产生新提交，不能把旧SHA的审核默认为覆盖任意新代码。明确区分被审实现提交与随后协调文档提交；后续工作以双方核实后的基点开工。合并前仍须对最终候选准确SHA核diff和完整CI，必要时以既有PR审查记录确认，不递归提交自指SHA或新增批准服务。
同账号/同磁盘权限不构成密码学身份隔离；这套方式是可追溯的流程纪律，不宣称技术上不可伪造。平台原保护、权限、金融硬门和发布检查全部保留。

## 6. 失配、额度及访问失败

读不到所需版本或证据时不批准；回写/推送被拒绝时说明未交付，不能只在聊天说审核完成。连接超时先确认动作结果，不重复提交。安全拒绝不通过换通道重放原操作，独立且获准的工作可继续。
Codex额度不足只暂停其推理，不新购额度或切付费API；用户恢复可用后触发正常读取。短提示不会消除Git权限、浏览器登录、生产授权或CI要求，不承诺任意失败仍能继续。

## 7. 精简及恢复边界

不使用自动派工、浏览器自动发送或模型互调作为协作依赖。Bridge与扩展可不使用，本轮不卸载个人App或删除个人对话。业务后台采集、计算、通知、风险、复盘和有界研究调度保留，不与协作互调混淆。
旧协作原型先核消费者/运行者与哈希，通过既有safe-trash成对回收，真实恢复核验后再退出；保留26a0c44和原证据。仅其专属测试删除，业务测试不减。重复导出不再生成；独有历史、当前方案/阶段/交接不能当废稿删掉。
恢复旧代码用于调查不自动恢复旧施工目标，不启动模型互调、不放松CI/金融/权限保护。

## 8. 可行性与验收边界

现有Git、阶段索引、任务唯一记录及两端已具备的读写能力足以承担此流程；不再以Codex接口、扩展采集完整性或自动唤醒为成立条件。文件读取、链接及状态检查可以现在验证；Codex在新规范下的真实一轮执行/回报/复审仍须之后实测，不能将文档检查称为双端验收。
接续验收覆盖：唯一当前任务、普通通过、需要整改、证据不足、重复提示、未推送结果、错分支、新会话和并发旧任务。用户仅说两句提示时，双方都能从仓库恢复正确动作才算使用验证完成。
