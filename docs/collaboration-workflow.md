# 网页 ChatGPT 统筹审核与 Codex 执行协作规范

> 生效：2026-09-18，依据用户最新明确指令；属于实施方案 v9.2 的治理修订。
> 本文只维护权责、审核协议和交接方法。实现任务唯一归 [阶段总账 §6.0](retro-and-gaps.md#60-阶段索引) 的 W08/GOV-022；当前现场见 [handoff](handoff.md)。
> 结论：人工转递可以组成闭环；受控半自动具备部分实证；双向无人值守尚未打通。本轮没有向 Codex 发送模型请求、没有绕额度、没有部署后台桥接服务。

## 1. 固定分工与旧授权替代

2026-09-18临时代执行：用户在Codex额度不足期间明确要求ChatGPT继续按方案实施；当前切片、继承分支与证据统一见 docs/handoff.md 及所属阶段，不在多处复制当轮状态。不调用Codex或付费模型；作者自检不冒充独立审核。只推送功能分支，审阅与准确版本完整CI未齐不合主干或上线；长期统筹/执行分工保留。

| 主体 | 负责 | 不得代替的职责 |
|---|---|---|
| 网页端 ChatGPT | 产品目标、架构取舍、方案、阶段/任务增删与优先级、验收标准、逐轮偏差及合理性审核、下一轮授权 | 不接管日常业务代码实现，不用自报全绿代替实际审查 |
| Codex | 执行已批准切片，代码/测试/兼容与迁移实现、测试证据、提交/PR、按条件发布、执行事实回填 | 不自批自己的成果，不自行降低验收标准或改主计划/优先级，不跳到未授权下一轮 |
| 用户 | 需求与最终取舍、账户/登录/权限/费用、必要人工转递和异常裁决 | 不必替双方逐文件搬运内容，但保留可停止和撤销权 |

这条最新分工替代旧“Codex 无需网页端最终审查即可合并”和“可自行改方案后继续下一轮”的条款。历史提交保留，不追溯伪造旧审核。
Codex 可自主选择批准范围内的实现细节；发现更优方案、额外缺陷或范围变化时先提交依据和变更建议，由网页 ChatGPT 决策后更新计划。紧急情况可停止危险操作、保全现场，不可借止险扩大权限。
Codex 可回填已批准任务的实际执行状态、证据与阻塞；任务增删/重排、验收降级、架构/策略变更由网页 ChatGPT 统筹。确认通过与下一轮指令必须由网页审核侧给出。
网页 ChatGPT 可独立读取代码、日志及隔离复现，运行必要审核检查；编写/提交治理文档属于统筹职责。这不等于把业务实现或应用内自主执行重新交给网页端。

## 2. 可行性验证结果

| 环节 | 本轮结论与证据 | 使用边界 |
|---|---|---|
| 网页 ChatGPT 读本机项目、写计划/审核文件 | 当前 Remote Desktop Commander 已实际使用，项目与 Git 可读写 | 电脑在线、连接和当轮工具权限可用；不能推定 Codex 也有同名工具 |
| 网页 ChatGPT 发控制请求到本机 Codex | 找到内置 CLI；独立空 CODEX_HOME 下 initialize、initialized、thread/loaded/list 往返成功并正常退出 | 只证明控制面；未加载原任务、未调用 turn/start、未进行模型推理 |
| Codex 可编程继续任务 | 本机 CLI 帮助和生成 schema 有 thread/read、thread/resume、turn/start；官方也支持 exec resume/SDK [S1][S2] | 原任务身份、权限和额度恢复后必须做一次受控实测 |
| 打开 Codex 并预填指令 | 本机注册 codex URL scheme；官方支持新会话 prompt/path 和打开已有 thread [S3] | 预填不是发送；未实测自动提交，默认由用户确认发送 |
| Codex 向网页审核会话提交提示词 | 官方浏览器/计算机操作可作为候选；本机 Safari 常量脚本探针被权限阻止 [S4] | 没有给网页发消息；不修改浏览器安全设置，不冒称此方向已通 |
| 网页组件触发后续消息 | 官方 MCP Apps ui/message、sendFollowUpMessage 存在 [S5] | 需可用并加载的组件及主机允许；不是从任意外部进程直接写任意会话的公共入口 |
| 自动等待并再次唤起当前网页会话 | 本次未找到已连通的通用入站发送/唤醒工具，未实测 | 普通工具回执、文件变化、网页开着不等于会启动新审核轮；保留人工发送 |
| 额度耗尽时继续 Codex 推理 | 本轮按用户说明视为不可用，未试探提问 | SDK/CLI/换入口不转移额度；不换付费 API、购买 credits 或循环重试 [S6] |
| “Codex 必须服从”的机器强制 | AGENTS/流程规则本轮生效；审核强制检查尚待 Codex 实现 | 文本指令不是权限隔离，同账户/同磁盘可写不能证明审核凭证不可伪造 |

本机信息：应用位置 `/Applications/ChatGPT.app`，bundle 为 `com.openai.codex`，应用版本 `26.908.70816`；内置 CLI `/Applications/ChatGPT.app/Contents/Resources/codex`，版本 `0.154.0-alpha.6.2`。裸 `codex` 不在当前终端 PATH。安装/更新后重新定位，不硬编码为永久位置。
Safari 探针只执行常量和站点 origin，不读聊天内容/凭据、不输入或发送消息；返回必须开启 Allow JavaScript from Apple Events。该权限本轮没有启用。不能把这一条路径受阻解释成所有浏览器工具均不可用。
官方 app-server 文档与本机帮助仍标有实验性边界，优先本机 stdio，不开放公网控制端口。握手成功不代表原桌面任务可安全并发接管，也不代表零额度可推理。

## 3. 立即可用的最小闭环

1. 网页 ChatGPT 明确一个切片的任务ID、目标、文件/消费者、非目标、验收与停止条件，并给出计划版本。
2. 用户将首次执行指令发给 Codex；Codex 先读最新 AGENTS、handoff、本规范及所属任务，确认工作区、分支与继承成果。
3. Codex 完成批准范围内实现和适用完整门禁，提交可审核 commit，生成脱敏审核包；标“待交付”，停止下一轮。无额度则保留已有现场，不重试模型。
4. 用户在本项目网页会话发送“审核任务ID＋分支/完整SHA＋审核包位置”；有可用已授权浏览器工具时可辅助填写，发送前仍遵守主机确认策略。
5. 网页 ChatGPT 实际读取方案、精确差异、关键消费者和证据，输出通过、需修改或阻塞，附发现、限制与具体下一步。证据不齐不能默认通过。
6. 审核不通过，Codex 只按整改范围修复并重新提交；通过也只执行审核回执明确允许的动作。合并仍要求当前准确SHA完整CI及原安全条件。
7. 用户转递审核回执/继续提示词给 Codex，或使用已验证的本机控制桥接单次发送；完成后再回报网页审核。每次放行只覆盖一个确定切片/整改轮，不构成无限自治许可。

人工传递通常只需短提示和文件/SHA，不复制大段日志。人工点发送不是重新设计方案，也不自动证明代码审核通过；它负责可靠触发下一端。

### 3.1 按动作区分开工、整改和发布条件（v9.2 复核勘误）

| 动作 | 必须具备 | 不应要求 |
|---|---|---|
| 首次只读确认 | 用户/网页明确指令、正确任务/工作区、当前规范 | 尚不存在的成果审核回执或本轮CI；不得因此修改业务代码 |
| 首次实施派工 | 网页明确派工，记录 assignment_id、任务/切片、计划版本、base、范围/非目标、验收及停止条件 | 对尚未实现的成果先出APPROVED；派工不是成果审核，不自动授权合并 |
| 审核整改 FIX_ONLY | 来源可核的CHANGES_REQUESTED及明确整改范围，绑定被审版本 | 先有APPROVED或先通过正在修复的CI；整改后必须重新送审 |
| 合并 MERGE_IF_GATES_PASS | 当前版本的网页APPROVED＋本地完整门禁＋准确提交/集成态的必需CI＋原发布约束 | 不得只凭派工、整改授权或摘要中的“通过”代替 |
| 下一切片 START_NAMED_SLICE | 上轮对应成果已通过网页审核、网页明确指定下一切片，并满足该切片实际前置 | 不强迫所有无关阶段先完成；不得用一份批准无限跨轮 |

首次派工与成果审核共用现有交接/消息定位，不新增平行任务账本。没有正确授权仍须HOLD，但不能因缺少尚不存在的上轮回执而禁止首次开工；没有审核也不得合并。人工和未来机器检查器使用同一动作语义。

## 4. 受控半自动路线，不先建大平台

A. **先文件协议**：复用 Git、阶段任务、handoff 与忽略的 artifacts；先跑通一轮人工转递。不引入新模型、云服务、自动消费额度或系统常驻任务。
B. **辅助转递**：Codex 生成审核包和网页提示词，网页端写审核回执和 Codex 提示词。可用官方 deep link 打开指定任务/预填新任务，但不把打开成功当发送成功。
C. **优先有限前台工具闭环**：额度恢复后，网页ChatGPT用当前已授权连接启动一个Codex切片，工具返回thread/turn及实际结果；只要当前网页轮次仍在执行，就在同一轮读取证据、审核并按明确许可发下一条有限指令。Codex无需操作浏览器“给网页发消息”。本轮仅控制协议往返已测，真实模型结果返回和审核续作未测；由Codex实现必要的最小适配，不部署常驻大平台。
前台循环必须有明确轮数/任务预算、完成/停止/超时条件；本轮不启用。网页响应结束、工具超时/断连或任务转后台后，这个机制不会自行唤醒下一轮，必须用户发送继续或使用另行验证且获准的触发机制。运行中的工具结果可被当前轮读取，与“文件变化自动启动空闲网页”是不同能力。
D. **网页审核请求触发**：先评估现有已授权 Browser/Computer Use；缺能力或不稳定就保留人工发送。仅在实际账户支持且明显省时后才评估自定义 MCP UI 的“请求审核”按钮，不为此购买套餐。
E. **双向自动化条件验收**：两方向各自成功、错误会话拒绝、重复/过期请求拒绝、权限与额度异常停止、并发锁、证据持久化、用户停止均通过后，才考虑有限轮数联调。当前没有启用这一层。

不采用无人监督 DOM 脚本作为默认审核入口；不使用未公开会话接口、复制登录cookie、读取auth.json或改写旧会话日志来伪造对话。遇到登录、验证码、权限提示由用户处理。
## 5. 审核包与放行回执

审核包由 Codex 生成；至少包括 repo、任务/切片ID、计划版本及哈希、base_sha、head_sha、改动文件清单、实现与偏差、实际命令/结果/环境、未验证项、恢复方法、证据路径及哈希。只传任务必要信息，不上传密钥/完整用户日志/私人持仓或模型内部推理。
网页 ChatGPT 不只读 Codex 总结：检查真实 diff、范围与设计一致性、失败分支、数据/统计语义、回归与独立反例、性能比较条件、恢复和用户价值；未知/未测单独列出。

审核回执最少字段：

```text
review_id: 全局唯一、不可复用
reviewer: ChatGPT-Web（必须有可核实的网页消息或受控写入来源）
task_id / slice_id: 与本轮派工一致
repo / base_sha / reviewed_head_sha: 完整固定版本
plan_revision / plan_hash: 审核依据
request_hash / evidence_hashes: 对应审核包
verdict: APPROVED | CHANGES_REQUESTED | BLOCKED
findings / limitations: 具体发现、严重度和未验证范围
allowed_action: FIX_ONLY | MERGE_IF_GATES_PASS | START_NAMED_SLICE | HOLD
next_slice: 明确下轮或空；不得写“随意继续剩余任务”
issued_at / expires_at: 带时区绝对时间，人工转递也要复核新鲜度
source_reference: 网页审核消息定位或独立受控回执
```

APPROVED 仅说明所列范围的审核结论，不等于所有效果已证明、已合并或已上线；MERGE_IF_GATES_PASS 才允许在完整CI和现有授权均满足后合并。开始下一业务切片须有 START_NAMED_SLICE 或同等明确派工。
有新提交、base/计划/证据变化、过期或审核撤销，旧回执不能直接放行。文档回填若改变候选HEAD也须重新绑定，不允许拿旧SHA审核新提交。
回执优先放**候选提交之外**：已有PR的独立评论，或原项目受控 artifacts 中的审核文件并由网页消息确认。不要为把审核报告提交进候选分支而造成“写回执→SHA变→再写回执”的自循环。阶段页只保留回执索引与执行事实。
桥接器只按完整结构和来源核验，不搜索自然语言中的“通过”二字；不接受代码注释、工具返回或 Codex 自述作为网页审核批准。相同review_id/request_id重送不得再次启动任务。

## 6. 当前强制力与实现要求

AGENTS 是行为规则，不是安全隔离 [S7]。必须如实区分：本轮已更新规范；Codex 后续负责实现检查器/必要hook；平台保护和独立审核签发权限尚未建立，不能称为强制不可绕过。
审核输出与执行端若共享同一Git账号或同一用户磁盘权限，`reviewer=ChatGPT-Web` 字段和哈希都不能单独证明来源。自动放行前需独立可核来源/受控签发，做不到则由用户确认回执并手动触发，不为追求自动化扩大凭据或权限。
最小检查器只验证任务/版本/证据/回执与允许动作，和既有 release_check.py **合取**；不得替换其完整CI检查。首次实现先本地正反夹具，仍需网页审核实际diff后启用。没有检查器时先按人工流程执行，不把业务工作全部挂死。

## 7. 工具用法与不能混淆的入口

**Codex 控制面（本轮仅握手）：** `codex app-server --listen stdio://` → `initialize` → `initialized` → `thread/read`核指定任务 → `thread/resume` → `turn/start`。后两步及模型续作本轮没有执行；必须先验证额度、工作区、会话空闲和有效放行。[S1]
`codex exec resume <明确SESSION_ID> <提示词>` 为官方非交互续作入口 [S2]。不得用 `--last` 猜任务；不要同时由桌面和桥接器写同一会话/工作区。CLI/SDK与网页端工具调用是不同接口，不能互换参数。
本机CLI绝对路径见 §2；后续更新后核实际版本与生成schema，不能只照旧网页示例。禁止 bypass approvals/sandbox/hook-trust；不把控制端口暴露到公网。

**桌面预填：** `codex://threads/<thread-id>` 打开已有本地会话；`codex://new?path=<编码后的绝对目录>&prompt=<编码后的短提示>` 预填新会话。官方明确预填不会自动发送 [S3]。URL只放任务ID及文件位置，不放密钥、完整代码或私人数据。新会话必须读取项目交接，不能假装继承了原线程。
**当前轮工具返回：** 对网页侧发起的前台Codex执行，优先让控制工具回传完成摘要和持久证据定位；网页仍在运行时可直接审核，无需Codex二次调用网页UI。不能把控制请求accepted当任务completed，工具超时后先核实际状态。
**网页请求：** 默认由用户向本项目的网页聊天发送 §9 模板。浏览器工具必须核域名、项目、会话与输入内容；不能把“另一标签页是ChatGPT”当成正确审核线程。没有实测工具权限时，不编造点击/输入命令。
**MCP组件：** 官方支持 iframe 内 ui/message/兼容 sendFollowUpMessage；这是未来可选的单次请求审核按钮，不是当前Remote Desktop Commander已有功能，不承诺关闭网页后仍能唤起审核 [S5]。
**Hooks：** 可用于生成交接包或提醒；Stop续作可能创建额外模型轮次，不能用它反复催促等审核。后台hook在无活跃turn时不会自行开始新turn；禁止无限轮询/重试消耗额度 [S8]。
**API模型不等于网页审核：** Responses/Conversations API创建的是API侧会话 [S9]。即使模型同名，也不自动获得本网页线程、项目指令和工具上下文；不得悄悄换成付费API审核或Codex子代理自审。

## 8. 人工介入点与失败停止

| 情形 | 应做什么 |
|---|---|
| Codex额度不足或未知 | 保留提交/审核包/未完成位置，停止模型调用；等待额度恢复后由用户或获准桥接单次续作，不买额度、不换API计费 |
| 网页登录、验证码、浏览器/MCP权限 | 用户完成必要登录/授权；工具不得关闭安全保护或读取登录凭据 |
| 网页当前轮已结束、不会自动开始审核 | 用户发送短审核提示；上传/写入文件、Git push、网页开着都不等于审核已启动 |
| 审核完成但无Codex可用执行入口 | 用户在正确Codex会话发送回执和继续指令；未发出前记待转递 |
| 来源不可核、内容被截断、SHA变化或回执过期 | HOLD；重新读取完整证据/回执并请网页复核，不猜测批准 |
| 工具确认被拒绝、设备睡眠/断连、进程中断 | 保留断点；只对可证明未执行的转递做有界重试。接收状态未知先查实际thread/turn，不重复提交 |
| 发现任务越界或方案不合理 | Codex给依据与替代建议并停止越界部分；网页ChatGPT裁决，必要用户确认 |
| 云端CI/权限/余额不可核 | 阻止合并而不是冒称通过；已有本地取证可继续，但不无限堆积未发布工作 |

默认自动续作预算为零，直到 GOV-022 完成受控联调并由用户启用；联调只允许一个指定切片/往返，任何失败、审查异议或上下文不一致即停。技术上可发送不等于已获业务授权。

## 10. Codex 实现 GOV-022 的验收清单
