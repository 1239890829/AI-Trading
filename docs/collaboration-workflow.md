# 账本驱动协作：网页规划审核，Codex执行

> 现行方式是固定仓库记录+用户短提示；没有Bridge或自动互调依赖。协作任务归 [GOV-022](stages/w08-governance.md#gov-022)，当前允许动作看 [handoff](handoff.md)，理论/计划收口归 [GOV-020](stages/w00-foundation.md#gov-020)。

## 1. 职责与授权

网页ChatGPT负责理论、目标/架构/产品设计、计划、阶段任务增删重排、验收设计与成果审核。Codex实施明确派工范围、测试并回填事实/偏差/建议，不自行批准或降低验收。用户决定目标与重大权限/费用/范围取舍，并触发两端读取。
2026-09-18 的 DESIGN_ONLY 规划批只做理论、方案及关联文档；该限制只约束那一轮，不是长期“当前模式”。当前允许动作必须从最新 `master` 的 handoff 与所属 stage 读取；更新计划/任务定义仍不等于实施那些任务，设计批准也不等于代码批准。

## 2. 固定入口与共享事实

仓库 `1239890829/AI-Trading`，固定共享入口为最新 `master` 上的 `AGENTS.md`、`docs/handoff.md`、阶段总账与对应 stage。功能分支只是当前施工载体，不再承担长期入口职责；接收方仍须核实际分支、HEAD、未提交变化及并行执行者。
方案决定目标，stage拥有任务状态/派工/结果/审核，handoff只定位本轮模式和唯一协调项；不建立重复账本，不每轮导出接手版。先提交并确认共享版本，再说已交付。仅本地文件不等于网页已看到，聊天中的“通过”也不替代可核记录。
更换执行分支先在 handoff / stage 回写分支与基点并确认双方可见；合主干和删除分支后，固定入口仍留在 `master`，不得把已删除功能分支继续写成当前入口，也不得丢未合成果。临时目录不是唯一证据位置，必要脱敏证据须在双方可访问载体，缺原始证据明确未核验。

## 3. 人工短提示循环

网页在原阶段记录当前模式、轮次、范围/非目标、依据版本、验收和允许下一动作。Codex收到“ChatGPT审核完了”后只触发读取，按真实记录决定执行、整改、等待或只读；不能因为提示里有审核就默认通过。
Codex执行完必须记录实现/测试/偏差/剩余、提交推送，然后用户在网页说“Codex执行完了”。网页读真实差异和必要证据，先审核成果再复评下一步，结论写回同一任务。没有明确下一任务时，Codex不得自行凭感觉跨轮；但用户若在 Codex 端明确调用 `ashare-ledger-continue` 并说“继续任务/继续”，且 handoff 允许实施，则可按该 Skill 的全局动态选刀规则自动领取**一个**最高优先级可开工切片。
用户不复制任务卡、提交号或整段历史，不承担技术审核；短提示是通知，不是已完成证据、批准或发布授权。模型额度不足影响执行，不妨碍获准的规划工作，不试探额度或切收费API。

### 3.1 三种不同的完成

**规划交付**：需求/目标/边界/依赖/对象/验收方法/文档去向齐备，检查和共享版本可核；不需要同时修BUG、跑业务测试或证明策略收益。2026-09-18 的 DESIGN_ONLY 批属于这个模式。
**实施送审**：Codex有明确派工、执行事实和对应证据；初次开工不要求先有尚未产生的成果审核。需整改只返回明确范围，不能借整改启用新功能。
**发布放行**：网页对准确候选代码作出有效结论、明确允许发布，且原完整CI和权限条件全部满足；规划确认或作者自检均不能替代。未合/未部署如实说明。

### 3.2 换会话、重复通知与冲突

同项目新会话先读最新 `master`：AGENTS→handoff→协作→方案→对应 stage 与证据。第一次完全无项目上下文时先定位仓库一次，之后不依赖聊天记忆或前台窗口标题。不能从不带项目的一句提示猜任务。
同轮已完成/已执行不因重复通知重做；先确认旧执行者停止，不并发写同工作区。不reset/clean、不覆盖未知改动；远端更新不代表本机已同步。目标/版本/任务不唯一时先核对，不能凭最新时间戳选择方便的一份。

### 3.3 模式不能自行升级

handoff 若明确 DESIGN_ONLY / REVIEW / BLOCKED，则不得执行；计划存在 P0、图已展示或用户说“完善方案”也不自动构成业务修复、回放、模型、采集、迁移或部署授权。正常情况下仍由网页针对当前版本派发实施切片；另一个等价入口是：handoff 已处于可执行模式时，用户在 Codex 端明确调用 `ashare-ledger-continue` 并说“继续任务/继续”，由 Skill 按账本 P0/P1/P2、依赖、解锁价值和证据成熟度动态选择一个唯一切片。该授权只覆盖这一刀，Codex不能因此重排计划或连续扫完整账本。

## 4. 每轮需要思考什么

规划轮审要求去重、概念是否混用、用途/消费者是否完整、替代方案、隐私/权限、前后台和验证边界。实施审核轮另读实际代码与证据，沿真实影响链核所有大小消费者，不能只看报告或大模块标题。
对新发现记录证据等级、原因/竞争解释、用户净收益、开发/维护/迁移/运行/模型/CI成本、风险和恢复；比较保持现状、最小修补、复用与替代。可整改、并入原任务、重排、补证、观察、否决或不改，不要求每轮添加功能。
没有新证据不不断重写已定稿方案。工程与效果验收分开，不以任务数/采纳率/代码行数当收益；原验收不得事后放宽。持续节省但保留有效测试和安全机制。

对架构、模型、研究方法、数据源或长期策略方向这类高影响问题，规划复评还必须问“外部是否已有更好的公开实现/反证/标准变化”；按 `continuous-evolution.md` / `ashare-innovation-radar` 做原始来源筛选。机械修复和已知局部问题不强制每轮广搜，避免把外部研究变成固定成本。

### 4.1 重大决策不能只更新一个专题

新模型、工具链、架构、产品语义、协作、权限或治理决定进入项目时，网页规划侧必须按 `plan-registry.md` §1.1 做传播核对：逐项列出总方案、专题蓝图、INDEX、所属 stage、AGENTS/Skills/handoff 等受影响权威面是“已更新”还是“不适用+理由”。Codex 在接手/交接 Skill 中复核该清单；发现漏更先标治理缺陷，不把“专题已写”当整套方案已同步。

历史基线不因传播核对被批量改写；只有仍声称描述当前版本/架构的摘要需要更新当前指针。可机械判断的版本/入口/Jev 链由 doc-health 守卫，语义是否受影响仍由网页审核负责。

## 5. 版本与审阅记录

阶段留本轮范围、依据/被审提交、实际读取内容、结论、限制及明确下一动作。作者自检不是独立代码审核；用户短提示不是审计签名，同账号权限也不是密码学角色隔离。
被审实现提交与随后纯协调文档提交分开；新业务代码/基点变化必须重审。最终合并仍针对准确候选SHA和完整CI，不做递归自指提交。规划稿由网页编制/自查可以交付，不能据此声称同作者业务代码获独立批准。

## 6. 故障与缺证据

读取失败不批准，写入/推送未成功就不称已交付；网络超时先核实际结果再重试。平台安全拒绝不能换接口重放同一动作。独立且获准的文档读取/规划可继续，不能把不相关失败扩大成所有工作必须停。
缺失原始资料的内容要么限定为未证候选，要么安排将来明确取证切片，不能伪造已读/已验证；也不因此把已完整定义的总体规划无限延期。源资料、设计、执行证据有不同的完成标准。

## 8. 规划与使用验证各自的界限

规划检查：要求和取代关系可追、任务单点、角色/版本/模式一致、失败动作明确、已有文档入口可达。本文给出的流程是协议设计，不宣称已跑通真实双端一轮。
持续使用验证：每次真实交接都要覆盖正确项目/任务、通过/整改/阻塞、重复提示、未推送、错分支、换会话及并行旧任务。2026-09-18 规划批没有执行这项双端实测；之后的真实实施轮逐次积累证据，不另建自动化平台。
