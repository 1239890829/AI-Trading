# AShare AI Trader 开放式自主进化蓝图

> **定位**：系统长期“向外发现 → 严格筛选 → 隔离验证 → 证据准入 → 观察淘汰”的唯一现役设计。
> **状态归属**：流程治理归 W08 / GOV-025；具体候选一旦进入实验，回到真正拥有它的阶段任务，不在本文维护第二套任务状态。
> **核心原则**：开放但不透传；新不等于好，旧也不等于该守。当前方案是可证伪、可替换的基线，不存在“最终版”。

## 1. 为什么需要这条链

Jev 的引入暴露了两个相反风险：

1. **闭关风险**：只优化现有模块，会错过能改变成本、速度、可靠性或能力边界的新模型、工具、方法论和数据机制；
2. **追新风险**：看到热度、榜单、demo 或高 star 就接入，会扩大权限、依赖、维护、隐私和研究偏差。

因此外部世界只能先产生**候选与证据**，不能直接产生生产能力或新任务。系统长期目标不是“采用更多东西”，而是更快发现真正有增量的东西，也更快否决没有增量的东西。

## 2. 两条互补通道：Watch + Scout

### Watch：已知对象发生了什么

复用现有 backend/scripts/repo_watch.py、docs/repo-watch/ 与 docs/kb/05-repo-tracker.md：

- 已采用/已评仓库的新 release、breaking/deprecation、关键路径变化；
- 现有依赖的维护状态、归档、供应链风险；
- 已否决候选若发生足以推翻旧结论的变化，允许重新进入 Assess。

Watch **不负责发现全新世界**，也不自动 pull/install/升级。

### Scout：世界出现了什么值得我们看

按领域轮换发现新候选：

- AI 模型、推理/路由/验证、Agent 与 coding harness；
- 数据源、检索、RAG/知识管理、浏览器/工具协议；
- A 股/量化/事件/微观结构/风控/回测与研究方法；
- 工程、性能、可观测性、测试与安全供应链；
- 产品交互、研究工作流与可解释呈现；
- 监管、交易规则和官方接口变化。

Scout 只创建候选卡，不自动创建业务任务。

## 3. 来源分层

### A 级：主证据

优先使用可固定版本或日期的第一方来源：

- 官方模型/工具 release notes、文档、模型卡、API 契约；
- 上游仓库源码、tag/commit、LICENSE、测试与安全公告；
- 交易所、监管机构、数据供应方正式接口说明；
- 原论文、作者代码与可复现实验。

### B 级：独立/可复现实证

用于验证厂商或作者主张：

- 任务相关 benchmark、独立复现、同行评审；
- SWE-bench / lm-evaluation-harness / MLPerf 等公开可复现实验框架；
- OpenSSF Scorecard 等供应链机器信号；
- 与本项目冻结基线同条件的本地 A/B。

### C 级：发现线索

GitHub Trending/star、社区帖子、Reddit/HN/X、博客、视频、榜单、二手解读只负责“发现可能值得查的东西”。它们不能单独支撑 Adopt/生产准入。

**star 不再是硬门槛。** 新出现但能力独特、来源可信、能解决真实缺口的候选，即使 star 很低也可进入 Assess；高 star 也不能替代许可证、测试、适配与实证。

## 4. 候选生命周期（不是任务状态）

~~~text
DISCOVERED
   ↓
SCREENED ───────────────→ REJECTED
   ↓
ASSESS ───────→ HOLD / RECHECK_TRIGGER
   ↓
TRIAL
   ↓
SHADOW / CHALLENGER
   ↓
ADOPTED
   ↓
OBSERVE ─────→ RETIRED / REPLACED
~~~

这些状态描述**外部候选成熟度**，不替代 W00–W09 任务状态。只有进入 TRIAL 且需要项目改动时，才并入已有任务或在所属阶段新增最小任务。

失败/淘汰记录不删除；它们用于下一轮去重、搜索词改进和判断旧结论是否仍有效。

## 5. 候选卡最小字段

每个进入 SCREENED 的候选至少记录：

- identity：名称、类型、来源、版本/commit、发现日期；
- claim：它声称解决什么；
- project_gap：对应本项目哪个真实问题/机会；没有消费者则不继续；
- novelty：与现有机制、已否决候选、最小替代方案的差异；
- evidence：A/B/C 级来源及未验证主张；
- prerequisites：数据、权限、硬件、账号、网络、模型/运行时；
- license_security：许可证、维护状态、依赖/供应链与可执行第三方代码风险；
- privacy_permission：外发内容、secret、私人数据、写权限和副作用；
- cost：钱、token、延迟、CI、算力、存储、维护复杂度；
- reversibility：停用/回滚/替代是否清楚；
- target_metrics：用什么本项目指标判定，而不是看宣传榜单；
- disposition：继续、观察、否决及原因；下一次重评触发条件。

禁止用一个“总分”掩盖硬门。许可证不明、真实交易越权、秘密/私人数据外发、不可恢复副作用等可以直接一票否决。

## 6. 七级筛选与准入

### G0 相关性

先问：它是否解决当前真实缺口，或能显著提升正确性、可靠性、成本、速度、研究能力、用户体验、安全性？

没有明确消费者 → 只留线索，不深评。

### G1 硬门

网络调用前优先做确定性筛选：

- LICENSE / 使用条款；
- 真实交易、资金或生产权限；
- secret / 私人信息 / 数据外发；
- 强制新增付费；
- 平台/硬件不可满足；
- 已被现有能力完全覆盖且无可测增量。

### G2 新颖性与替代

同时比较：

1. 保持现状；
2. 最小修补；
3. 复用现有组件；
4. 引入候选。

外部新方案只有在至少一条重要维度有**可测增量**时继续。

Jev 可用于 bounded 的类别、相关性、候选去重、能力路由判断；不得让 Jev 自己决定 Adopt，也不得把 confidence 当效用。

### G3 源码/契约审计

固定版本后核：

- 实际代码/模型契约是否等于宣传；
- 测试、issue、release、维护频率；
- 许可证与供应链；
- API/数据时间语义；
- 权限、写操作、日志/receipt 是否泄露正文。

### G4 隔离 Trial

第三方代码默认在独立环境运行：

- 固定 commit / model version；
- 不给生产 secret、私人持仓和写生产权限；
- 冻结输入、基线与简单替代；
- 记录环境、失败分母、成本和可复现命令；
- smoke 只证明“能跑”，不证明“有价值”。

### G5 Shadow / Challenger

必须与现有 Champion 同时看：

- 同输入、同时间窗、同数据质量；
- 质量 + 成本 + 延迟 + 可靠性 + 维护/权限风险一起比较；
- 策略类必须 point-in-time、walk-forward、成本后、分市场状态；
- 模型/Agent 类必须使用本项目真实任务集，公共 leaderboard 仅作外部参考；
- 组件若只提升解释而不提升业务指标，也可保留为解释工具，但不得伪装成策略增益。

### G6 Adopt

只有证据达到对应领域门槛才进入现役设计，并触发 plan-registry.md 的重大决策传播核对。

采用时必须保留：

- 为什么比当前方案好；
- 哪些场景不用它；
- rollback/fallback；
- 版本 pin 与复验触发器；
- 观察期指标。

## 7. 不同候选必须用不同证据

| 候选类型 | 最低验证重点 |
|---|---|
| AI 模型 / Jev 类 | 自有任务 gold/eval、grounding/错误型、token/延迟/失败率、隐私、fallback；公开榜单不直接准入 |
| Coding / Agent / Skill | 本仓真实任务、权限边界、工具选择、测试/CI、失败恢复；SWE-bench 仅作外部 sanity check |
| 量化策略 / 因子 | point-in-time、purged walk-forward/embargo、手续费/滑点/T+1/涨跌停/可成交性、样本数/置信区间、消融与市场状态 |
| 数据源 | 身份/单位/时间戳/修订语义、覆盖、失败/限流、许可、与现源独立性 |
| 开源依赖 | LICENSE、OpenSSF/安全公告、维护/归档、测试、发布节奏、供应链、替换成本 |
| 工程/性能 | 相同负载与覆盖、错误率、P95/P99、CPU/内存/IO/费用、回滚 |
| 产品/UX | 用户任务成功率、步骤/认知负担、错误恢复；不能靠增加前台配置换“能力更多” |

## 8. 节奏与触发器

不是“每天追热点”，而是多尺度：

- **每个重大设计/重构前**：做一次外部替代检查，确认是否已有明显更优做法；
- **每周 Scout**：轮换 2–3 个领域，低成本只做 DISCOVERED/SCREENED；
- **每月 Radar Review**：清理重复、检查 HOLD/RECHECK_TRIGGER、更新搜索词和来源覆盖；
- **事件触发**：重大模型/工具 release、依赖 breaking/security、A 股制度/接口变化、当前方案连续失败时立即重评；
- **采用后观察**：新组件在真实使用窗口继续比较；新鲜感消失后仍无净收益则降级/退出。

频率不能高于证据价值；昂贵调用、GPU、大规模回测只对通过前级门的少数候选开放。

## 9. 现有资产如何接入

- backend/scripts/repo_watch.py：Watch lane，只监控已知仓库变化；
- docs/repo-watch/：append-only Watch 报告；
- docs/kb/05-repo-tracker.md：GitHub/repo 候选经验与历史否证；
- docs/jev-integration.md：Jev 专项采用/否证的范例；
- docs/stages/*：真正实验/实施的唯一任务状态；
- docs/implementation-plan.md：只有重大长期取舍改变后才升级；
- docs/plan-registry.md：重大决策传播和历史取代关系。

后续 GOV-025 的执行重点是补 **Scout lane + 通用候选卡/去重/来源覆盖/回填**，不是重写 Watch。

## 10. 防“闭关”也防“追新”

必须同时满足：

1. **开放源**：不能只看 GitHub star，也不能只看已有供应商；
2. **搜索轮换**：领域、关键词、语言、来源定期变化；
3. **反例搜索**：主动找失败案例、issue、安全问题和反对证据；
4. **重评旧否决**：触发条件满足时允许推翻过去结论；
5. **最小替代对照**：新东西必须和最便宜的可行方案比较；
6. **不迷信榜单**：benchmark 只能证明 benchmark；本项目 own-task evidence 权重更高；
7. **不迷信新颖性**：能稳定解决真实问题的老方法优于漂亮 demo；
8. **不锁定当前计划**：v9.5 只是当前证据下的最佳基线；新证据可以修改、合并、废弃任何非红线设计；
9. **不自动扩权**：发现与评估可以高度自动化，生产准入、费用、凭据、重大权限和不可逆副作用仍走现有门禁。

## 11. 评估“Scout 自己”是否有价值

开放进化机制本身也必须接受淘汰：

- 每轮候选数、重复率、无消费者率；
- 从 SCREENED → TRIAL 的比例；
- 最终产生真实改进/否证知识的比例；
- 发现领先时间（是否在用户指出前就能发现重要变化）；
- 搜索/模型/token/人工审核成本；
- 错过的重要候选及为什么错过。

如果连续多轮只产生噪音，就收窄来源/频率；如果重大候选总靠用户提醒才发现，就扩大来源或修检索策略。不能因为“已经做了雷达”就宣布开放进化成功。

## 12. 外部方法参考

只吸收方法，不照搬平台：

- Thoughtworks Technology Radar：用 Adopt / Trial / Assess / Hold 的思想管理技术成熟度，而不是“发现即采用”；
- NIST AI RMF：用 Govern / Map / Measure / Manage 把风险治理和度量放在模型采用之前；
- OpenSSF Scorecard：对开源候选加入机器化供应链信号，但不把一个总分当唯一结论；
- lm-evaluation-harness / SWE-bench / MLPerf：强调代表性、可复现和任务相关的 benchmark；本项目仍以自己的目标域数据和业务验收为最终准入证据。

这些外部框架自身也只是参考候选；若未来出现更好的治理/评估方法，同样按本蓝图被挑战和替换。
