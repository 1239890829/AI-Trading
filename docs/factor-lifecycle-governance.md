# 因子全生命周期管理制度（Factor Lifecycle Governance）
> **同族文档（因子体系，2026-09-10 归口）**：建设方案 → `summary/factor-system.md`；候选登记册 → `factor-candidates.md`；IC 复核报告 → `summary/factor-system.md`。本文 = 全生命周期制度（**入口文档**）。

> 定位：在 `docs/summary/factor-system.md`（因子库建设方案，P0 评估闭环）之上，把「评估」扩展为**全生命周期闭环**：挖掘 → 筛选评估 → 入库登记 → 使用 → 出库 → 衰减监控与更新，六环联动，每一环有明确的存在价值与承接物。
> 配套代码资产：`backend/app/factors/library.py`（注册表=唯一口径锚）、`backend/app/factors/evaluate.py`（评估引擎）、`backend/app/factors/report.py`（评估报告运行时只读层）、`backend/scripts/run_factor_eval.py`（跑批 CLI）；候选登记册现为**纯文档** `docs/factor-candidates.md`（2026-09-08 起仅以文档形态维护）。
> 版本：v1（2026-09-07）。评估数据全部为 marketdb 10 年日 K 实测（1023.8 万行 / 5555 只 / 2016-09-05~2026-09-03），非推演。

## 0. 闭环总览

```
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│  ① 挖掘          ② 筛选评估         ③ 入库登记                     │
│  来源矩阵扫描  →  四维+一票否决   →  注册表登记（口径/场景/调用点）  │
│  候选登记册       事件因子通道       状态: observatory→active       │
│  ↑                                   ↓                             │
│  ⑥ 更新与再挖掘    ⑤ 出库            ④ 使用                        │
│  月度再评估       失效判定          唯一口径消费                    │
│  分年衰减对比  ←  观察名单  ←────  IC 滚动监控                      │
│  复活机制          deprecated        冗余族纪律                     │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

联动规则（不允许孤立设计）：
- ①的产出**必须**进候选登记册（candidates.py），带来源与数据可行性分级——没有登记的挖掘不算挖掘；
- ②的判定**只能**由 evaluate.py 产出（机器判定，禁止人工拍脑袋放行）——评估结果自动写入 eval_report.json；
- ③的登记**必须**带「适用场景+功能点+调用位置」，没有消费点的因子不得转 active（防囤积）；
- ④的使用**只能**引用注册表口径——消费方自算=口径漂移（涨停家数两口径的前科）；
- ⑤的出库**不删定义**：deprecated 保留 SQL 定义与历史评估（负 IC 亦是信息），仅停用消费；
- ⑥的再评估**回灌**②：月度全量评估的增量窗口结果直接驱动⑤的失效判定。

### 2.2 挖掘 SOP（四步，缺一不入候选池）

1. **提取原始定义**：公式 + 源码文件路径 + 原始注释语义（保留原仓命名，如 qlib KMID/CORD）；
2. **数据可行性分级**（复用 summary/factor-system.md §2 四层）：
   - A 层：marketdb 日 K 立即可算 → 进评估管线；
   - B 层：需已积累但未满 60 日的序列（板块资金/情绪/热度）→ 候选池挂「积累中」；
   - C 层：需外部数据（财报/换手率/行业）→ 候选池挂「数据缺口」+ 指名数据源；
   - D 层：盘中瞬态 → 候选池挂「待落库」；
3. **去重预判**：与注册表现有因子同信源 → 标注（评估时用 IC 相关实证，预判≠结论）；
4. **登记**：写入 `candidates.py`（schema 见 §2.3）。

## 3. 环节②：筛选与评估（Evaluate）

### 3.1 准入标准（evaluate.py 代码级，四维 + 一票否决）

沿用 summary/factor-system.md §4（本制度不重复展开）：
有效性（|IC|≥0.02 且 |ICIR|≥0.30）/ 稳定性（分年同号 ≥60%）/ 分层单调（多空年化 ≥3% 同号且 ≥3/4 单调对）/ 覆盖率 ≥90%；一票否决：未来函数、幸存者偏差未标注、口径不可复现。
三层判定（三态纪律）：**PASS 入库 / CONDITIONAL 辅助维度 / FAIL 淘汰留档**。
去重：与已入库因子主窗 IC 序列 |corr| ≥ 0.70 标 redundant，同族按 |ICIR| 择优。

**「多空年化」的量纲（R17 修正，2026-09-14）**——该量的口径曾是错的，改动后判定会自然变严：

| 量 | 定义 | 字段 |
|---|---|---|
| **期间收益** | T+1 收盘 → T+h 收盘，持有 **h−1 个交易日**（**不是**日收益） | `q_avg_period` / `long_short_period` |
| 日均近似 | 期间收益 ÷ (h−1) | `q_avg_daily_approx` |
| **简单线性年化** | 期间收益 × 243/(h−1)，**近似** | `q_avg_ann_simple_pct` / `long_short_ann_pct` |
| 可实现组合年化 | 须来自逐日建仓/持仓净值曲线 | `implementable_annual_return_pct`（**恒 None**，三态未判定） |

- **旧口径**：把期间收益当日收益直接 ×243（19 日持有期高估 **19 倍**）。实测：某因子 19 日期间
  多空 **−4.31%** 被报成 **−1048% 年化**；修正后约 **−55%**，而报告里的 −268% / −239% / −151%
  这类值应整体缩小 **19 倍**（主窗 20 日）。审查原文用例：期间 2% ⇒ 旧报 486%、正确 ≈ 25.58%。
- **阈值不变、判定变严**：`LS_ANN_MIN = 3%` 字面不变，但分母修正后凡真实多空年化 <3% 的因子
  会从「过线」变「未过线」⇒ **这是修正的预期后果，不是回归**。
- **重叠持有声明**：样本内每日都在建仓，同一时刻存在 h−1 个未平仓批次 ⇒ 该缩放值
  **不是可实现的年化收益**，只用于跨窗口量纲可比；不得写进对外结论（REPORT 必须带
  `annualization.method=simple_linear` + `approximation=true` + `implementable=false`）。
- **年度多空**：`yearly_ls_*` = **同年 Q5 − Q1**（旧实现只取 Q5、不减 Q1——那仍是含市场 beta
  的绝对收益）；某年缺 Q1 或 Q5 时该年不产出（三态，不凑 0）。
- **口径变更留痕**：报告带 `algo_version`；重算时旧结论保留为各因子的 `verdict_prev`，
  翻转项标 `recheck=pending` 并汇总进顶层 `recheck`——**修复不静默把「通过」改成「失败」**。

### 3.2 防泄露纪律（不可妥协项）

signal at T 收盘 → entry T+1 收盘（保守执行口径）→ exit T+h；T+1 一字板剔除；每日截面 <30 只不计；次新 cnt<min_bars 不计；缺失一律 NULL 三态。幸存者偏差与无 ST 过滤的已知局限随报告标注（DATA_QUALITY_NOTES）。

### 3.4 事件因子通道（新增，Sequoia 系策略的评估口径）

0/1 事件因子（涨停洗盘/高紧旗形/海龟突破等）**不走 RankIC**（截面连续值假设不成立），改走事件研究法（`picks/backtest.py` 既有范式）：触发日 vs 全市场基线的前瞻收益差 + 样本 ≥120 触发 + walk-forward 多窗。
本通道 **P1 尚未落地**（截至 2026-09-12 实测无实现：`app/factors/` 下只有注册表 / 评估引擎 / 评估报告三件）；候选登记册已收录 Sequoia 6 策略原始规则（tier=C：需涨停家数/连板数据联判，且事件稀疏需长窗口），待通道就绪后按上述事件研究法批量评。**待办出口**：`docs/retro-and-gaps.md` §6.2 P1-42。

### 3.5 样本内外纪律

- 全期评估报告为**样本内**（in-sample）结论；入库后**前 60 交易日为观察期**（observatory 状态），期间 IC 滚动表现即准样本外（out-of-sample）证据；
- 观察期满 IC 与入库评估同向 → 转 active；反向 → 回候选池复评（§6）。

### 3.6 窗口敏感性扫描（同算子 × 5/10/20/30/60，2026-09-14 实测）

**动机**：§3.1 的准入只看**单一生产窗**（现役多为 20 日、`atr` 为 14 日）⇒ 无法区分「**本质有效**」与「**窗选得巧**」。`mom` 族早有反例（同算子仅换窗：`mom5` FAIL → `mom10` CONDITIONAL → `mom20` PASS → `mom60` PASS → `mom120` FAIL）。

**方法**：`backend/scripts/verify_window_sensitivity.py`。**零 SQL 复制**——把生产 `_base_cte` 的 frame 与守卫**定点参数化**（列名保持不变，`amt20_cur`/`vola20_w` 里的 `20` 只是历史命名 ⇒ 21 条生产 `FactorDef.expr` **逐字复用**），IC 管线与聚合直接复用生产 `_base_sql` / `_agg_window`。**双自证**：① 结构——生产窗下生成的 IC SQL 与生产 `_base_sql` 尾段**逐字相同（21/21）**；② 保真——抽样实跑 3/3 等价（`liq`/`corr_pv`/`atr`，`|Δ|≤1e-9`）。**外部交叉校验**：w=20 处与磁盘生产报告 `eval_report.json` **ΔICIR ≤ 0.003**、`best_horizon` **20/20 一致**、判定无一矛盾。

**结果（21 算子 × 5 窗 = 105 格；2016-09-05~2026-09-11 / 2433 交易日 / 1027 万行）**：

| 类别 | 数量 | 算子 | 含义 |
|---|---|---|---|
| 全窗稳健 | 7 | `liq` `vola` `range` `std` `atr` `corr_pv` `cord` | 5 窗全部至少 CONDITIONAL ⇒ PASS **非窗过拟合** |
| 存在失败窗 | 10 | `amihud` `beta` `resi` `bias` `imax` `cntp` `sump` `vma` `vstd` `vsumd` | 生产窗结论**不可外推**到其他窗 |
| 全窗失败 | 4 | `rsqr` `rsv` `max` `wvma` | 与既有报告一致，判死 |

39/105 FAIL 格**全部挂在「有效性」层**（仅 3 格另挂稳定性）。

**「20 日」不是普遍最优窗——四类形态均有实例**：

| 形态 | 实例（ICIR，括号为因子窗） |
|---|---|
| 短窗更强 | `liq` **0.667**(w5) → 0.498(w60) |
| 长窗更强 | `bias` 0.234(w5) → **0.438**(w60)；`vma` 0.202 → **0.487**；`vsumd` 0.278 → **0.601** |
| 中间窗最优（两端衰减） | `cord` **0.731**(w20) / **0.732**(w30)；`corr_pv` 峰在 w10（0.849） |
| **非单调 · 生产窗恰为谷底** | `vstd` 0.340(w5) · 0.278(w10) · **0.054(w20)** · 0.146(w30) · 0.301(w60) |

**本轮确立的纪律**：

1. **单一窗 PASS ≠ 稳健**：实测 **9/21** 存在「生产窗过线、其他窗失败」⇒ 因子结论须**限定窗口**表述，不得写成无窗限定的「该因子有效」。
2. **7 个全窗稳健算子可直接沿用其生产窗**；其余因子**不可**把生产窗的结论外推。
3. **跨窗样本池不同且是必然的**：`min_bars = w + 1` 保证满窗 ⇒ 大窗会剔除历史不足的样本。只可比各窗的**判定与 ICIR 量级**，**不可把跨窗 IC 差直接归因于窗口本身**。
4. **本扫描不含五分位分层** ⇒ `至少CONDITIONAL` 是**上界**结论，完整 verdict 仍以 `run_full_eval` 为准。

**派生待批（只提不做，见账本 §6.0 B 档）**：`RSH-023`（`resi`/`vstd` 生产窗复评——`resi` w20 FAIL 而 w60 过线、`vstd` w20 恰为谷底）、`GOV-011`（准入增加「窗口稳健性」维度）。

## 5. 环节④：使用（Consume）

### 5.1 调用规则

1. **唯一口径**：消费方一律引用 library.py 定义（P1 起 factor_values 落库后读库；P1 前仅允许通过 evaluate 的 base SQL 片段复算）——禁止消费方自写公式（口径漂移禁令）；
2. **CONDITIONAL 限制**：仅可作辅助维度（tech_score 次要权重/复盘归因），不得单独构成买卖依据；
3. **deprecated 因子**：消费方在读取时校验状态（P1 factor_values 落库后由 verdict 列驱动），不得继续计权；
4. **方向纪律**：负 IC 因子以「取反方向」参与多头侧（低波/低拥挤/弱动量组=多头），note 中的预期方向仅供参考，判定以实测 IC 为准。

### 5.2 消费接入时点（P1，依赖 factor_values 落库）

tech_score v4（权重 IC 校准，SCORER_VERSION 递增）→ regime 条件化（情绪相位 × 因子暴露，`picks/regime.py` 先例）→ 复盘归因（当日涨跌的因子暴露分解）→ 告警（amihud 异常升高=流动性恶化）→ 助手工具 factor_profile。

## 6. 环节⑤：出库（Delist）

### 6.1 失效判定（量化触发，月度评估自动计算）

| 触发条件（满足其一） | 动作 |
|---|---|
| 滚动近 250 交易日 IC 与入库符号相反且 |IC|≥0.02（系统性反向） | 立即 deprecated（符号翻转是结构性失效，不是噪声） |
| 滚动近 250 日 \|IC\| < 0.01（信号消失） | 进观察名单（observation） |
| 观察名单持续 2 个评估周期（~2 月）未恢复过线 | deprecated |
| 数据源变更导致口径不可复现 | 立即 deprecated + 登记原因 |

### 6.2 出库 ≠ 删除

- deprecated 因子保留全部资产：SQL 定义、历史评估报告、消费史——负 IC 亦是信息（mom5 的留档结论「5 日反转不稳定」直接指导了 P1 短窗口策略设计）；
- 消费方自动停用（P1 靠 verdict 列，过渡期人工核对月度报告）；
- 出库记录进本文件 §7.2 的版本日志。

### 6.3 复活机制

deprecated 因子满足：新数据窗口重新跑全量评估 → 四维全过 + 与现役因子去重通过 → 可回 active（走一遍③的登记更新）。观察名单因子同理。
