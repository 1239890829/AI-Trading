# 因子全生命周期管理制度（Factor Lifecycle Governance）
> **同族文档（因子体系，2026-09-10 归口）**：建设方案 → `summary/factor-system.md`；候选登记册 → `factor-candidates.md`；IC 复核报告 → `summary/factor-system.md`。本文 = 全生命周期制度（**入口文档**）。

> 定位：在 `docs/summary/factor-system.md`（因子库建设方案，P0 评估闭环）之上，把「评估」扩展为**全生命周期闭环**：挖掘 → 筛选评估 → 入库登记 → 使用 → 出库 → 衰减监控与更新，六环联动，每一环有明确的存在价值与承接物。
> 配套代码资产：`backend/app/factors/library.py`（注册表=唯一口径锚）、`backend/app/factors/evaluate.py`（评估引擎）、`backend/app/factors/candidates.py`（候选登记册）、`backend/scripts/run_factor_eval.py`（跑批 CLI）。
> 版本：v1（2026-09-07）。评估数据全部为 marketdb 10 年日 K 实测（1023.8 万行 / 5555 只 / 2016-09-05~2026-09-03），非推演。

## 0. 闭环总览

```
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│  ① 挖掘          ② 筛选评估         ③ 入库登记                     │
│  来源矩阵扫描  →  四维+一票否决   →  注册表登记（口径/场景/调用点）  │
│  候选登记册       事件因子通道       状态: observatory→active       │
│  ↑                                   ↓                             │
│  ⑥ 更新与再挖掘    ⑤ 出库            ④ 使用                        │
│  月度再评估       失效判定          唯一口径消费                    │
│  分年衰减对比  ←  观察名单  ←────  IC 滚动监控                      │
│  复活机制          deprecated        冗余族纪律                     │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

联动规则（不允许孤立设计）：
- ①的产出**必须**进候选登记册（candidates.py），带来源与数据可行性分级——没有登记的挖掘不算挖掘；
- ②的判定**只能**由 evaluate.py 产出（机器判定，禁止人工拍脑袋放行）——评估结果自动写入 eval_report.json；
- ③的登记**必须**带「适用场景+功能点+调用位置」，没有消费点的因子不得转 active（防囤积）；
- ④的使用**只能**引用注册表口径——消费方自算=口径漂移（涨停家数两口径的前科）；
- ⑤的出库**不删定义**：deprecated 保留 SQL 定义与历史评估（负 IC 亦是信息），仅停用消费；
- ⑥的再评估**回灌**②：月度全量评估的增量窗口结果直接驱动⑤的失效判定。

### 2.2 挖掘 SOP（四步，缺一不入候选池）

1. **提取原始定义**：公式 + 源码文件路径 + 原始注释语义（保留原仓命名，如 qlib KMID/CORD）；
2. **数据可行性分级**（复用 summary/factor-system.md §2 四层）：
   - A 层：marketdb 日 K 立即可算 → 进评估管线；
   - B 层：需已积累但未满 60 日的序列（板块资金/情绪/热度）→ 候选池挂「积累中」；
   - C 层：需外部数据（财报/换手率/行业）→ 候选池挂「数据缺口」+ 指名数据源；
   - D 层：盘中瞬态 → 候选池挂「待落库」；
3. **去重预判**：与注册表现有因子同信源 → 标注（评估时用 IC 相关实证，预判≠结论）；
4. **登记**：写入 `candidates.py`（schema 见 §2.3）。

### 2.3 候选登记册 schema（candidates.py）

```python
CandidateDef(
    name="cord20",                    # 统一命名（库内唯一）
    source="qlib://contrib/data/loader.py#CORD",   # 来源+代码位置
    raw_expr="Corr($close/Ref($close,1), Log($volume/Ref($volume,1)+1), 20)",
    category="volume_price",
    tier="A",                         # A 可立即评 / B 积累中 / C 缺数据 / D 待落库
    data_dep="",                      # C/B 层必填：缺什么数据、指名来源
    dedup_hint="mom20/amt_ratio",     # 同信源预判（实证以 IC 相关为准）
    status="evaluated",               # mined→evaluated→(promoted|rejected|parked)
    verdict_note="",                  # 评估结论摘录（PASS 时引用 eval_report）
)
```

### 2.4 持续产生新因子的途径（管线化，非一次性）

1. **完整化既有来源**：qlib Alpha158 逐算子补全窗口（本轮评 20 日代表窗，P1 补 5/10/60 日扫描）；TA-Lib 指标族中 MFI/OBV/ADX/CCI 等待 P1；
2. **系统内准因子收敛**（summary/factor-system.md §1.2 的 11 处）到期逐个转正：board_flow streak（B 层 60 日倒计时）、竞价溢价（D 层）；
3. **LLM 挖掘管线**（P2，参考 finhack alphaEngine / QuantMind×RD-Agent 集成）：表达式空间生成 → 批量过 evaluate → 人审入库。前提：factor_values 每日截面落库（P1）；
4. **数据源扩容解锁**（C 层因子解锁钥匙）：财报数据（HiThink Financial-API 官方已有 → 解锁 PEAD/Graham 族）、流通股本（解锁真换手率）、行业分类（解锁行业中性化）。

## 3. 环节②：筛选与评估（Evaluate）

### 3.1 准入标准（evaluate.py 代码级，四维 + 一票否决）

沿用 summary/factor-system.md §4（本制度不重复展开）：
有效性（|IC|≥0.02 且 |ICIR|≥0.30）/ 稳定性（分年同号 ≥60%）/ 分层单调（多空年化 ≥3% 同号且 ≥3/4 单调对）/ 覆盖率 ≥90%；一票否决：未来函数、幸存者偏差未标注、口径不可复现。
三层判定（三态纪律）：**PASS 入库 / CONDITIONAL 辅助维度 / FAIL 淘汰留档**。
去重：与已入库因子主窗 IC 序列 |corr| ≥ 0.70 标 redundant，同族按 |ICIR| 择优。

### 3.2 防泄露纪律（不可妥协项）

signal at T 收盘 → entry T+1 收盘（保守执行口径）→ exit T+h；T+1 一字板剔除；每日截面 <30 只不计；次新 cnt<min_bars 不计；缺失一律 NULL 三态。幸存者偏差与无 ST 过滤的已知局限随报告标注（DATA_QUALITY_NOTES）。

5. **滚动 250 日监控基线（37 因子）**：全部 sign_flip=False（无结构性失效）；衰减最明显的是 amihud20（全期 +0.054 → 滚动 +0.021，仍过线但接近临界）与 liq20（-0.091 → -0.052）——流动性溢价的近年弱化与 A 股量化资金扩容的时点吻合，P1 月度评估重点跟踪这两个。

### 3.4 事件因子通道（新增，Sequoia 系策略的评估口径）

0/1 事件因子（涨停洗盘/高紧旗形/海龟突破等）**不走 RankIC**（截面连续值假设不成立），改走事件研究法（`picks/backtest.py` 既有范式）：触发日 vs 全市场基线的前瞻收益差 + 样本 ≥120 触发 + walk-forward 多窗。
本通道 P1 落地 `app/factors/evaluate_event.py`；候选登记册已收录 Sequoia 6 策略原始规则（tier=C：需涨停家数/连板数据联判，且事件稀疏需长窗口）。

### 3.5 样本内外纪律

- 全期评估报告为**样本内**（in-sample）结论；入库后**前 60 交易日为观察期**（observatory 状态），期间 IC 滚动表现即准样本外（out-of-sample）证据；
- 观察期满 IC 与入库评估同向 → 转 active；反向 → 回候选池复评（§6）。

| klen/kup/klow/vma20/vsumd20 | conditional(本轮) | 辅助维度 | 仅复盘归因/次级确认，不得单独决策 | `library.py`（verdict=CONDITIONAL 约束消费） |
| rsqr20 | 观察名单(本轮) | — | FAIL 但滚动 IC 增强（0.018→0.048），月度评估跟踪 | `library.py`（观察期无消费） |
| amihud20 衰减 | active+关注 | — | 滚动 250 日 +0.054→+0.021 临界，月度评估第一优先复核 | `evaluate.py` rolling 字段 |

### 4.3 冗余族纪律

同信源族（实测 IC 相关 ≥0.70）内按 |ICIR| 择优一个为**代表因子**进消费；族内其他 PASS 因子保留登记（数据异常时可替换）但不重复计权。当前族结构：动量族（mom20 主）、流动性族（liq20 主）、波动族（vola20 主）——新 PASS 因子入族时更新此结构。

## 5. 环节④：使用（Consume）

### 5.1 调用规则

1. **唯一口径**：消费方一律引用 library.py 定义（P1 起 factor_values 落库后读库；P1 前仅允许通过 evaluate 的 base SQL 片段复算）——禁止消费方自写公式（口径漂移禁令）；
2. **CONDITIONAL 限制**：仅可作辅助维度（tech_score 次要权重/复盘归因），不得单独构成买卖依据；
3. **deprecated 因子**：消费方在读取时校验状态（P1 factor_values 落库后由 verdict 列驱动），不得继续计权；
4. **方向纪律**：负 IC 因子以「取反方向」参与多头侧（低波/低拥挤/弱动量组=多头），note 中的预期方向仅供参考，判定以实测 IC 为准。

### 5.2 消费接入时点（P1，依赖 factor_values 落库）

tech_score v4（权重 IC 校准，SCORER_VERSION 递增）→ regime 条件化（情绪相位 × 因子暴露，`picks/regime.py` 先例）→ 复盘归因（当日涨跌的因子暴露分解）→ 告警（amihud 异常升高=流动性恶化）→ 助手工具 factor_profile。

## 6. 环节⑤：出库（Delist）

### 6.1 失效判定（量化触发，月度评估自动计算）

| 触发条件（满足其一） | 动作 |
|---|---|
| 滚动近 250 交易日 IC 与入库符号相反且 |IC|≥0.02（系统性反向） | 立即 deprecated（符号翻转是结构性失效，不是噪声） |
| 滚动近 250 日 \|IC\| < 0.01（信号消失） | 进观察名单（observation） |
| 观察名单持续 2 个评估周期（~2 月）未恢复过线 | deprecated |
| 数据源变更导致口径不可复现 | 立即 deprecated + 登记原因 |

### 6.2 出库 ≠ 删除

- deprecated 因子保留全部资产：SQL 定义、历史评估报告、消费史——负 IC 亦是信息（mom5 的留档结论「5 日反转不稳定」直接指导了 P1 短窗口策略设计）；
- 消费方自动停用（P1 靠 verdict 列，过渡期人工核对月度报告）；
- 出库记录进本文件 §7.2 的版本日志。

### 6.3 复活机制

deprecated 因子满足：新数据窗口重新跑全量评估 → 四维全过 + 与现役因子去重通过 → 可回 active（走一遍③的登记更新）。观察名单因子同理。

## 7. 环节⑥：衰减监控与更新（Monitor & Refresh）

### 7.1 衰减规律分析（2026-09-07 滚动 250 日实测基线）

分年 IC（yearly_ic，11 个年度切片）+ 滚动 250 日 IC（rolling 字段）已内建于评估报告：
- **37 因子滚动 250 日 sign_flip 全部 False**（无因子系统性反向）——当前无出库触发项；
- **衰减最明显的两个**：amihud20（全期 +0.054 → 滚动 +0.021，降幅 61%，接近 0.02 有效线临界）与 liq20（-0.091 → -0.052）——流动性溢价的近年弱化，推测与 A 股量化资金扩容、微结构效率提升有关（推测仅作假设，以月度滚动数据实证）；P1 月度评估重点跟踪；
- **增强的两个**：mom60（-0.059 → -0.076）与 rsqr20（+0.018 → +0.048，FAIL 因子的滚动增强，进观察名单）；
- **第一批 PASS 因子分年同号率 0.9~1.0**：反转/低波/流动性三效应 2024-2026 仍在——但幸存者偏差使全期多头端高估，分年结论以近 3 年更可信（DATA_QUALITY_NOTES 已固化进每份报告）。

### 7.2 再评估机制（定期，制度核心）
