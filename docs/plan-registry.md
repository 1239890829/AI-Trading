### 1.1 重大决策传播契约（防遗漏）

新模型、工具链、架构、产品语义、协作机制或治理规则进入项目时，不能只更新“最直接”的专题文档。先判断变化属于哪一类，再完成对应传播面；**没有完成传播核对的重大决策，不视为文档闭环**。

| 变化类型 | 必须核对的权威面 | 只有在受影响时更新 |
|---|---|---|
| 架构 / 模型 / AI工具链 | `implementation-plan.md`、本表、唯一专题蓝图、`docs/INDEX.md`、所属 stage | `AGENTS.md`、协作 Skills、`handoff.md`、仍声称描述“当前架构”的 summary |
| 产品 / 交易 / 研究语义 | 产品/猎场/历史涨停研究/细功能权威文档、所属 stage；若改变长期取舍则同步 implementation-plan | handoff、AGENTS、相关专题/summary |
| 协作 / 权限 / 发布 / 治理 | `collaboration-workflow.md`、`AGENTS.md`、相关 Skills、本表、W08；若改变当前现场则同步 handoff | implementation-plan、INDEX、专题治理文档 |
| 仅当前执行状态 | stage + handoff | 不为状态快照改写长期方案 |
| 历史证据 / 旧基线 | 原历史载体保持原文，本表写清被何种新规则覆盖 | INDEX/summary 仅补“当前去哪里读”，不篡改历史证据 |

每次重大决策的交付说明必须包含“传播核对”：列出上述权威面中**已更新**与**不适用（含理由）**的项目。不得以“专题文档已经写了”代替总方案、索引、任务归属或接手入口的同步；也不得为了形式一致批量改写历史基线。

机器守卫只负责能机械判定的根入口一致性（版本指针、专题蓝图可达、Skill读取链、退役分支/旧模式不能复活）；语义影响面仍由网页规划审核按本节逐项判断。发现漏传判定为治理缺陷，优先修传播链并补回归，而不是只补漏掉的那一个文件。

### 1.3 文档自治治理契约

每类权威载体必须有自己的治理逻辑，不能靠“大家都写一点”维持一致：

| 载体 | 新内容如何进入 | 如何变更 | 如何退出/归档 | 机器/人工守卫 |
|---|---|---|---|---|
| `implementation-plan.md` | 只有新需求、长期取舍或治理原则变化才升级版本/U编号 | 明确旧→新取代关系并做 §1.1 传播 | 不删除历史版本事实，Git恢复 | 版本传播 + 网页语义审核 |
| `retro-and-gaps.md` | 新 W 领域、G 阶段门或任务调度规则先在此定义 | 改门序/算法必须同步 Skills、stage、handoff 和守卫 | 不保存逐轮日志/业务设计 | doc-health 阶段门守卫 |
| `docs/stages/*` | 新任务先去重，再登记 W归属/G门/顺位/角色/硬依赖/效果前置 | 状态或门禁元数据变化必须有证据；不得为方便施工降门 | 完成/退出/合并保留 ID 与证据/去向 | Q/S 守卫 + 网页审核 |
| `handoff.md` | 只记录当前候选版本、主门、主切片、阻塞与一次性例外 | 每轮交接原位覆盖当前现场 | 历史从 Git/PR 恢复，不累积日志 | 禁任务副本 + 版本/范围守卫 |
| `INDEX.md` | 新文档先分配唯一编号、层/领域/用途 | 路由变化同步主题入口 | 删除先迁移独有知识并标退役 | 编目双向闭包 |
| 专题蓝图/方法论 | 只拥有本领域设计、假设、边界和验收方法 | 新证据局部修订，不复制任务状态 | 被取代时在 plan-registry 写去向 | 死链/当前指针 + 网页语义审核 |
| `summary/*` | 只提炼稳定知识和当前权威指针 | 当前指针随重大决策传播，历史数字保留口径 | 不成为活计划/活账本 | 当前方案指针守卫 |
| KB/因子/策略登记 | 来源、定义、适用域、负结果与生命周期证据齐备才进入 | 版本化、保留反证和重开条件 | 归档/否决不抹证据 | 对应 lifecycle + KB/doc-health |
| Skills | 只把已在总方案/总账批准的规则变成可执行读取/交接协议 | 政策先改权威文档，再改 Skill；Skill 不得领先创造项目政策 | 退役需移出活动入口并保留恢复 | 读取链/退役入口守卫 |

任何文档发现自己正在维护“不属于自己”的状态、优先级或规则，默认动作是**迁回拥有者并留指针**，不是复制同步。这样文档闭环依靠所有权和守卫，而不是人工记忆。

本机/忽略资产同样只设一个生命周期拥有者：W08/GOV-026。`doc-health` 只检查 Git/文档面，不因看不见主机临时目录就宣称工作区干净；临时 clone/worktree、测试沙箱、缓存、artifacts/recovery 的分类、保留条件与安全清理由 workspace hygiene gate 负责。跨项目/未知所有权和业务数据不进入自动删除面。

### 1.2 Living Plan 与开放世界重评

“当前方案”表示当前证据下的首选，不表示永久最终答案。外部创新与反证的现役入口为 [开放世界持续演进蓝图](ai/continuous-evolution.md)：雷达可持续发现模型、工具、量化方法、数据源、工程和产品替代，但候选状态不构成施工授权，也不在本文维护第二套 backlog。

外部候选只有在改变长期设计时才触发 §1.1 传播；未过 E3/E4 的候选留 WATCH/LAB，不修改总方案。既有决定如果关键前提失效、出现稳定反例、外部有同条件可复现实证或维护/成本结构显著变化，允许重新打开；拒绝/观察项须保留可核重开条件，避免“曾拒绝一次 = 永久封禁”。
