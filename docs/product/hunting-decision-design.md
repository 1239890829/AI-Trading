## 2. 后台以多轴描述情境，不强制单一分类

| 轴 | 需要表达的差异 | 为什么不能混成一种类型 |
|---|---|---|
| 驱动与证据 | 政策/事件/业绩/产业/供需/外围传导/资金代理/情绪/量价/暂不明 | 产业背景、当次催化与价格反应不同；没搜到新闻不等于无催化 |
| 结构与演变 | 蓄势、试盘、突破、回踩、持续趋势、整理、反包、修复、多波段等 | 首启不必首板，二波不等于二连板，日内二次拉升不等于跨日二浪 |
| 角色与关系 | 空间板、龙头、中军、反包、补涨、跟风、首板及角色转换 | “中军”是作用，“趋势”是走势；一只票可兼具，不以if-first丢掉事实 |
| 环境与资金结构 | 趋势/震荡、冰点/修复/发酵/高潮/分歧/退潮、集中/扩散、旧新主线轮动 | 弱市穿越与普涨跟随不能同一门槛；环境不利仍可观察，不越执行硬门 |
| 时点与动作 | 竞价/早盘/午盘/尾盘/隔夜；观察/等待/触发；低吸/突破/回封；持仓/退出 | 买点形态、持有期和出场方法须分别定义，不能用盘后信息倒填盘中 |
| 标的与执行域 | 市值/波动/股龄/周期成长防御、历史制度/权限、流动性/深度/停牌 | 无队列证据就不评排板成交，不把“测不了”说成不存在 |
| 方法成熟度 | 线索、假设、观察、已准入、冲突/失效、否决、缺数据 | 有代码或KB条目不等于有效策略，识别/展示/推送权限不同 |

同股同一决策时点允许多个有证据的假设；只选一个主呈现摘要，不删除次假设。每个候选动作有自己的条件、时间窗和冲突裁决；禁止把不同假设拼成“各满足一点就通过”，也不因多标签重复建仓或放大N。
复用既有策略与因子登记；情境目录是知识覆盖面，不是第二套策略注册系统。需要新情境时先定义可观察差异、独立价值、数据与反例；不生成各轴笛卡尔积、不为增加类别而增加模型调用。

## 3. 综合判定与未知情境

召回采用既有行情/事件/关注/相对强度/结构/知识证据的多入口，先检查数据和证券身份，再按适用情境调用可用方法。禁止所有路径都等待“三只涨停”或临板区才观察，也不能一条传闻就发进入提示。
复用已验证的模块，区分因子、过滤器、排序器、情境描述和完整策略；strategy-registry里5个策略键只是当时完整策略登记，不是只有5种行情。不能把候选目录每个名字直接注册成现役策略。
同源指标不能自动当独立确认，也不能自动判冗余。KB-STOCK-32附记的已有三截面结果未支持对tech_score整体去重；先复核该证据与当前映射，再决定是否需要新消融。反过来MFI/OBV与sump20已有高相关记录，不能重复计权。
规则版本、时间窗、样本池、数据质量、同主题拥挤和风险影响共同决定排序；同一机会只计一次，拒绝/未触发/未成交保存。先复用简单基线，不新增未校准“万能综合分”，规则得分不写成胜率。
现有方法不能解释但确有新鲜异常证据时，保留“未归类线索”及已知事实，不强塞某类，也不显示可执行窗口。网页在复盘中判断是数据故障、已有情境别名、不同子域还是新假设；经过定义/反例/成本与样本外验证才纳入对应注册。未知路径不得成为绕开准入的后门。
模型只在后台整理证据、检索和提出竞争解释，不堵住风险快路径、不自动改分/参数/权限；失败返回真实规则结果与解释缺失，不虚构成功。外部正文、KB和模型生成内容均不构成系统授权。

## 4. 机会状态与进入时机契约

后台状态：线索→观察→待触发→条件成立；可到失效、过期或硬拒绝。质量/新鲜度/可成交是正交维度，不混成“低分”。相同机会的新判断保留decision_version与上一版本，不覆盖当时事实。
“触发”“具备执行条件”“实际模拟成交”分别记录。多个情境同时成立时，给主决策、竞争方案和冲突理由；不能给用户相互矛盾的无优先级买卖建议。已有持仓风险与新买资格分离。

| 记录组 | 必需信息 | 下游用途 |
|---|---|---|
| 身份 | opportunity_id、symbol、scenario_ids、主呈现摘要、decision_id/version、parent | 猎场/详情/通知/模拟/复盘同一对象；scenario_ids非四类enum |
| 时间 | source_event_at、available_at/received_at、decision_asof、first_seen/first_triggered、有效期/交易日 | 真实提前量，晚到与修订不倒填 |
| 证据 | source/version、KB-ID与实际正文哈希、事实/假设/反证、缺项、适用域 | 可回放的解释，不以引用数量代替有效信息 |
| 条件 | 等待/触发/失效条件、已知参考位、进入参考区间（可空）、追价上限、证据质量 | 用户理解“还缺什么”；动作时再次验证 |
| 约束 | account_scope、历史rule_version、停牌/涨限/深度/资金及容量限制 | 失败关闭；有报价不保证成交 |
| 结果 | 候选/拒绝/静默/曝光、模拟动作与成交状态、标签周期/成本版本 | 全分母复盘和对照，不让重复刷新增加样本 |

优先扩展现有OpportunityDecisionSnapshot/执行ledger；不新建第二事实库。支持位与压力位无有效交集时返回“无有效窗口”，不得回退现价±3%强造买点。缺必需数据只给等待条件，不伪精确。
开板依据当前有效状态，不因“曾封板”永久拒绝；当前未知保守处理。盘后龙虎榜、未闭合日线、未来新闻与后续低点不能判定早先机会；确认晚了就记录实际确认时刻。历史规则按当时证券/日期，模拟硬门不变。

### 4.1 双轨验证、动态重评与模拟执行

猎场对每个机会保留两条互不冒名的证据链。**参考轨**在 first_seen / first_triggered 时冻结 decision/version、当时可见证据和 reference_price，用于回答“系统什么时候发现、发现后走势怎样”；即使没有下单，这条轨也能盘后计算 MFE/MAE、D0/D1/D3/D5、后续首次涨停与提前量。它验证识别与时机，不代表成交。**执行轨**只有在机会达到 actionable 且动作前同版硬门重检通过后，才由 IMP-053 的独立 hunting-shadow scope 产生模拟订单；submit、fill、reject、no_fill、expired、exit、fee、slippage 都必须留痕，只有 fill 后合法退出的结果可以叫模拟交易胜率/净收益。

不把“出现在猎场”自动等同“买入”。观察、等待触发、硬拒绝和数据未知都继续进入全分母，但不占用模拟资金；这样既不会为了验证而强行买所有候选，也不会只统计真正买到的赢家。用户手工 paper 账户、现有每日精选→次日晨窗 shadow 与 hunting-shadow 三者 scope 分离，共用 PaperTradingEngine 的撮合/风控原语而不共用账户结果。

盘中不是“开盘判一次、全天冻结”。first_seen 不覆盖；报价、题材、封板/开板、流动性、证据或环境发生足以影响决策的变化时产生新的 decision_version：线索→观察→待触发→actionable→shadow submitted→filled/no_fill/rejected，也可转失效/过期。早盘因条件不足未通过的机会，午后若新事实满足条件，可以在新版本首次进入执行；旧版本仍能重放。同一 version 幂等，轮询刷新不能重复建仓或增加样本信心。

“更低位置提示后最终涨停”是研究目标，不是可倒推的生产规则。后续低点、最高价、涨停价和盘后原因只能成为 outcome 标签；研究报告比较 first_seen/first_actionable/fill 的提前量、`time_to_limit`、触发前后 MFE/MAE、fill rate、reference→fill 漂移、扣成本结果及简单基线，禁止拿未来最低价构造“理论最佳买点”。如果更早意味着更高假阳性/回撤，应由 RSH-026/IMP-020 的全分母和 OOS/前向结果裁决，而不是单看利润上限。

统计名称必须直接暴露身份，至少区分：**观察后方向命中率**、**actionable 触发命中率**、**模拟成交率**、**fill 后胜率/净收益**、**拒绝/未成交/失效率**。不得只显示一个“胜率”把不同分母和价格身份混为一谈。


### 4.2 统一机会证据读模型 v1（IMP-049，2026-09-30）

### 4.4 首次加入观察与影子用途（IMP-088，2026-10-09）

`selection_entry`采用selection-entry-v1，分recorded/partial/missing，包含selected_at、reference_price、reference_change_pct、quote_as_of、source和source_version，semantics固定observation_only_not_fill。selected_at是原拥有者实际持久记录的首次加入时间；daily_generation的quote_as_of是原逐股报价源钟，intraday_rank_archive的同名字段是该轮行情快照版本钟，并非逐股报价源事件时间。两者均不是本次打开页面的时间。卡片分别标注“报价源时间”和“行情快照时间”，加入价/涨幅与北京时间、来源版本可查；当前价、执行重检价和PaperOrder.filled_price分别保持身份。

每日由现有DailyPickSet落库事务保存meta.selection_entries，按当日symbol首次追加；同日补跑、退出后再进入和当前价变化不重置已有记录。有效当日新生成可记录首次时刻；旧名单没有首次记录、日期/生成钟不合法或历史内容损坏时保留missing，不以重生成倒填历史。原价格/来源/可信质量或同日新鲜源钟不满足时为partial，保留实际加入钟与原报价值并展示原因，不宣称完整原报价。精确窗口沿数据源§7.2的原契约，GET不事后重算升级。

盘中GET只投影OpportunityDecisionSnapshot：同一北京时间交易日、stage=rank、decision=ranked、selection_entry_contract匹配，且1≤rank≤effective_limit与within_display_capacity为真。按实际created_at再id取首次已提交记录，不取更早被拒、unknown、超展示容量或仅参考的源钟。该结构升级feature为pit-evidence-v4.selection-entry，stock-identity-v2的同股归并语义保留；§4.3的v3是前一版记录，效果读者仍按feature隔开，旧版只能显式读取，不补写v4标签。无归档或读取失败显示missing，合格记录原价/数据状态缺项显示partial；读取不归档、不扩样本分母。

已入选后封板的股票仍可显示原首次加入事实；从未合格入选的封板参考股不伪造加入记录。参考身份由原梯队生产者与top投影明确传递，缺归档时显示“当前仅参考，未查到已归档入选依据”，不堆叠时间与价格占位，也不把读取失败或旧版缺项断言为从未入选。真实候选缺记录仍明确提示并保留原因。这里记录出现时点供复盘优化，既不放宽候选/执行门，也不承诺当时可以成交。每日与盘中同股在去重主卡分别显示各自首次加入事实和“每日依据”，不把两个首次时点或价格混成一个。新盘中候选读侧可能先于下一轮持久快照归档出现；GET不为消除未知而写入样本或重选。

今日盘面涨停数/最高高度来自原同源完整涨停池；最高证券身份来自summary.market_max_board_stocks，并列先列身份，缺身份不从当前可见候选猜。题材机会数是本轮按强度截取的题材数，含无参与候选的题材；断层仅计has_succession=false，unknown不当断层。两类题材旁览固定点击时原opps/date/理由并复用OpportunitySection，能继续核原股票、官方成分和市场梯队；不是全市场题材全集。

每日影子用于比较原每日精选在原执行门和模拟规则下的实际委托/成交。实际配置晨窗为start_time≤北京时间<end_time，后台60秒轮询；晨窗读取最新已保存精选，可能是当日生成或此前组合，实际组合日以执行回执为准。机会影子用于验证原buy_point合格决定的执行轨，不直接消费所有盘中候选；沿既有30秒轮询、60秒同版报价重检及原RiskEngine/T+1规则。窗口与间隔由activation展示，不在UI猜配置。

两者enabled表示配置开关，activation.runner_loaded表示装配；runtime分别呈现not_loaded/unknown/running/paused/ready/degraded及as_of/原因。配置已开不证明运行正常，ready也不是订单成交。每日/机会GET均只读原账户和历史回执，不ensure_account、不启用开关、不启动模型/订单；未创建账户的金额为null。关闭后仍可读历史，实际启用/暂停走原受控配置和授权，不新增前端启动按钮。
