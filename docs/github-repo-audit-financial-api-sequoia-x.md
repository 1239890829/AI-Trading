## 一、Financial-API（同花顺 fuyao API 文档镜像）

**一句话定位**：同花顺 fuyao 官方 API 的文档/SDK 镜像仓库——就是本项目 `skills/hithink-finance/docs/` 的上游。

### 1.1 核心发现：我们已经在用它的「下游」，且几乎不落后

- 逐文件比对结论（证据 A）：`skills/hithink-finance/docs/` 与该仓库内容为同一来源，本地 vendored 版本仅落后上游约 2 天。
- 该仓库的真正价值不是「新能力」，而是**文档更新流**——ths 官方端点变动会先出现在这里。目前 `git log` 该 docs 目录即可跟踪上游变化，无需引入额外同步机制。

### 1.2 market-dumps：本次审计最有价值的实测发现（证据 A）

该仓库提供的全市场历史行情 dump 通道实测：

| 指标 | 实测结果 |
|---|---|
| 拉取量 | 10 年全市场日 K，约 **1025 万行** |
| 耗时 | **2 分 24 秒** |
| 对比 | 比逐股拉取（baostock 式）快约 **30 倍** |

对本项目的意义：当前日 K 数据逐股获取，做**全市场横截面**计算（如 RPS 相对强度、全市场分位数）成本过高。本地 dump 仓一次性解决。

### 1.3 采纳清单（3 项）

| # | 采纳项 | 收益 | 落点 |
|---|---|---|---|
| 1 | **market-dumps 本地日 K 仓** | 解锁全市场横截面回测与参数校准（RPS、分位数、批量回放） | 新增一次性脚本 + 增量更新 |
| 2 | **RPS 横截面分位** 进 tech_score 第 7 维 | 现有 6 维全是「个股自身 vs 自身历史」，缺「个股 vs 全市场」维度；打板系统里「强者恒强」正是横截面信息 | `backend/app/picks/tech_score.py` |
| 3 | **后端补齐前端已有 3 个形态** | `tech_score.py` docstring 声称实现形态识别，实际后端为 0、前端有 3 个——先修 docstring 撒谎问题，再决定补哪些 | 同上 |

### 1.4 放弃项

- 无。该仓库无代码引入风险（纯文档/数据通道）。
