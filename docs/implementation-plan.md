## 3. 总体设计裁定

| 设计点 | 当前选择及理由 | 拒绝的替代做法 |
|---|---|---|
| 架构 | 保留模块化单体与现有FastAPI/Next.js、Provider/QuoteHub、存储、撮合/回放；按真实边界复用 | 为整齐全面重写、默认微服务/新图数据库/新调度平台 |
| 全功能闭环 | 每个功能产生可用事实、用户动作或保护效果，并有可核反馈 | 所有功能硬塞一个选股流程或只有按钮没有消费者 |
| 对象关系 | 市场上下文、事件修订、机会/决定、通知、模拟动作、手工记录、复盘/实验各守身份，关联而不混同 | 全站强共用一个机会ID；个人成本当市场形态 |
| 前后台 | 后台拥有业务判定/费用/规则/标签/预算；前端呈现与正常交互，受控后台承接管理动作 | CSS藏按钮冒充鉴权；连图坐标/焦点也搬服务端；静默上传私人聊天 |
| 选股 | 多入口召回、多轴情境、阶段状态/条件/失效；案例不封版，未知有事实入口 | 仅临板或少数家族；一堆指标投票；没机会强凑Top-K |
| 知识与模型 | 知识区分原则/案例/假设/反证；模型用于整理/解释/研究建议，规则硬门独立 | 有KB引用等于有效，模型改权限/参数或自产批准 |
| AI 分层 / Jev | 确定性规则优先；只有 bounded Choice/Noul/Score、证据→主张验证或多个真实能力竞争且选择不明显时才用 Jev；复杂自由推理再升级 DeepSeek/Codex/ChatGPT | 每任务固定调用 Jev、让 Jev 替代金融硬门/权限/执行、把 confidence 当上涨概率/策略胜率 |
| 开放世界演进 | 稳定内核 + 探索前沿；主动找新模型/工具/方法/数据/反证，先来源核实和硬门，再 E2–E5 实验/影子/挑战者；拒绝/观察也有重开条件 | 把当前方案写成永久最终版；只等用户提供新东西；按热度/Stars/论文宣传自动安装、建任务或改生产 |
| 通知与模拟 | 同决定版本派生各自意图/动作；动作前重检，结果未知保留 | 正文有“通过”就发；已显示/已受理等于送达或成交 |
| 迭代与节省 | 有据提出→比较替代→小范围验证→审核→版本切换→观察/恢复；持续量测成本 | 每轮必须新增任务；用删有效测试、隐瞒数据退化换速度 |

全站与小动作的具体目标及验收契约见产品设计§4/§5，覆盖来源和已有疑点见细功能审计；两者合用，不用“还要逐个测试”替代现在应写清的目标行为。

## 6. 持续推理与改进的闭环

观察来自当时数据、用户反馈、失效/漏报/正确弃权、代码与接口差距，不能只从被推送或被点击的成功对象学习。先判断数据/身份/规则/排序/执行/展示/假设哪一层的问题，再判断是否有新方案需求。
每个提议必须写：现象与证据等级、受影响用户/消费者、原因或竞争解释、现状/最小修补/复用/重构四种替代、收益方向与测量办法、开发/迁移/维护/模型和CI成本、风险及恢复。没有量化证据时给可测假设，不编收益百分比或用任意权重算一个“高分”。
裁决允许：本轮必改、并入原任务、重排后继、限定取证、观察等待、否决/退出、保持现状。只有真正不同的新要求或高价值缺口才新增任务；同义去重、保留来源，不能反复给同一想法换名字。
执行侧提出实际发现，网页侧评估并修原方案/任务。实证不足者只研究，不使用已失败方法的另一个名称绕过准入；同一比较窗口只允许可归因变化，模型参数/代码变更与普通记录不同权。
已有安全停机/恢复和有预算的观察可后台进行；新策略/参数晋级依当前批准、冻结证据及回滚所有权，不由模型自己批准。Jev 当前只处于受限语义协处理、条件能力路由和 off/shadow 验证阶段；human gold、同条件 A/B、walk-forward/消融没有完成前，不启用生产 cascade、不调交易阈值、不宣称准确率或额度节省。运行/效果异常触发局部重评，稳定且无新证据时不重写全方案。持续节省优先消除重复工作，不减安全和有效覆盖。

### 6.1 开放世界持续演进

内部反馈只能告诉我们“现系统哪里不好”，不能证明“外部是否已经出现更好解法”。长期研发因此必须同时运行外部雷达，方法见 [continuous-evolution.md](continuous-evolution.md)：官方规范/源码/论文优先，社区热度只作线索；候选先过许可、隐私、权限、费用、供应链和可恢复硬门，再做相同输入/基线的 E2–E5 证据升级。

雷达可以自主发现、分类、拒绝、观察和提出最小实验，但**不能自主采用**。Jev 可做 bounded triage/去重/相关性辅助，复杂候选由 DeepSeek/Codex/ChatGPT 研究，最终仍由目标域实验、stage 所有权、网页审核与准确版本门决定。量化候选额外受 point-in-time、成本、可成交性、purged walk-forward、multiple-testing 和 Champion 对照约束。

“已完成/已采用”不是永久豁免。重要决定要保留重开触发：市场/监管/依赖变化、稳定失败模式、维护成本恶化、外部可复现实证或原关键前提失效时重新比较。没有更好候选时保持现状是正确结果，不为了表现自主进化而制造任务。

重大新决策完成后还要做一次“文档影响面传播”：总方案、专题蓝图、权责表、INDEX、所属 stage，以及受影响的 AGENTS/Skills/handoff 必须同步或明确不适用。该步骤属于决策交付本身，不是事后可选整理；机器守卫负责根入口漂移，网页审核负责语义影响面。

## 7. 不能漏掉的跨模块约束

双时间与修订：发生时间、可知时间、接收次序、当时规则/知识版本分开；迟到更正不倒填原决定。历史成分、复权、披露、费用/标签版本与分母明确，D0涨幅不伪装成可实现净收益。
状态与并发：换股票/日期/筛选绑定请求身份，成功/失败/取消都只影响当前对象；按钮完成以服务器事实回执为准。页面消失不停止后台风险，旧回包不能污染新标题；陈旧值可保留但不可伪新鲜。
故障与恢复：数据恢复不能撤回已外发消息，结果未知先核对再重试；恢复默认避免重复副作用。关键事实、审计与不可重建用户记录保留，缓存/派生可重建；保留期、外发、敏感数据按用途和授权，不盲统一数据根。
性能与成本：同输入/覆盖/新鲜度/负载比较错误率、尾延迟、CPU内存、请求/模型/CI成本；硬门优先、解释可降级。不得为测量反复跑收费任务，未知余额不是无限预算，平台拒绝不换工具绕过。
功能价值：少提醒/不操作也可能是正确结果；保护、备份、取消、鉴权等低频功能有价值，不以点击率删除。文本或DOM正确不代替真实Canvas；用户理解、研究效用、运行可靠与代码工程分开。
