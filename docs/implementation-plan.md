## 1. 结论与依据优先级

不能将“治理结构迁移通过”理解为“方案已无缺口”。主方案的模块化单体、证据驱动、先真实性后能力、领域分权和分层验收方向继续采用；原阶段正文仍有过粗任务、历史指针和不充分的依赖表达，须按本版修正后实施。

依据顺序为：最新明确用户要求与安全边界 → 本版对 v9 的明确修订 → v9 及附件未被修订的目标/约束 → 所属阶段的单点任务 → 有日期的历史说明。代码与实测是“当前发生了什么”的依据，不因现有实现存在就成为“应该继续这样做”的依据。

本版不覆盖原件。原件是用户本机可视化目录中的《AShare-AI-Trader-最终审计与重构实施方案》v9，SHA-256：`b144a07787d07c5ffe4e5fa27e858ae86cbeebbc0576c93140e04c5bf65c1984`。原件完整路径和取证范围随本批本地回执保存。旧原件、HTML、逐文件 CSV 仍是历史证据，不回写为新审计状态。

## 6. 自主进化应怎样落地

目标不是每天自动生成更多报告，而是可验证地提高决策或研究效用。复用已有 findings、快照、experiments、agent_params 和审核记录，不另建完整控制平台。

1. 观察：采集入选、漏选、硬门拒绝、弃权、未成交、延迟/重复提醒；完整保留分母与当时可见数据。
2. 定位：区分源错误、时间错误、规则、排序、执行、产品误解；相关性只形成假设，不冒充因果。
3. 假设：登记插入层、适用市场状态、数据版本、基线、预期最小改善、成本/风险、停止条件与替代方案；同一假设去重。
4. 试验：固定开发/验证/盲测划分；全量登记成功与否证，覆盖手续费、成交未知、标签延迟、跨日和相关样本。
5. 决策：输出证据不足、拒绝、继续影子或待批准晋级；限制一次只有一个可归因的候选变化，不能由产出模型独立给自己批准。
6. 切换：策略/选股参数晋级必须满足当前明确授权、证据与风险约束；漂移温和只证明没有剧变，不证明有收益。低风险只读/报告/已授权影子任务不一刀切关闭。
7. 观察与回退：按预注册条件监测，数据/安全事故可立即停相关能力；回退只恢复仍由本变更拥有的状态，保留历史和失败证据。

不预设新增的统计模型、战法或 Agent 优于当前规则。缺数据时先建设可用的收集与验证链，不改门槛制造“更聪明”的表象。

## 7. 主动补足的遗漏及取舍

| 不应漏掉的方面 | 为什么值得做 | 归属与限制 |
|---|---|---|
| 审计单位与独立样本分离 | 一次机会可跨阶段/主题/轮次产生多行；刷新不应增加统计信心 | BUG-026、RSH-026；聚类/时点/轮次口径预先定义，不简单全按股票去重 |
| 数据与知识的双时间、修订身份 | 事件发生较早，不代表当时就能知道后来补录/更正的内容 | BUG-020、IMP-048、RSH-026；effective time 与 available time 同时约束 |
| 标签版本、费用版本与可实现边界 | D0 方向分数、扣费代理、合法模拟净收益不可混称 | BUG-026、RSH-026；旧标签不覆盖，不重写已应用迁移 |
| 实验期间的配置污染 | 同一比较窗口改多项参数，无法归因；温和变化也可能改变排序 | IMP-046、IMP-020；固定候选版本、记录并发试验与审批，保留 CAS 回滚 |
| 恢复后的外部副作用 | 数据恢复不能撤销已经发出的消息；重放不可盲目再次发送 | IMP-044、GOV-013；unknown 保留、重放默认不外发、按能力核渠道幂等 |
| 源共同故障与预算放大 | 多适配器可能同上游；逐层重试和后台研究会争抢关键链 | IMP-040、IMP-019；方法级 deadline、预算与失败分母，不先引消息中间件 |
| 决策档案的容量与保留 | 高频完整快照可能无限增长；删数据又可能破坏回放 | GOV-013、RSH-026；测体积后区分不可重建审计、可重建派生和缓存，增量压缩不丢因果 |
| 非动作的产品价值 | 少提醒可能是正确弃权，不是系统失败；更多交易不是成功指标 | BUG-016、GOV-021；检查不提醒原因、有效期、误扰与用户理解成本 |
| 生产版本可观察性 | 工作区、构建包、Git 主干和运行进程可能不同 | OPS-003；记录构建/配置/数据/schema身份，不泄漏凭据，未加载明确披露 |
| 治理成本和继承可靠性 | 永久全量重读或只存临时目录会吞掉开发能力/丢接续证据 | GOV-019/020；按差异及影响读取，持久化交接；完整CI不因治理成本删除 |

补充以下跨模块风险的验收要求；这些是设计风险推导，尚未全部复现，不能登记为已发生事故：

| 风险 | 最小改进与证据 | 归属 |
|---|---|---|
| 只从被提醒或被点击的股票学习 | 分别记录合格、静默、曝光、点击、动作；未点击不等于负收益。对未提醒候选只做只读/影子对照，不能为了采样扩大推送 | RSH-026、IMP-020、GOV-021 |
| 排队后授权、风险或参数被撤销 | 领取与发送前核政策/决策版本；界定发送开始的边界，之后发生撤销不能伪称消息未发，必要时记录未知及有授权的更正 | IMP-044、IMP-006、IMP-046 |
| 墙钟回拨、同秒多更新、进程重启 | 明确业务时间、接收次序、实例代号和本机耗时计量；旧帧不能覆盖新状态，租约和过期不依赖来源时钟可靠这一假设 | BUG-020、IMP-019、GOV-013 |
| 各模块分别通过却整条链路错误 | 同一固定案例贯穿数据→决定→页面/通知→标签/复盘，比较具体业务ID和版本；保留独立期望值，不让生产算法同时产生测试答案 | GOV-021 与对应业务任务 |

以上是针对已发现风险的最小闭环，不等于新增多套平台。安全/恢复低频能力不能按点击率删除；未知数据许可、跨项目资料和唯一证据不清理。

## 9. 发布、度量与文档纪律

每个切片写清：需求/来源版本、已读与未读范围、现状及反例、至少一个低成本替代、选择/拒绝理由、具体消费者与文件、可验证验收、切换条件、恢复和观测。仅为当前领取的切片细化，不为未来所有候选空填工时或虚构指标。

“性能不劣”用同输入、同版本、同负载、同数据新鲜度的对照证明；保留错误率、覆盖、内存和尾延迟。不能通过减少数据、隐藏降频、放宽金融硬门或排除失败样本求快。尚未证明的全球最优/显著收益不写成承诺。

工程、运行、研究、用户价值四层分别判定。字段/引用/安全修复可先独立交付；后续长期样本不拖住已修切片，也不能提前宣称策略优势。代码正确不能替代外部消息真实送达、生产版本加载或用户理解验证。

账单 API 403 不是 CI 失败，也不是可花费余额为零/无限的证明。发布前核当前可用额度及既有零付费约束，无法核实则阻塞相关云端发布，不反复轮询无权限接口，也不停止安全的本地证据/小切片工作；在途切片须有边界，不无限累积未发布大分支。不得改仓库可见性、付款设置、保护规则或跳完整 CI 求交付。

接手工作区不可直接 reset/clean，不因旧 Skill 写“从主干新建”而丢掉前任成果。核对来源分支、HEAD、已暂存/未暂存/未跟踪和并行编辑者；每批准确 Git 与门禁证据写 handoff，交付日志保存原项目忽略的 artifacts 持久目录，临时工作区只作为施工位置。

Codex 仅能访问 GitHub 时，先检出包含本批的功能分支，读取仓内方案、任务、交接与实际代码；不要只读尚未合并的 master。原 v9/私有回执缺失时，只把确实依赖它们的证据项标为未核验，不编造本机文件，也不阻断可安全复现的独立缺陷。导出的交接包是固定版本副本，不是可单独更新的另一份账本。

原始 v9 与附件保留历史身份；当前计划写本文件，当前状态写阶段，权威指针写 INDEX，实际接口与知识改到原专题。只纠正会误导当前执行的旧说法，不全仓追逐历史字符串，不另建一个“治理治理”的系统。

## 10. 一手依据及采用边界

- AWS Transactional outbox pattern：用于同库事务、重复消费和顺序边界；不采用整套 AWS 架构，不声称外部恰好一次。https://docs.aws.amazon.com/en_en/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html
- Feast Point-in-time joins：用于“特征在决策时点可用”的约束；本项目另要求可见时间与修订身份，单凭事件时间不能消除迟到修订。只采纳时间语义，不引入 Feature Store。https://docs.feast.dev/getting-started/concepts/point-in-time-joins
- scikit-learn Common pitfalls：用于训练/测试与预处理隔离，防止性能估计乐观；不是本项目策略有效性的证明。https://github.com/scikit-learn/scikit-learn/blob/main/doc/common_pitfalls.rst
- Google SRE Canarying Releases：借鉴按版本比较、逐步暴露、可恢复切换及指标取舍；单机项目不为采用案例新增集群。https://sre.google/workbook/canarying-releases/
