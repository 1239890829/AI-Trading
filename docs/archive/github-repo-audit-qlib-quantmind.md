## 一、microsoft/qlib

**一句话定位**：微软开源的 AI 量化研究平台（日频截面多因子范式的完整实现：数据层 → 因子库 → 模型训练 → 回测 → 分析）。

### 1.1 实测：完整 workflow 跑通（证据 A）

- 安装 + 最小回测样例全链路跑通，总耗时 **1273 秒**（数据下载 + 特征 + LightGBM 训练 + 回测）。
- 实测中观察到一个有价值的现象：**成本模型把模拟组合的交易成本扣到超额收益归零**——qlib 的成本约束设计是认真的，不是摆设。
- 回测引擎细节（证据 A/B）：`volume_threshold`（按成交量占比限单，防假设无限流动性）与**涨跌停按板块映射处理**（不同板块不同涨跌幅限制）都是生产级细节。

### 1.2 判定：不引入 qlib 本体（证据 A + 架构对比）

**核心论据：范式不同构。**

| 维度 | qlib 范式 | 本项目范式 |
|---|---|---|
| 决策频率 | 日频调仓，持仓数十日 | 打板/题材接力，T+0~T+2 |
| 决策对象 | 横截面多因子打分全市场 | 涨停池/题材梯队/情绪周期 |
| 数据底座 | 标准 OHLCV 因子库 | 涨停池/连板/人气榜/封单（ths 特有） |
| 建仓假设 | 按均价成交 + 量约束 | 涨停价排队、竞价抢筹、炸板 |

qlib 的因子框架对「连板梯队、封单质量、晋级率」这类对象**没有原生表达**；硬套等于削足适履。

**且我们的目标是「校准风控参数」，为校准引入整个平台（数据层+模型层+回测层）不成比例。** 更划算的路径：**扩展现有 `backend/app/market/backtest.py`（407 行，已含 T+1/涨跌停拒单）到多标的横截面**，配合第 1 组 market-dumps 本地日 K 仓即可获得横截面回测能力。

### 1.3 抄设计清单（2 项，不抄码）

| # | 抄什么 | 细节 | 落点 |
|---|---|---|---|
| 1 | **volume_threshold 量约束** | 回测成交假设按当期成交量占比封顶，防止小市值标的回测虚高 | `backtest.py` 扩展 |
| 2 | **涨跌停按板块映射** | 主板 10% / 创业科创板 20% / ST 5% 的映射处理方式（与我们情绪模块的「双边区间限价判定」互相印证） | `backtest.py` 扩展 |

## 二、QuantMind

**一句话定位**：基于 LLM 的量化研究 Agent 平台（自然语言驱动因子研究）。

### 2.1 判定：一票否决（证据 C/B）

- **License：AGPL-3.0。** 本项目是私有部署的个人交易系统，AGPL 的传染性条款（网络交互即需开源）使**任何代码级引入都不可行**。
- 功能层面与本项目重合度低（其价值在「自然语言→因子代码」的研究流，我们不需要）。

**判定：忽略。**

- QuantMind：AGPL 一票否决，忽略。
