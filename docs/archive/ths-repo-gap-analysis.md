## 二、改进项清单（每项：收益论证 → 方案 → 可行性 → 排序）

### A1 当日异动原因接入（anomaly-analysis-list + stock）——**P0，已开始实施**

- **收益论证（真实需求，非堆砌）**：① 直接补昨天 `hotspot-pipeline-design.md` 的 **G5 验证回路**——「消息→板块→个股」链路里最缺的『盘面确认』环，异动原因（官方分析文本 + 关键词）就是『哪些股票正在因什么异动』的权威答案，且为 **ths 独占口径**（东财无对应）；② 自选股监控（官方场景 5 的直译）——自选行现在只有价格异动，没有「为什么」；③ 助手可直接回答「XX 为什么异动」（当前 9 工具无一能答）。
- **方案**：`ths.py` +2 方法（list 支持 tag_codes 过滤：LIMIT_UP/SHARP_RISE 等 6 标签；stock 支持 1-50 代码批量）→ `AnomalyRecord` schema → composite 登记（ths 独占，无备源）→ `GET /api/market/anomalies`（全市场，60s TTL 缓存，today-only 显式）+ `GET /api/market/anomalies/stock?symbols=` → 助手 `anomaly` 工具 + 自选行徽标（前端下一批）。
- **可行性**：成本低（字段 5 个、无分页、today-only）；风险 = ths 429（已有 breaker 兜底）、非交易日空集（显式空 + 说明，不冒充）；依赖 = 无新增。
- **预期收益**：验证回路的盘面证据环当日可用；自选监控从「涨了」升级到「涨了+为什么」。

### A2 封单质量指标（max_seal_money + 早封率/封单留存）——**P0**

- **收益论证**：first_seal_time/seal_amount 已入库但**下游未消费**，max_seal_money（盘中最高封单）缺失导致「封单留存率=收盘封单/最高封单」算不出。早封率与封单留存是短线情绪的两大质量口径（官方场景 12 核心方法），题材梯队卡与复盘直接受益；dragon_service 的介入时机清单（entry_checklist）获得封单维度证据。
- **方案**：ths.py 补 max_seal_money 字段 → schema 加可选列（None 三态）→ 题材梯队卡加「封单质量」（早封率=10:00 前封板占比、封单留存=收盘/最高）。
- **可行性**：低成本（一个字段 + 两个纯函数指标）；风险 = 无；依赖 = 无。历史不可回补，从实施日起随涨停池落盘自然积累。
- **预期收益**：复盘与梯队判断获得「封得早不早、封得实不实」两个可解释口径。

### B1 飙升榜 skyrocket-list——**P1**

- **收益论证**：热股榜是「已热」，飙升榜是「正在变热」（rank_change/rank_trend 字段）——热度异动的更早信号，watcher/alert 的「关注度突增」规则的现成数据源（热点消息方案 G7 的一半）。
- **方案**：+1 端点方法（period=day/hour，7 字段）→ tape 热股榜旁列飙升榜 → heat_history 落盘扩展。
- **可行性**：极低成本；风险与 A1 相同（ths 限流、breaker 已备）。
- **预期收益**：关注度维度从截面变动态。

### B2 个股热榜排名趋势 hot-stock-rank-trend——**P1**

- **收益论证**：场景 11 的底座——「昨日排名跃升 vs 今日相对收益」共振是可验证的注意力信号；heat_history 已有榜单历史，补单股走势端点后可做「关注-价格背离/共振」提示。
- **方案**：+1 端点方法（单股 + 日期区间）→ heat_history 扩展落盘 → P2 做共振信号。
- **可行性**：低成本；依赖 B1 的落盘扩展同批做省事。
- **预期收益**：为「关注度异动」提供时间轴证据链。

### B3 龙虎榜跨日概念轨迹（场景 16 方法学）——**P1**

- **收益论证**：现有龙虎榜是单日榜单；「近 N 日游资/机构净额按题材聚合的迁徙轨迹」直接回答『资金在题材间怎么轮动』——与热点消息验证环（消息→板块→游资确认）互补，且**不需要新端点**（dragon-tiger-list 已接，纯聚合计算 + ths 概念成分映射）。
- **方案**：dragon_tiger 逐日落盘（N≤10 控限流）→ 多概念等分净额（官方口径：保证总额守恒）→ `/api/market/longhu/theme-trail` → tape 龙虎榜 tab 加「题材迁徙」视图。
- **可行性**：中成本（聚合逻辑 + 概念映射复用 theme_catalog）；风险 = 逐日拉取的限流（落盘缓存后每日仅增 1 次/日）；口径标注（等分是官方建议的守恒法，非真实拆分）。
- **预期收益**：游资轮动从「看单日个股」升级为「看题材轨迹」。

### C1 meta/tickers/search 名称消歧——**P2**

- **收益论证**：assistant 实体识别靠本地词典，词典外名称（新上市/别称）消歧失败；search 端点是官方消歧通道。收益真实但边际（词典 + 多轮澄清已覆盖主力场景），列 P2 顺带做。
- **可行性**：极低成本（+1 方法 + 助手兜底调用一次）。

### C2 行业强度矩阵（成交额脉冲 + 强度加速度）——**P2，须先等 board_flow P0**

- **收益论证**：RPS 已有相对强度，「5/20/60 强度 + 排名变化 + 成交额脉冲」是官方场景 9 口径；但板块强度类能力**必须收口一处**（与资金流向重构方案的 L2 board_flow 枢纽原则一致），否则违反「同类能力只允许存在一处」红线。
- **方案**：board_flow P0 落地后，在其上叠加脉冲/加速度衍生列，不新建服务。
- **可行性**：依赖 board_flow P0 实施。

### D 财务四端点 + 估值快照——**P3 暂缓（需求未确认，防堆砌）**

- 系统定位短线情绪/题材，五维评分全为量价+情绪；估值卡（个股详情 PE/PB）与现金流质量过滤（场景 10）有真实价值但**当前无用户需求信号**。按「严禁盲目堆砌」纪律，列为暂缓，待用户提出基本面需求再评估。

### 明确剔除

- **基金 28 端点**：系统不做基金分析与申赎，全部剔除。
- **marketdb 官方 toolkit**：自建 marketdb 已对齐官方设计（dump 同步、复权视图、面板导出），无需迁移；官方 recipes 的 Arrow 零拷贝路径在后续做大面板时参考。
