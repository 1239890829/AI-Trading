## 0. 结论速览

1. **现行组合方向正确，不需要换源。** 腾讯主源 + ths 官方 + 东财/新浪备源 + easy_tdx 回测的组合，经 GitHub 生态普查（17 仓）与本机开盘时段 3 轮复测双重验证。缺的不是"更好的源"，而是"源的可观测与哨兵"。
2. **三模块定源**（详见 §2/§3）：
   - 分时图 = 腾讯 minute_line（97ms，3/3）主源 + TDX 历史回补（1 分钟 94 交易日深度）+ `mergeQuoteIntoMinutes` 实时合成
   - K线 = ths prices-historical 官方主源（133ms；**【更正】本文撰写时误记为"未接线空桩"——`ths.get_kline` 早在 e77971f 已实现并作为主源在跑**，2026-09-02 parity 60/60 与腾讯 qfq 全一致，最大偏差 0.0023%，备源可信）；腾讯 kline_1d（41ms，3/3）为第一备源
   - 实时行情 = 腾讯 1Hz（62ms，3/3）+ WS 推送（6s 握手超时已修）；新浪并发 hedge 未做（约 20 行，P1-A）【09-02 下午 P1-A 已落地：主源宽限 200ms + 备源对冲】
3. **最优先执行项不是接新源**，而是 P0-A（provider 健康可观测——`breaker_state()` 已存在但没有任何 API 能看到它）+ P0-B（ths 涨停原因单点哨兵——覆盖率 100% vs 东财 0%，零备源）。
4. **盘点收敛**：21 个陈旧任务已清理剔除（§6），真正开放项收敛为 **P0×2 / P1×4 / P2 触发式池 / 用户决策阻塞×3**（§7）。
5. **不引入** akshare / tushare / baostock：GitHub 生态用它们做聚合中间层，本项目已是"官方 ths + 源站直连"，再包一层只增加失效面（§5）。

### 3.2 补强清单（不是换源，是补短板）

| 项 | 内容 | 为什么是它 |
|---|---|---|
| **P0-A** | provider 健康可观测：把 `composite.breaker_state()` 暴露为 `GET /api/system/providers` | 熔断器已存在但**无任何 API 能看到**——降级发生时界面照常，人不知道数据已经换源。搜索事故、东财断连都靠事后排查才发现 |

### 新源接入检查单（每项必过，顺序执行）

1. 读官方端点文档（字段表/分页/时间戳格式）——`skills/hithink-finance/docs/api/*.md`
2. 3 轮×间隔 2 分钟延迟与成功率复测（错误单独计数）
3. 语义测试：空结果、失败、边界（ST/新股/停牌/非交易日）三态明确
4. breaker 接入 + 失败语义归类（该源"空"属于哪类）
5. parity 交叉验证 ≥50 只标的与现主源逐项对比
6. `GET /api/system/providers` 可见新源状态（依赖 P0-A）
7. 灰度：先备源后主源，观察一个交易日
