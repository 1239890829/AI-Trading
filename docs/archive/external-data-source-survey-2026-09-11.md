## 0. 结论速览

**一句话**：**四家里没有一家提供 Level-2**——它们最高只到 **L1 五档**；而且其中两家的上游
**和我们用的是同一批源站**（东财/新浪/同花顺），买它们买的是"别人爬好清洗好的数据"，不是更上游的数据。
它们的优势在**数据工程**（标准化、复权、批量、SDK、多市场）与**广度**（宏观/基金/因子），
**不在**短线情绪语义（涨停原因、游资席位、连板晋级、题材归因）——后者正是我们系统的护城河。

| 平台 | 出品方 | 计费 | 最强项 | 是否 L2 | 对本项目的边际价值 |
|---|---|---|---|---|---|
| **Tushare Pro** | Tushare 社区（半官方） | 积分 + 单项订阅 | 财务/基本面规范度、历史复权 | ❌ 无 | ⚪ 低（财务已有东财） |
| **FTShare** | 非凸智能（FTShare-Lab） | 免费版 + 付费档【未公开】 | 广度（宏观/基金/供应链）+ 特色因子 + Agent 接入 | ❌ 无 | 🟡 中（免费版可试） |
| **KlineShare** | 未公开主体 | ¥99~399/月 | A 股实时 + 打板专题（涨停/炸板/连板/游资） | ❌ 无（期货有 tick 推送） | 🔴 高（可作 ths 备源） |
| **QuantDash** | 未公开主体 | Free / ¥58 / ¥98 / ¥188 月 | 多市场（A/港/美）+ 工程化 SLA | ❌ 无 | ⚪ 低（除非做港美股） |
| **PTrade** ⚠️ 异类 | 恒生电子 | 权限免费，需 10–30 万资产 | **真 L2 + 真实下单** | ✅ **有** | ⚪ 低（数据不出券商环境，且触碰实盘红线） |

**核心判断：不换源，且不建议为"更专业/更全"付费；唯一值得掏钱的是 KlineShare 作为 ths 打板数据的备源。**

> **2026-09-11 追加（重要更正）**：下午补充调研了 **PTrade（恒生）**——它**不是数据 API，是券商量化交易终端**，
> 而且是四家里唯一**真提供 L2** 的（十档 + 逐笔成交 + 逐笔委托 + 首档前 50 笔队列），**对达标客户免费**。
> 但它的数据**不出券商环境**，详见 §1.5 与 §2.2 的"第三条路"。

### 1.5 PTrade（恒生）—— ⚠️ 它不是数据 API，是券商交易终端

> **品类差异（必须先厘清）**：上面四家卖的是「**把数据送到你手里**」；
> PTrade 卖的是「**你在它里面跑策略、它替你下单**」。把它和 Tushare 并列比较是错位的。

| 项 | 内容 |
|---|---|
| 出品方 | **恒生电子**，券商定制（各券商版本不同） |
| 定位 | 券商端**云端托管式**量化交易终端，与迅投 QMT 齐名 |
| 运行环境 | **策略跑在券商服务器端**；客户端本地只做管理，**量化模块在云端，策略文件加密存储** |
| 门槛 | 资产 **10–30 万**（客户经理白名单渠道约 10 万）；风险测评 C4+；首笔交易满 6 个月；须签程序化交易协议并报备 |
| 费用 | **权限本身免费**；L2 对达标量化客户**免费赠送**（券商差异，需逐家确认） |

**它的 L2 是真 L2（四家里唯一）**：

| 接口 | 能力 | 对应上证所 L2 定义 |
|---|---|---|
| `get_l2_order_book(level=10)` | 十档买卖盘 | ✅ 十档 |
| `get_individual_transaction()` | 逐笔成交（毫秒时间戳、成交方向 0卖/1买） | ✅ 逐笔成交 |
| `get_individual_entrust()` | 逐笔委托（委托价/量/编号/方向/类型） | ✅ 逐笔委托 |
| `get_gear_price()` | 十档 + **第一档前 50 笔委托队列**（实测可看到自己 8888 手排第 9 位） | ✅ 首档前 50 笔 |
| `get_tick_direction()` | 分时成交（含每笔笔数），默认 **3 秒**一刷 | 分时 tick |

**但它有三个硬约束，决定了它对我们不是"数据源"**：

1. **数据不出券商环境**：与本地交互靠**文件中转**——进是交易指令 CSV，出是**成交回报**。
   **L2 行情数据本身没有导出通道**，无法落地进我们的 Parquet / 回测库。
2. **逐笔接口仅实盘策略可用**：多篇资料明确"测试环境不提供"，即**不跑真策略就取不到逐笔**。
3. **券商版本碎片化**：内置 Python 从 **3.5 到 3.11** 不等（国金已升 3.11，多数仍 3.5），
   同一函数返回格式可能不同（老版返回 Panel，新版统一 DataFrame）。

**⚠️ 项目红线交叉**：PTrade 是**真实下单通道**。本项目 `AGENTS.md` 红线 1 为
「禁止连接真实券商 / 自动真实下单」。因此它的**交易能力当前不可用**，
L2 能力又因为"数据不出环境"**无法为本项目供数**。
已有的实盘接入方案走的是 miniQMT 路线（`docs/archive/live-trading-guosen-plan.md`，**09-07 已搁置**），
该文 09-01 已判定：**PTrade 云端托管不适合本项目「本地策略引擎 + 外部执行」架构，仅作备选**。

## 2. 专项回答：它们有 L2 吗？

**没有。四家全都没有。** 这是本次调研最需要澄清的一点。

### 2.1 Level-2 到底是什么（上证所官方定义）

来自上证所信息网络有限公司官网（`sseinfo.com/services/assortment/level2/`）：

| 维度 | Level-1 | **Level-2** |
|---|---|---|
| 盘口 | 五档 | **十档**（价格 + 委托数量 + 委托笔数） |
| 首档细节 | 无 | **第一档前 50 笔订单的委托量** |
| 成交 | 快照 | **逐笔成交明细** |
| 撤单 | 无 | **累计撤单笔数/数量/金额** |
| 传输 | — | **FIX/FAST 协议，上证所专网** |

### 2.2 为什么"付费 API"买不到 L2

**L2 是授权制，不是商品制。** 上证所官网列的是两条许可路径：

- **Level-2 行情展示许可**（看）
- **Level-2 行情非展示许可**（用于策略/计算）

要走**授权申请 + 公示**流程，数据经**专网**传输。这意味着：一个 ¥99/月 的 HTTP JSON API
在物理上就不可能是交易所 L2——L2 走的是 FAST 专网，不是公网 REST。

**价格参照**（本项目 `docs/archive/realtime-broker-feasibility-2026-09-01.md` 已记录）：
同花顺 iFinD 类商用终端 **2–5 万/年**，**L2 逐笔 8–15 万/年**。
这与上面四家的 ¥58–399/月 差 **2~3 个数量级**——量级本身就在告诉你它们不是 L2。

#### ⚠️ 更正：L2 还有「第三条路」——券商量化通道（本次调研补上的）

上面说的"买不到"，准确表述是：**买不到一个"把 L2 数据交付到你手里"的独立数据产品**。
但存在第三条路径，且**零数据成本**：

| 路径 | 成本 | 数据能否落地到自己系统 | 备注 |
|---|---:|---|---|
| ① 交易所授权许可（展示/非展示） | 8–15 万/年 | ✅ 能 | 需申请公示 + FAST 专网 |
| ② 商用终端（Wind / iFinD / Choice） | 2–5 万/年 | ✅ 能 | 数据可导出 |
| ③ **券商量化通道（PTrade / QMT）** | **权限免费**（资产 10–30 万门槛） | ❌ **不能** | 数据只在券商环境内可用 |

**第三条路的关键代价是"数据不出场"**：券商把 L2 作为交易通道的配套能力给你，
你可以在它的环境里用十档/逐笔做策略，但**拿不走数据**。
所以它对"做订单流/高频执行"有意义，对"我们要建本地 L2 数据库"**没有意义**。

### 2.3 一个常见误解：五档 ≠ L2

本次调研中，**KlineShare 旗舰版**与 **QuantDash 全档** 提供的"五档盘口"是 **Level-1**，
与我们系统现有的腾讯/新浪五档是**同一层级**。把五档当成"接近 L2"是错的——
L2 的门槛在**十档 + 逐笔 + 委托队列**这三样，一样都不可少。

## 4. 三个判断

### 判断一：它们"更专业"——专业在**数据工程**，不在**市场语义**

| 维度 | 外部平台 | 本项目 |
|---|---|---|
| 数据标准化 | 统一字段命名、统一代码后缀、服务端复权、分页/批量 | 每源一套解析，逐一手写 normalizer |
| 交付形态 | SDK / MCP / Skill 开箱即用 | 自己接 HTTP |
| SLA【宣称】 | 商业保障、高并发 | 依赖免费源站，东财已实测间歇断连 |
| **短线语义** | 只给"谁涨停了" | **还给"为什么涨停"**（题材归因）+ 谁在买（游资席位）+ 能不能接力（`seal_nextday`） |

**结论**：专业度是**分方向**的。它们在"把数据搬整齐"上专业；我们在"把数据翻译成短线决策依据"上专业。
**这两件事不互相替代。**

### 判断二：它们"更全面"——广度确实更全，但**短线这块它没我们全**

FTShare 的 227 个方法在**横向广度**上确实超过我们（宏观 23、公募基金 18、期货 18、供应链、因子）。
但落到本项目核心场景（题材/情绪/打板），外部平台普遍**缺三样**：

1. **涨停原因**（题材归因的唯一输入）—— 四家均未宣称提供
2. **游资席位身份**（打板溢价来源）—— KlineShare 有游资名录/营业部反查，但那是名录反查，
   不等于龙虎榜席位已标注游资身份
3. **连板晋级的官方口径**（`seal_nextday`）—— KlineShare 有连板天梯，是否含次日晋级字段**未验证**

### 判断三：⚠️ 最关键——它们和我们**同源**，不是更上游

| 证据 | 说明 |
|---|---|
| KlineShare 资金流接口 | 直接命名 `新浪板块资金流向榜` / `新浪个股主力资金榜` / `东财个股资金流排名` |
| FTShare 接口命名 | `eastmoney_stock_flow` / `eastmoney_board_constituents` / `ths_board_list` / `ths_all_board_kline` |

**这意味着：付费买它们，买的是"别人已经爬完、清洗好、格式化好的数据 + 运维"，
不是"更原始、更权威的数据"。** 我们的 ths fuyao 反而是**同花顺官方直出**，
在"涨停原因/游资席位/连板"这几项上比这些**聚合层更靠近源头**。

按优先级排序。**以下均为建议，未落地任何代码。**

### 🔴 P0 —— 评估 KlineShare 旗舰版作 ths 打板数据备源（¥399/月）

**理由**：`docs/data/data-source-comparison.md` §2.2 已记录一条明确的单点风险——

**正好覆盖这条风险面**，是目前市面上唯一在 A 股打板数据上与我们重叠度足够高的商业源。

**成本陷阱**：打板专题在基础版（¥99）/专业版（¥199）都是**试用**，只有**旗舰版 ¥399/月**完整开放。
评估时按 ¥399/月 ≈ **4788 元/年** 算。

**验证路径（先验证再买）**：
1. 用它**免费/试用额度**取 2026-09-11 当日涨停池，与 ths 81 只逐只比对
2. 重点验证三件事：①是否有**涨停原因**字段 ②连板天梯是否含**次日晋级**字段
   ③游资名录能否反查出**龙虎榜席位的游资身份**
3. 三项中若①为否 —— **则它不能替代 ths 的题材归因，价值大幅下降，建议不买**

### 🟡 P1 —— 零成本试用 FTShare 免费版，补宏观/基金广度

**理由**：免费版长期保留，覆盖宏观 23 项 + 公募基金 18 项 + 供应链关系，都是我们目前**完全没有**的维度。

**纪律要求**（避免重犯"示例当规范"）：
- 其**特色因子**（新闻情绪因子 / 相关性 Top-K / K 线形态标注）属于**他人加工的研究数据**，
  引入时一律登记为 **「候选假设 · 待验证」**，**不得直接进评分体系**
- 参考 `docs/summary/factor-system.md §5` 已有的因子核查表流程，先验证后入库
- 若未来要用，先做**与东财现有数据的交叉验证**（我们已有东财财务，可做口径对账）

### ⚪ P2 —— Tushare / QuantDash：暂不引入

| 平台 | 不引入的理由 |
|---|---|
| **Tushare** | 财务数据我们已有东财，**边际价值低**；真正有价值的"历史分钟"要 **2000 元/年**，而我们已有 pytdx（easy_tdx）落地的 1 分钟 94 交易日回测底座；实时日线 200 元/月 也不如现有秒级链 |
| **QuantDash** | 数据面最薄（无财务/无龙虎榜/无题材），唯一优势是**多市场（港美股）**。**除非决定做港美股**，否则与腾讯源重叠；免费档 10 次/分甚至低于我们现有 60 次/分 |

### ❌ 不建议 —— 为"更专业/更全/更接近 L2"付费

**四家数据 API 没有一家提供 L2**（PTrade 有，但它是交易终端不是数据 API，见 §1.5）。
想拿十档/逐笔/委托队列，只有三条路（详见 §2.2 更正）：

1. 走交易所**授权许可**（展示/非展示）+ 专网，成本量级 8–15 万/年 → **数据可落地**
2. 买商用终端（Wind / iFinD / Choice），2–5 万/年 → **数据可落地**
3. 券商量化通道（PTrade / QMT），**权限免费**但需 10–30 万资产 → **数据不可落地**

**为什么第 3 条对我们也不成立**：我们要的是"**进本地库的 L2 历史数据**"（做因子、做回放、
做盘口模式挖掘），而券商通道只提供"**在场使用的实时 L2**"。两者不是一回事——
就像给你一张只能在场馆内使用的门票，你不能把它带走。
再叠加它触碰"禁止真实下单"红线，**当前不予考虑**。

**按本项目定位（题材/情绪/打板，非订单流、非高频），L2 的边际收益远低于成本。**
这条结论与 `docs/data/data-source-comparison.md` §9 此前的判断一致，本次调研**没有推翻它**。
