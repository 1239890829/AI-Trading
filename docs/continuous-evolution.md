# AShare AI Trader 开放世界持续演进蓝图

> **定位**：定义系统如何长期发现、筛选、验证、吸收或拒绝外部新能力。它是“开放世界研发治理”的唯一现役蓝图，不维护任务状态；状态只归 `docs/stages/`，当前现场只看 `docs/handoff.md`。
> **原则**：计划是 living plan，不存在永久“最终版”。稳定原则可以长期保留，但实现、工具、模型、数据、研究方法和产品路径必须允许被更强证据推翻。
> **边界**：自主发现与提出候选可以持续；安装、付费、扩大权限、修改生产阈值、交易规则、真实外发或采用新依赖仍须走原有任务、PR、审核与准入门。

## 1. 为什么需要开放世界机制

系统最大的长期风险不只来自代码缺陷，还来自“旧方案曾经合理，所以一直沿用”。Jev 的出现已经证明：真正高增量的外部能力可能改变模型分工、成本结构和验证方式；如果只在用户偶然指出时才发现，系统会形成信息封闭。

另一种极端同样危险：看到新模型、热门仓库、论文或社区项目就立即接入，会把宣传、不可复现收益、供应链风险、许可问题、数据不适配和维护成本一起带进生产。

因此长期目标不是“追新”，而是建立稳定的**外部发现 → 证据筛选 → 隔离实验 → 比较基线 → 影子/挑战者 → 准入或淘汰 → 传播复盘**闭环。

## 2. 稳定内核与探索前沿

系统同时维护两层：

- **稳定内核（Stable Core）**：金融确定性规则、权限、风险、撮合、数据身份/时点、回放禁令、发布门禁和已经有充分证据的生产路径。新技术不能仅凭“更先进”绕过。
- **探索前沿（Exploration Frontier）**：新模型、Agent/协议、开源工具、量化研究框架、因子/选股方法、数据源、验证方法、基础设施、交互模式。允许快速研究，但默认不影响用户可见结果或生产评分。

探索成功可以挑战稳定内核中的**实现方式**，但不能跳过安全/真实性原则。稳定内核也不是永久正确：若外部标准、监管、市场结构或反例改变，必须重新评估。

## 3. 主动发现什么

外部雷达至少覆盖七类，不因当前功能目录而封顶：

1. **AI / 模型 / Agent**：LLM、语义模型、时间序列基础模型、工具/Skill/MCP、Agent 研发与验证框架。
2. **量化与选股**：候选生成、事件/题材传导、资金/筹码、形态、市场状态、组合构建、做T、执行与风险方法。
3. **研究方法**：point-in-time、walk-forward、purged/embargo、multiple-testing、校准、因果/消融、挑战者治理。
4. **数据**：行情、公告/新闻、产业链、资金、订单簿、另类数据及其许可、时效、修订和身份契约。
5. **工程与运行**：数据库、缓存、调度、可观测性、测试/CI、供应链安全、隔离、恢复与成本。
6. **产品与交互**：更低认知负担的机会表达、证据链、失效条件、提醒治理、分析工作流。
7. **环境变化**：交易所/监管规则、市场微观结构、模型/API/开源协议变化以及重要依赖退役。

正常扫描还要主动寻找**反证**：不仅问“有什么新东西值得加”，也问“我们现在坚持的做法是否已经被更好的公开证据否证”。

## 4. 来源优先级

发现阶段可以宽，做决定必须收窄：

| 级别 | 来源 | 用途 |
|---|---|---|
| S0 | 官方规范、监管/交易所、项目官方文档/版本、原始论文与代码 | 事实与能力边界的首选依据 |
| S1 | 可复现实验、官方 issue/PR、独立 benchmark、维护者讨论 | 找失败模式、版本差异和真实限制 |
| S2 | 高质量技术文章、会议分享、成熟社区经验 | 生成候选与补充解释 |
| S3 | 榜单、社媒、营销、Stars/热度、二手转载 | 只作为“去核查”的线索，不作为准入证据 |

任何“显著提升”“更快”“更准”“最强”都必须回到可比条件；外部作者自己的 benchmark 是候选证据，不自动成为本项目事实。Stars/下载量只能作为成熟度或关注度线索，**不得设置 star 硬门**：早期但能力独特、来源可信且解决真实缺口的候选仍可进入 TRIAGED。对开源候选可使用 OpenSSF Scorecard/安全公告等机器信号补充供应链判断；对模型/Agent/推理系统可参考 lm-evaluation-harness、SWE-bench、MLPerf 等可复现实验框架，但最终准入仍由本项目目标域 benchmark 决定。

## 5. 候选生命周期

外部候选只有以下状态；这些状态**不是施工授权**：

```text
DISCOVERED
   ↓ 核来源/版本/用途
TRIAGED
   ├─ REJECTED（无增量/不适配/风险过高）
   ├─ WATCH（有潜力但证据或条件不足）
   └─ SHORTLISTED
          ↓ 隔离可复现
         LAB
          ↓ 相同输入/基线比较
     SHADOW / CHALLENGER
          ├─ RETIRE（后续失效/成本恶化）
          ├─ WATCH
          └─ ADMISSION_CANDIDATE
                 ↓ 原任务/PR/审核/发布门
              ADOPTED
```

只有进入需要真实实现/实验的阶段，才在已有 W00–W09 中找到真正拥有该问题的任务；能并入现有任务就不造新 ID。外部雷达自身不成为第二套 backlog。

## 6. 证据梯度

- **E0 线索**：名字、宣传或社区讨论；只证明“值得看”。
- **E1 原始来源核实**：锁定版本、能力、许可、输入/输出、依赖、维护状态与公开限制。
- **E2 隔离复现**：本地/沙箱 smoke 可重现；无生产权限、无私人数据、无未批准费用。
- **E3 基线对照**：与当前系统在同输入、同覆盖、同成本口径下比较质量、失败、延迟、token/CPU/内存和维护面。
- **E4 目标域验证**：A股真实 point-in-time 数据、人工 gold、walk-forward/消融/影子运行或真实工程负载；按候选类型选择。
- **E5 准入证据**：收益稳定、风险可控、恢复可用、消费者明确，且完成独立审核与准确版本门禁。

任何候选不得从 E0/E1 直接跳到生产。Jev、LLM 或 Agent 的 confidence 不能代替 E3–E5。

## 7. 先过硬门，再谈“值不值得”

不使用一个神奇总分把不可接受风险平均掉。先逐项过硬门：

- 许可/知识产权可接受；
- 不要求违反当前费用授权；
- secret、私人输入和遥测边界清楚；
- 权限最小化，可关闭、可回退；
- 供应链和上游版本能固定/校验；
- 数据/环境确实可获得；
- 不破坏真实交易、风控、鉴权和研究禁令。

通过后再比较增量价值：

- 解决的真实问题是否存在；
- 相对当前机制是否有独立增量；
- 质量/可靠性/时效/成本/开发效率改善是否可测；
- 复杂度、维护负担和 provider lock-in 是否值得；
- 是否存在更小、更确定性的替代。

正常结论可以是“不改”。拒绝也是有价值的研发结果，应记录**拒绝原因 + 重开条件**。

## 8. 各类候选的专门验收

### 8.1 AI / 模型 / Agent

至少测：目标任务质量、结构化输出稳定性、低置信/失败语义、延迟、token/费用、上下文和隐私、重试/回退、provider/版本漂移。模型只在它真正改变下一步时存在价值。

Jev 只可帮助 bounded triage、去重、相关性/候选路由等窄判断；**Jev 不拥有最终技术准入权**。复杂候选由 DeepSeek/Codex/ChatGPT 研究，最终仍靠实证和审核。

### 8.2 量化、因子、战法和选股逻辑

必须额外证明：

- 经济/市场机制或可证伪假设；
- A股制度与数据字段可映射；
- point-in-time、修订时间、历史股票池/成分无泄漏；
- 手续费、滑点、整手、T+1、停牌、涨跌停和可成交性；
- purged walk-forward / embargo、分市场状态和足够样本；
- 多重尝试/参数搜索不会只留下“最幸运”的结果；
- 相对当前 Champion 有稳定增量，而不是同源指标换名。

单票案例、单窗口胜率、论文在美股/币圈有效，都只能生成研究假设。

### 8.3 数据源

锁定来源身份、字段/单位、许可、历史覆盖、实时性、修订、失败语义、限额与成本；实抓样本后才能进入 Provider 比较。包装库数量不等于独立数据源。

### 8.4 工程工具

比较正确性、开发时间、CI/运行成本、权限面、依赖/供应链、可观测性和恢复。若引入平台复杂度大于解决的问题，保持现状。

## 9. 研究隔离与防“自动研发自我欺骗”

自主研发最危险的不是“不会想”，而是反复看同一 holdout 后把验证集训练成隐形训练集。因此：

- idea generation、开发反馈、validation、final holdout 分离；
- final holdout 不反馈给同一轮迭代；
- 版本、数据窗口、尝试次数与否证结果全部留痕；
- 新候选与 Champion 在同一冻结输入上比较；
- 失败实验不得静默消失；
- 自动 Agent 不能自行把“实验改进”转成生产准入。

如果外部自主量化框架自身仍在修 holdout 泄漏、退市样本或环境隔离问题，应把这些 issue 当作风险证据，而不是只读其收益宣传。

## 10. 何时主动挑战现有方案

每项长期决策至少允许以下重开触发：

- 新的官方标准/协议或重要模型能力改变了成本/权限边界；
- 当前方案出现稳定失败模式或维护成本显著上升；
- 外部方案在同类真实任务有可复现实证；
- 数据源、市场规则、依赖或 provider 发生破坏性变化；
- 原决定的关键前提不再成立；
- 周期复核发现长期没有重新比较过替代方案。

“已完成”只表示当时问题闭环，不代表永不重审。

## 11. Watch + Scout 双通道

现有 `backend/scripts/repo_watch.py` 是 **Watch lane**：只跟踪已经知道、已经采用或已经评估过的仓库发生了什么，负责 release / breaking / deprecation / 关键路径变化与供应链提醒。它不负责发现全新模型、论文、协议、数据方法或新仓库，不能把“Watch 正常”误写成“外部世界已扫描”。

`ashare-innovation-radar` 是 **Scout lane**：从官方发布、论文/作者代码、GitHub 新项目/Trending、独立 benchmark、安全信号、监管/交易所变化、量化研究等更宽来源发现新候选；只产 DISCOVERED/TRIAGED/WATCH/SHORTLISTED，不自动安装、付费、建业务任务或改生产。

两条链共享 `docs/kb/05-repo-tracker.md` 的已评仓库经验和否证记录；repo 类候选进入 Watch 后再由 repo_watch 增量跟踪。非 repo 候选不强塞进 repo_watch。

## 12. 扫描节奏与信息降噪

设计上的默认节奏：

- **事件触发**：重大模型/协议/依赖安全/监管/交易规则变化立即评估；
- **轻量周扫**：只发现候选和淘汰明显噪声，不安装、不跑昂贵实验；
- **月度深扫**：挑少量 SHORTLISTED 做源码/论文/benchmark 复核；
- **季度架构挑战**：主动选择若干现行关键决定，寻找更好替代和反证。

这些是研发节奏，不等于自动网络/付费/生产权限。真正自动化频率只有在多轮证明“有用候选率高、噪声和成本可控”后再实施。

原始扫描与长笔记放忽略的 `artifacts/radar/`；仓库只保存长期有效的蓝图、被采用/拒绝的关键结论和任务证据，防止热点新闻把文档库污染成资讯流。

## 13. 采用后必须完成传播

候选一旦改变长期设计或生产能力，必须同时：

1. 进入真正拥有该问题的 stage，写验收/恢复；
2. 更新唯一专题蓝图或现有设计；
3. 按 `plan-registry.md` §1.1 做重大决策传播核对；
4. 更新 INDEX / AGENTS / Skills / handoff 中真正受影响的入口；
5. 保留旧方案为什么被取代、如何恢复；
6. 让 doc-health 和相关测试对新增不变量建立可失败的守卫。

这样“发现新东西”才算进入系统，而不是停在聊天或一次实验。

## 15. 成功指标

持续演进机制本身也必须被验证，否则它会变成新的形式主义。至少跟踪：

- 高价值候选被发现后到完成 E1/E2 的时间；
- **发现领先时间**：重大候选是否能在用户提醒前被系统自己发现；漏发现时必须记录原因（来源缺口、检索词、硬门过窄、去重误杀等）；
- SHORTLISTED 中最终产生可测增量的比例；
- 被拒绝/观察候选的重开命中率；
- 因外部发现避免的重复开发或失效方案；
- 每轮扫描的人力/token/网络/CI成本；
- 采用后真实质量/可靠性/成本变化；
- 是否出现“热点驱动却无消费者”“长期只收集不验证”的堆积。

若雷达长期只产生噪声，就缩小来源/频率；若持续漏掉后来证明重要的变化，就扩展发现面。雷达本身也必须持续进化。
