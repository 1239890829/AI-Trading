## 一、myhhub/stock（筹码分布等）

**一句话定位**：A 股综合工具库，本组重点评估其**筹码分布（成本分布）算法**——这是我们完全缺失的能力。

### 1.1 筹码分布算法：设计值得抄，实现有 3 个实测缺陷（证据 A）

用真实行情数据复算其筹码分布后确认：**算法骨架（ triangular/volume-weighted 换手衰减）正确，可直接参考设计；但直接引入其代码会踩 3 个坑**：

| # | 缺陷 | 实测表现 | 对我们的启示 |
|---|---|---|---|
| 1 | **归一化口径错** | 同一股票同一时点，其获利比例与我们按定义复算的结果差 **60.8 倍** | 引入时必须自建归一化并加哨兵（获利比例 ∈ [0,1]） |
| 2 | **窄幅横盘悬崖** | 窄幅震荡段成本分布出现不连续跳变 | 分布直方图的 bin 宽度不能绑定固定价差，要按波动率自适应 |
| 3 | **一字板量纲错** | 一字涨停日换手极小但全按同价处理，分布被单日污染 | 一字/无量日要特殊处理（低权重或沿用前日分布衰减） |

**判定：不自研筹码分布（三角衰减 + 换手加权的原理清晰，照设计自实现约一天工作量），不引入其代码。** 数据源用 akshare `stock_cyq_em` 单接口即可（东财官方算好，免自算；本次实测本地网络被限流，接入时需配降级）。

### 1.2 形态识别（TA-Lib 直出形态）：放弃（证据 B）

- 该类仓库把 TA-Lib 61 个形态（CDL* 系列）直接搬进 A 股场景。
- 作者自己在实战策略里**并未使用**这些形态（代码检索确认其策略主体不消费形态信号）。
- TA-Lib 形态在 A 股日线级别噪音过大，且我们前端已有 3 个自用形态。**判定：放弃引入，改为后端补齐前端已有 3 形态（见第 1 组报告）。**

## 二、easy_tdx（通达信协议直连）

**一句话定位**：pytdx 后继者，TDX 协议 Python 直连库。**本项目已在用**（requirements 已含）。

### 2.1 实测：TDX 服务器连通性（证据 A）

- 官方 host 列表 16 个，实测 **11 个可达**。直连可用性足够。
- 对本项目唯一增量价值：**补 ths 分钟 K 的边界**——ths 官方 API 硬性不覆盖分钟 K/tick（数据源对比文档已确认），TDX 直连是分钟级数据的可行备源。

### 2.2 采纳清单

| # | 采纳项 | 收益 | 动作 |
|---|---|---|---|
| 1 | **版本钉住** `>=1.20.12,<1.30` | 该库 1.30 起接口有破坏性变更，不钉住随时断 | 改 requirements |
| 2 | **TDX 直连补分钟 K 边界** | ths 不覆盖分钟 K，TDX 是免费备源 | ✅ 已收束（2026-09-03）：回测底座主源（m5 495 日/m1 94 日，2026-08-30 #51）+ `/api/minute-line` 运行时降级备源（腾讯失败时 TDX m1 接管，仅裸 6 位股票码） |

### 2.3 缠论类仓库

- 调研结论：分笔/笔段算法实现质量参差，且缠论体系与打板系统方法论不同构（缠论是多级别结构化体系，需要稳定的分笔数据底座）。**判定：不引入。** 当前题材/梯队方法论自洽，引入缠论是方法论堆叠而非补短板。

## 三、回测框架通用设计（Walk-Forward 与绩效指标，来自本组多仓共性）

### 3.1 采纳清单

| # | 采纳项 | 收益 | 落点 |
|---|---|---|---|
| 1 | **Walk-Forward 多窗验证** | 单窗回测过拟合风险高；多窗滚动（train→validate 交替）才能证明参数稳健 | `backend/app/market/backtest.py` 扩展 |
| 2 | **25 项标准绩效指标** | 当前回测产出指标过少（收益/回撤为主）；补充胜率、盈亏比、期望、最长连亏、Ulcer 等成套指标 | 同上 |
| 3 | **golden test（快照回归）** | 回测引擎重构后数值回归全靠人眼；用固定输入快照输出做 golden 断言 | tests |

**判定：这三项是对现有 `backtest.py`（407 行，已含 T+1/涨跌停拒单）的增强，不是新轮子。**
