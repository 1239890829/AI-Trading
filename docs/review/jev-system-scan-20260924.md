### 4. 新发现的价值排序判断（不是任务优先级）

最值得验证的新增能力是“同一事实跨事件、个股、猎场、提醒的修订/反证关系”，因为一份判读能服务多个真实消费者；其次是“已有报告/引用是否有依据”和“重复问题/助手能力误否认”，因为现有规则可比较、错误可人工判定，且无需先证明股票收益。

个股语义特征、主题新别名、检索重排属于有条件实验：前两项依赖原文/候选覆盖，最后一项可能不如强检索基线。市场相位、风控、主备、性能调度、自动发布及自进化批准不适合概率模型替换。可视化只为解释变化/采用/结果或辅助排错；批标签、后台归并、回归筛选有用但不需要新增前台页面。

本轮可判定必要性和验证成本，不能证明尚未实验的收益。每个候选若最小确定性修补就足够，则取消Jev实验；同质量增量未证明，最多保留解释用途或退出。

### 3. 替代必须怎样证明

每个替代提案需冻结：原任务要达成的用户结果、原候选/最小修补baseline、被替代的具体子范围、质量与失败边界、完整成本、回退以及尚未完成的原义务。对现有实现与替代方案用同一输入和独立标签比较；模型有价值但只覆盖一部分时，将它并入该子范围，不宣布整任务完成。

建议优先设计的对照（不是派工或排期）：

- IMP-051：现有编排、现有编排+Jev窄判断、计划重框架候选，在盘前研究/盘中解释/盘后复盘三类任务同模型/同数据/同授权比较。轻量方案赢得维护/时延/成本且关键质量不退化，才提议退出重框架接入；不能把只缩短prompt视为同等能力。
- IMP-048/049：确定性身份+现别名/匹配、最小扩词/规则、Jev残余歧义判断。必须证明不是原文缺失或候选召回缺失导致错误；Jev只能替代已验证的那个判断分支。
- RSH-027：现路由/检索、改善召回的纯工程方案、Jev候选判读或融合；看必要证据与引用真支持，而非模型对自己的相关分。
- RSH-003/RSH-031：同一研究预算下比较语义特征候选与原待研究候选，保留失败和多重试验账；只有时间外净增量支持时才争取准入，不能用解释更好代替收益。

### 4. 批准后的账本操作规矩

先由用户审核方案→对当前最新stage重新对账→相容内容补入原任务范围/验收或子片→确无owner且有必要才分配未用编号。新任务按既有门禁角色、依赖和P0–P2规则登记；不得抬高它以绕开当前G1/IMP-048，也不得因为本轮用户讨论Jev便降低、挪门或覆盖其他任务。

若提议合并/替代/退出，必须单独列出原ID、保留义务、迁移消费者与证据、历史身份/恢复、依赖是否受影响，批准后再更新唯一stage；新能力与原任务独立时并列登记，不偷换任务完成标准。不可复用已撤销编号。现阶段不建立新的执行阶段或确定新任务优先级；本方案只提供价值判断与现有owner映射。

### 3. 决策协议裁定

- **KEEP**：行情/数据质量/数值计算/风控/模拟执行/权限/发布与恢复的确定性机制及现有有效消费者。
- **FIX 候选**：已观察到的消费链、评价口径或时间排序疑点先归原owner；不在本轮顺手修复，不因使用Jev改优先级。
- **MERGE**：重复的雷达、gold、路由、证据核验、生命周期与可视化消费需求进入原owner。
- **EXPERIMENT**：修订/引用支持、机会理由变化、复盘同义问题、助手误否认；条件候选包括主题关联、标签分工、知识重排、选股语义特征与轻量编排。
- **WATCH**：无频次/消费者证据的组合叙事、通用日志聚类、新插件封装；到期没有新证据就退出活动队列。
- **RETIRE / 不接候选**：每模块一个插件、实时布局/风控/主备概率化、没有净收益的重复模型步骤；不借此删除现有代码资产。
- **ESCALATE**：方案正式采用、实验预算/外发、安装升级/权限/生产阈值按原授权与准入分层；方向批准不等于自动批准全部部署。

### 4. 下一最小步与验收

当前最小步是把完整候选方案交用户审核；没有用户批准不登记新任务。批准后先与最新stage对账，相容内容补原任务，独立必要工作才新编号；原门序不变。

未来第一个语义实验建议用冻结公开/获准材料验证“新材料是否实质改变原个股理由”，但这不是抢占当前G1/IMP-048。验收必须包含明确反证、同源转载、同名主体、未知、来源迟到和Jev失败；先测基线与人工真值，再看是否值得接业务。
