# AI 大脑（自主进化层）重构方案 v2

> 2026-09-08 · 用户指令：把 AI 控制台从「依赖手动触发的工具」升级为**驱动系统持续进化的"大脑"**——
> LLM 自主承担优化与维护、盘后复盘自动闭环（可行改进直接执行，去掉人工状态流转、只留完整留痕）、
> 手动按钮仅作 LLM 不可用时的降级备选、围绕胜率与短板持续进化并校验整体方向。
>
> 本方案**取代** `ai-agent-console-plan.md` 中"建议态需人工确认"的保守设计（该文档的权限分级、
> 变更单、审计、任务中心等基建全部沿用）；与 `strategy-evolution-plan.md`（五大方向路线图）、
> `ai-brain-plan.md`（AI 大脑化三层分工）互补对齐。

---

## 1. 方向转变：从"人工确认"到"自动执行 + 后置守护"

v1 的安全模型是**前置人工确认**（draft → 人点确认 → 生效）。用户明确：这会把大脑退化成
"需要人喂的工具"。v2 改为**后置守护**：

| | v1（已落地） | v2（本方案） |
|---|---|---|
| 触发 | 人点按钮 / 人发指令 | **自主议程**：盘后 LLM 汇总证据自动生成并执行 |
| 参数生效 | draft → 人工确认 → apply | **证据达标 → 自动 apply**（同一变更单机制） |
| 安全机制 | 前置确认 | **后置守护**：回归门禁 + 后置验证窗口（劣化自动回滚）+ 红线 + 预算 |
| 留痕 | 审计 | 动机 + 轨迹 + **文件清单（git diff）** + 实验记录本 |
| 手动按钮 | 主要入口 | **降级备选**（LLM 不可用时），界面显式标注 |

**不变的底线**：审计与回滚机制不削弱（反而加强）；L3 红线（真实交易/对外推送/凭据/删数据）
依然代码级禁止；全面停机开关常在。

### 用户四点诉求 → 架构映射

| 诉求 | 落点 |
|---|---|
| ① 主动自治优化 | **每日进化议程**（§3）：盘后 LLM 汇总五路证据 → 生成改进任务 → 按边界分级自动执行 |
| ② 盘后自动闭环 | 复盘调度（已有 15:30）之后接 **evolution_scheduler（15:45）**：改进项免人工流转，A/B/C 三类直接执行（§4） |
| ③ 降级备用 | LLM 可用性探测（复用 llm_probe）：不可用 → 议程/复盘标注「规则模式」+ 任务中心手动按钮兜底 |
| ④ 持续进化 | **方向校验器**（§5）：每日对账三份计划 vs 实际代码能力，防漂移、提补齐项 |

## 2. 自主进化循环（Evolution Loop）

```
        ┌────────────────────────────────────────────────────┐
        │  感知 → 诊断 → 议程 → 执行 → 验证 → 记忆 →（次日感知）│
        └────────────────────────────────────────────────────┘
感知  五路证据源（全部已有/在建）：
       ① 复盘报告改进项（15:30 review_scheduler 产出）
       ② 信号健康 signal_health（滚动胜率 + CUSUM 漂移，策略失效预警）
       ③ 因子 IC 复核（scripts/factor_ic_review.py，tech_score 八维优胜劣汰证据层）
       ④ 告警判读统计（agent_triage：哪些规则在产生噪音、哪些事件被反复忽略）
       ⑤ 计划对账（三份 plan 的阶段 vs 实际代码能力，§5）
诊断  LLM 汇总五路证据 → 输出「今日进化议程」：
       [{finding 发现, evidence 依据, action 动作, class 变更类别(A参数/B文档/C代码),
         priority, expected_effect 预期效果, verification 验证方式}]
执行  按类别走 §4 的执行器；预算与红线先闸（§6）
验证  A 类挂后置验证（30 日窗口 IC/胜率对比，劣化自动回滚）；
       C 类执行前过回归门禁（pytest/tsc/关键指标），执行后进实验记录本
记忆  实验记录本（假设→结果→结论）+ 知识沉淀（结论回写方法论/长期记忆，防重复犯错）
```

## 3. 每日进化议程（Daily Agenda）

**形态**：一天一份结构化议程（`agent_task` 的特殊类型 `evolution`，或独立 `agent_agenda`
表），LLM 产出，字段：

```json
{
  "date": "2026-09-09",
  "inputs": {"review": "…摘要", "signal_health": "…", "factor_ic": "…",
              "triage_stats": "…", "plan_alignment": "…"},
  "items": [
    {"finding": "picks_style_offsets_json 的 fundamental 偏移在发酵期 30 日胜率 -3%",
     "evidence": {"sample_days": 30, "win_rate": 0.41, "baseline": 0.48},
     "action": "将发酵期 fundamental 偏移从 -0.05 调回 -0.03",
     "class": "A", "priority": 1,
     "expected_effect": "发酵期组合胜率回升至基线",
     "verification": "30 日窗口对比 apply 前后 T+1 胜率，劣化 2pct 自动回滚"}
  ],
  "budget_used": {"llm_calls": 6, "tasks": 2}
}
```

**执行边界（三类）**：

| 类别 | 内容 | 自动执行方式 | 守护 |
|---|---|---|---|
| **A 参数类** | 白名单参数（目前：相位→风格偏移；后续：watcher 阈值、gate 阈值） | 变更单**直接 apply**（人工确认步骤移除） | 值域钳制（已有）+ 证据门槛 + 30 日后置验证（劣化自动回滚）+ 同参数 24h 一次 |
| **B 文档/知识类** | 方法论文档更新、复盘结论沉淀、计划对账报告、长期记忆回写 | 直接写文件/DB | 低风险；变更留 diff |
| **C 代码类** | 小型修复/重构/新规则（如"补一个缺失的边界校验"） | LLM 生成 patch → **回归门禁**（pytest 全量 + tsc + eslint + 关键指标对比）→ 通过则独立 commit（git 天然可回滚）→ 失败丢弃 | patch 大小上限（建议 ≤200 行 diff）；禁止触碰红线文件（§6） |

**红名单（任何类别都不可自动触碰，硬编码）**：风控阈值（`picks_gate_*`、止损纪律）、
资金/下单/实盘相关、飞书推送规则与凭据、数据源凭据、删除类操作、`.env`、 Alembic 迁移
之外的所有 DB 结构变更。

## 4. 盘后自动复盘闭环（改造点）

现有：15:30 `review_scheduler` 自动跑复盘（rules/llm）→ 报告 + action_items（人工 PATCH 采纳）。

改造为三段全自动：

1. **复盘生成**（已有，保持）：`ASHARE_REVIEW_MODEL=llm`，报告带 `llm_enhanced` 标记。
2. **改进项裁决**（新增，LLM）：复盘报告的 action_items 逐条经 LLM 裁决 →
   `{automatable: A|B|C, proposal}`；不可自动化的（需要数据积累/人工判断）标注理由后进
   「人工清单」（不是"待确认"流转，是**能力边界声明**——说清为什么机器做不了）。
3. **直接执行**（新增）：A 走变更单自动 apply；B 直接写；C 走 patch+门禁。去掉
   `已确认/已实施` 人工状态——action_items 的 status 只剩机器写的
   `executed / deferred(附原因) / rejected(附原因)`，全部可在控制台一眼看清。

**用户看到的东西**（控制台「进化」tab）：今日议程 → 每项的动机/依据/轨迹/文件清单 →
实验记录本（含历史自动改动的后置验证结果）→ 方向对账。**不需要点任何确认。**

## 5. 方向校验器（防漂移，对齐三份计划）

每日议程的第五路证据。对账对象与方式：

| 计划 | 对账内容 | 产出 |
|---|---|---|
| `strategy-evolution-plan.md` | 五大方向的 P0/P1/P2 阶段声明 vs 代码实际能力（grep 端点/模块存在性 + signal_health 实测数据） | 「已落地/漂移/待启动」三态清单 |
| `ai-brain-plan.md` | 三层分工（数据枢纽/分析决策/自主执行）进度 | 同上 |
| `ai-agent-console-plan.md` | 控制台模块完成度 | 同上 |

LLM 在议程里回答三个问题：**今天做的改动是否在既定方向上？哪些计划项被外部条件阻塞
（显式标注阻塞原因，不算欠账）？下一步最该补齐什么？**——防止"每天很忙但方向漂移"。

## 6. 延伸能力（用户未提及、本方案补齐的 10 项）

1. **实验记录本（Experiment Ledger）**：每次自主变更加 `hypothesis / verification_window /
   result / conclusion`——进化是"实验"语义，不是随机改动；同参数历史实验可查，避免重复试错。
2. **后置验证与自动回滚**：A 类变更 30 日窗口后自动对比 IC/胜率，劣化超阈值 → 自动回滚 +
   记录结论。这是取代"人工确认"的核心安全机制：**前置放行、后置纠错**。
3. **回归门禁**：C 类 patch 必须全量绿（pytest/pyflakes/tsc/eslint/vitest）+ 关键指标
   （signal_health 基线）不劣化，否则丢弃 patch。
4. **成本护栏**：每日 LLM 调用次数与 token 预算、每日自动任务数上限（建议 3 个）——
   防止"自主"变"失控烧钱"；预算耗尽 → 只生成议程不执行。
5. **全面停机开关**：`ASHARE_AGENT_AUTONOMY=off` 一键停掉全部自动执行（议程照常生成，
   只降级为"建议清单"）；控制台显式开关。
6. **阈值校准顾问**：watcher 确认阈值 / 执行闸门 gap 阈值的历史命中率定期复盘 → 自动生成
   校准变更单（A 类，带证据）。
7. **数据质量语义哨兵**：现状是纯阈值（ths reason 非空率）；升级为 LLM 判"语义异常"
   （如题材归因塌缩成单一未分类、快照字段大面积同值）——进告警判读链。
8. **元评估（自我审视）**：每周 LLM 回顾本周自主改动：采纳后效果如何？哪些判断错了？
   错误模式是什么？→ 结论进知识沉淀，反向修正判读 prompt。
9. **多模型冗余**：主模型（GLM-5.3）降级时自动切备模型；判读/议程界面标注当前模型
   （llm_fallback 机制已有，扩展到议程）。
10. **知识沉淀闭环**：复盘结论 → 方法论文档增量更新（B 类）→ 长期记忆（MEMORY.md）
    ——让"大脑"越用越准，而不是每天从零开始。

## 7. 实施计划（按优先级，每批带验收）

| 批次 | 内容 | 验收 |
|---|---|---|
| **P0 进化骨架** | ① `evolution_scheduler`（交易日 15:45）：汇总五路证据 → LLM 议程 → 落库；② A 类自动生效（参数变更单自动 apply，带 evidence；预算/红线/频率闸先上）；③ B 类文档执行器；④ 红线清单 + 停机开关 + 成本护栏（硬编码于 services/evolution.py）；⑤ 控制台「进化」tab（今日议程/动机/轨迹/文件清单） | 收盘后自动出现当日议程；A 类改进免人工直接生效且可回滚；红线参数被提议时被拒并留痕；`AUTONOMY=off` 时只生成不执行 |
| **P1 执行深化** | ⑥ C 类代码 patch 执行器（分支沙箱 → 回归门禁 → merge commit / 丢弃）；⑦ 实验记录本 + 30 日后置验证（劣化自动回滚）；⑧ 方向校验器（三计划对账）；⑨ 复盘 action_items 三段闭环（裁决→执行→executed/deferred） | 一个真实 C 类修复走完"发现→patch→门禁→commit→记录"；一个历史 A 类变更在后置验证中展示对比结果；对账报告指出至少一处计划漂移 |
| **P2 深化** | ⑩ 阈值校准顾问；⑪ 语义哨兵；⑫ 元评估周报；⑬ 多模型冗余；⑭ 人工清单 UI（能力边界声明） | 周报展示本周自主改动采纳率与错误模式；主模型故障日议程仍产出（备模型/规则模式标注） |

**依赖与顺序理由**：A 类先于 C 类（变更单/回滚/审计已就绪，风险最低收益直接）；实验记录本
必须先于 C 类放量（没有后置验证就没有资格自动改代码）；方向校验器在 P1（议程骨架跑稳后
才有对账意义）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 幻觉导致错误改动 | 证据门槛（无数据不改）+ 值域钳制 + 回归门禁 + 后置验证自动回滚 + 红线 |
| 自动改动互相冲突 | 同参数 24h 一次；同文件冲突检测（patch 前置检查）；每日任务数上限 |
| 失控烧钱 | 每日 LLM 预算 + 任务上限；超限只出议程不执行 |
| 方向漂移 | 每日计划对账；周元评估 |
| LLM 长期不可用 | 降级为"规则模式议程"+ 手动按钮（任务中心既有）+ 界面标注；**系统其余功能不受影响**（进化层是旁路，不侵入主链路） |
| 用户失去掌控感 | 全部动作一目了然（动机/轨迹/文件清单）；停机开关 + 红线可视化；回滚一键 |
